## 📌 一句话总结

老短路判据量的**根本不是短路**，是「全图最大的蓝紫连通域像不像一个特定大小的圆环」——
那个圆环是**生成器画给人眼看的标记圈**。于是：
真短路的 `power_short.png` 画的是一条金条 → 整板一路 PASS（**漏检**）；
不是短路的 `mcu_bridge.png` 画的是焊锡连片 → 多报一条「短路」（**误报**）。

改成「**同一个元件的两个端子之间，绝缘缝里有没有金属**」之后，
短路才第一次是短路；六个调不动的旋钮一起删掉（不是调它们，是它们量错了对象）；
「哪两个端子属于同一个元件」由**画焊盘的那一行代码**登记，判据不猜。

## 一、老判据错在哪

### 1.1 【实测】老判据量的对象是「标记圈」

旧判据（`common/pcb_core/pcb_core.cpp` 旧版）大意是：

```
全图找最大的蓝紫连通域 → 算它的面积占比 / 宽高比 → 落进某个窗口 → 报 short
```

窗口有六个旋钮：`short_min_pct` / `short_max_pct` / `short_w_min_pct` /
`short_w_max_pct` / `short_h_min_pct` / `short_h_max_pct`。

**这六个旋钮没有一个在描述短路。** 它们在描述「一个圆环该长什么样」。
调它们能改的只是「认不认得出那个圈」，跟「板子短没短」没有因果关系。

### 1.2 【实测】两个方向同时错

| 图 | 物理事实 | 老判据的结论 | 后果 |
|---|---|---|---|
| `power_short.png` | L1 电感两脚被金条连通（**真短路**）| PASS | **漏检** |
| `mcu_bridge.png` | Y1 晶振焊锡连片（焊桥，不是两脚被金属连通）| 多报一条 short | **误报** |

漏检那条实测数据：那条金条面积占比 0.1992%（上界 0.08%）、宽 41.4% 对角线（上界 8%），
**所有窗口都撞出去了**，于是整块板一路 PASS。

> 📌 误报比漏检更难查：漏检有「已知漏检」清单兜着，误报没有登记表。

### 1.3 【实测·项目】病根是量错了对象，不是阈值没调好

这和极性判据是**同一种病**（见 `notes_PCB_Polarity_2026-10.md`）：
判据量了一个**代理量**，而代理量和物理事实之间没有稳定的映射关系。
那种情况下调阈值是在**追一个不存在的相关性**。

## 二、新判据：短路 = 两个端子之间有金属

### 2.1 【实测】量的东西

```
两个端子中心连线
  → 掐掉两端各「焊盘半宽 + 1px」（焊盘本来就是金属，它是端子，不是缺陷）
  → 剩下那段「绝缘缝」逐点采样
  → 每个采样点在垂直方向取 ±(0.2 × min(焊盘半宽)) 的窄条
  → 有金属的采样点占比 ≥ 50% → 报 short（点名到那个元件）
```

实测：
- 好板 `baseline.png`（R2）：**0.0%**
- 废板 `short.png`（R2）：**100.0%**（54/54 个采样点）
- 废板 `power_short.png`（L1）：100.0%

阈值取中点 50：好板 0%、废板 100%，中间没有内容，50 是安全的。

### 2.2 【实测】端子位置从哪来：生成器登记，判据不猜

「哪两个端子属于同一个元件、它们在哪儿」只有**画焊盘的那一行代码**知道。
所以让那行代码顺手登记一笔：

```python
PADS[(cx, cy)] = [(x1, y1, r1), (x2, y2, r2)]    # 画焊盘的这一行,顺手登记
```

导出脚本 `W7_VisionMasterLite/tools/export_recipes.py` **原样搬**到配方：

```json
"pads": [[110, 480, 12], [190, 480, 12]]
```

判据、配方、算子三层都只是搬运，**没有第二份表**。

> 📌 这和极性判据的 `polarity_side` 是同一招，详见
> `atomic/at-criterion-must-not-guess-the-baseline.md`。
> 猜错的后果是把好板判成废板 —— 误报比漏检更难查。

### 2.3 【实测】六个旋钮一起删了

`short_min_pct` / `short_max_pct` / `short_w_min_pct` / `short_w_max_pct` /
`short_h_min_pct` / `short_h_max_pct` 全部删除。

不是「调好了所以留着」，是**它们量错了对象**，留着就是界面上摆六个**调了不生效**的旋钮。
新旋钮只有一个：`short_gap_min_pct`（默认 50）。

同时 `common/pcb_core/pcb_color_ref.h` 里的 `blueBand`（H 100-135）也删了 ——
没人再用它，留着会诱导下一个人照它写「蓝斑判据」。

### 2.4 【实测】short 从「全局缺陷」变成「按元件缺陷」

老判据是全局的：`defect.component` 留空，报告里单独成一行。
新判据是**按元件**的：它量的就是某个元件的两脚之间，所以它报出来的必须是某个元件。

- demo 板短路 → 点名 **R2**
- power 板短路 → 点名 **L1**

产线上只知道「这板废了」是不够的 —— 还得知道「哪个元件废了」。

## 三、前置条件：元件本体不能是金属色

### 3.1 【实测】为什么这条必须存在

生成器的调色板常量按 RGB 写、注释按 BGR 写，于是「电容黄」实际渲染成**青蓝色**，
H≈94.7，正好落在金层色带 H[85,115] 里，和铜箔（H≈96.3）几乎同色。

这类元件的「绝缘缝」本来就是金属色 —— 缝里有没有金属**根本判不出来**，
硬判就是**每一块好板都报短路**。

### 3.2 【实测】我踩过一次，判据**不能**自己查这个

第一版判据里加了一道图像守门：本体中心那块像素要是金属色，就跳过这条规则。
实测把「短路铜条盖住本体中心」当成了「本体是金属色」——
**缺陷图上那块像素正是铜条**，于是漏检又回来了（这坑和 polarity 那次一模一样）。

### 3.3 【实测】所以这条前置条件由**配方层**保证

- 谁给哪个元件配 `short` —— `export_recipes.py` 的 `CHECKS` 表（那里写着每个封装的本体是什么颜色）
- 配了以后对不对 —— 回归测试在**好板**上量本体中心的颜色，断言它不在金属色带里
  （`common/pcb_core/tests/test_pcb_core.cpp` 的 `checkShortPrecondition()`）

**配错了不会静默**：好板会整片报短路，测试当场红。

## 四、缺陷图必须物理上真的短路

### 4.1 【实测】旧的两张短路图都不成立

| 图 | 原来画的 | 问题 |
|---|---|---|
| demo `short.png` | 在底部走线之间补一段铜 | 那段走线**本来就存在**（`(418,480)-(664,480)`），画上去只是把 6px 走线加粗到 7px，电学上没短接任何东西 |
| `power_short.png` | 在 (200,244)-(820,156) 之间拉一条横贯全板的金条 | 跨过了 GND 与 VOUT 之间的**所有**铜箔，图上很「壮观」，但和「某个元件的两脚」无关 |

旧判据之所以能「抓到」demo 那张，正是因为它量的不是短路，而是**画给人眼看的那个圈**。

### 4.2 【实测】现在的画法

- demo `short.png`：**R2 的两个焊盘之间架一条金条** `[cx-dx, cy-8, cx+dx, cy+8]`
- `power_short.png`：**L1 电感两脚之间架一条金条** `[644,194,716,206]`
- 红圈画在**元件外围**（`cx±50, cy±30` / `cx±70, cy±40`），**不压到被测的那段缝** ——
  短路判据就靠量那段缝，标记圈要是压上去，判据就成了「量标记圈」
- 「SHORT!」字放在上方远端，同理

> 📌 这一条是**故意**的：新的判据**不依赖**任何标记圈。
> 旧判据依赖它，所以「删掉标记圈」对旧判据是致命的，对新判据什么都不是 ——
> 这正是判据量对东西的最好证明。

### 4.3 【实测】顺带修掉一个误报源：错件的颜色

`wrong.png` / `mcu_wrong.png` 里的错件原本用**铜色**画。
铜色落在金层色带里 → 错件那个元件的「缝」是金属色 → 短路判据会误报。
现在错件用 `WRONG_PART = (40,200,120)`（青绿，H≈75，不在金层色带）。

> 📌 顺带记一笔：调色板常量按 RGB 写、注释按 BGR 写，是本项目的老账。
> 这次只把「错件」用的颜色摘出来改，整体修会动全部图和已标定的阈值。

## 五、真值表加一列：缺陷画在哪个元件

### 5.1 【实测】为什么要有这一列

「缺陷画在谁身上」以前**藏在函数体里**（`SITES[3] = R2`），
manifest.csv 里没有这一列。于是测试想验「判据点名的元件 == 缺陷真的画在的那个元件」，
就只能自己再抄一份 —— 本项目栽过四遍的那个坑。

现在：位号**只写一次**（生成器的 `DEFECT_REGISTRY` / `REGISTRY`），
- 画图 → `site_by_label()` / `site_xy()` 按位号取坐标
- 真值表 → `manifest.csv` / `complex_manifest.csv` 多一列 `site`

### 5.2 【实测】两张清单现在的样子

```
demo:  file,defect,expected,site,note
       missing.png,missing,FAIL,R2,synthetic defect: missing

complex: file,kind,components,size,filesize_kb,expected,site
       power_short.png,power,16,1200x900,22,FAIL:short,L1
       mcu_wrong.png,mcu,22,1200x900,25,FAIL:wrong,R2
       ...
```

### 5.3 【实测】测试从真值表读期望

- `common/pcb_core/tests/test_pcb_core.cpp`：短路必须点名到 `wantSite`（原来写死 `"R2"` / `"L1"`）
- `W7_VisionMasterLite/tests/test_pcb_operators.cpp`：
  - 原来那张手抄的 `bads` 表（recipe/file/type/site 四列）**整张删掉**，

  - `readManifest()` 改成**按列名**读（两张清单的列根本不一样，按位置读必错位）

> 📌 「已知漏检」那张表**保留机制**（现在是空的）：

> 提醒你把问题当回事。极性和短路这两次，都是这条机制先红的。

## 六、变异验证

### 6.1 【实测】四个变异，三个被杀、一个是等价变异

| 编号 | 改坏的地方 | 对应的设计决策 | 结果 |
|---|---|---|---|
| **M1** | 阈值比较写反（`pct >= thr` → `pct < thr`）| 判定方向 | **被杀**：核心测试 11 条红；W7 的 `pcb_core` + `pcb_operators` 两个套件同时红 |
| **M2** | 少掐焊盘那 1px（`pa.r + 1` → `pa.r`）| 采样窗口要掐掉焊盘 | **没被杀**（等价变异）→ 见 6.2 |
| **M3** | 把「没登记端子 → 报『没查』」静默掉 | 没查必须报出来 | **被杀**：核心测试 3 条红 |
| **M4** | W7 算子层不把 `pads` 往核心传 | 字段要活过中间那一跳 | **被杀**：`pcb_operators` 12 条红 |

M1 的红是**双向**的：好板误报短路 + 短路板漏检，两头都抓到。
M4 的红来自 `test_skipped_rules_are_reported` ——
端子没传下去，短路规则变成「没查」，而「没查」的**集合**变了，测试当场抓到。

### 6.2 【实测】M2 教的一件事：注释里的数字没人验证过

M2 没被杀掉。查下来是因为**它在当前数据上是等价的**：
焊盘确实带 1px 描边，但那个描边是**暗金色**，不在金属色带里 ——
所以掐掉不掐，好板读数**都是 0.0%**。

而判据里原来的注释写的是：

> 不掐掉的话「缝」的两端各有一个假采样点（好板读数**从 0% 变成 4.8%**）

**这个 4.8% 是错的。** 它大概是推演出来的，没人验过。

处理：
1. 注释改成实话（写明实测是 0%，这 1px 是为了**不依赖描边的颜色**）
2. 补断言：好板的短路读数必须**恰好 0**（demo 板 + 三块 complex 板），
   原来只断言「小于阈值 50」—— 中间那一大截余量正好能盖住这类 bug

> 📌 这条是本项目「注释会骗人，断言不会」的又一例，
> 而且是**反向**的：不是注释和代码对不上，是注释和**事实**对不上。
> 详见 `atomic/at-unverified-number-in-comment.md`。

### 6.3 【实测】补了一条此前没人验的路径

变异验证还发现：判据里**「没登记端子 → 报『没查』」这条路径没有任何断言钉它** ——
把那行 `push_back` 删掉，整套测试照样全绿。

补的用例（`test_short_needs_pads()`）钉三件事：
1. 没登记端子 → 必须有 `skipped` 条目（`rule=short`），说清为什么没查
2. 没查的时候**不许**同时报出 short 缺陷（没查就不许给结论）
3. 登记够端子 → 规则必须真的跑了（不许有 skipped），而且必须给出读数

顺带把「登记了**三个**端子」也钉住：数量不对同样判不了，
不能因为「有 pads 字段」就当成登记好了。

## 七、副产物：本轮最大的坑不是判据，是数据

### 7.1 【实测】W7 的测试拿的是**2026-09-14 的旧图**

短路判据改完之后，W7 的 `pcb_operators` 套件**还是红的**，
而 W6 那边全绿。查下来：

| 位置 | `short.png` 大小 | 时间 |
|---|---|---|
| `W6_PCB_DefectProject/images/short.png`（真源）| 13092 | 2026-10-20 16:36 |
| `W7_VisionMasterLite/images/short.png`（**副本**）| 12744 | 2026-09-14 09:39 |
| `W7_VisionMasterLite/build/test_work/pcb_operators/images/short.png`（暂存）| 12744 | 2026-10-20 16:38 |

`W7_VisionMasterLite/images/` 是一份 **2026-09-14 的 demo 板副本**，而且**两份都进 git**。
W7 的构建脚本从**自己那份**拷测试图 —— 于是：

- 改了 W6 的生成器 → W6 的测试用新图 → 全绿
- W7 的测试用旧图 → 判据按新逻辑判旧图 → **结论照样自洽**，红得莫名其妙

**「判据变了、数据没跟上」的现象，和「判据写错了」一模一样** ——
这是最贵的那类 bug：看起来是代码问题，其实是数据问题。

### 7.2 【实测】修法：图只留一份

- 删掉 `W7_VisionMasterLite/images/`（9 个跟踪文件 + 5 个 `w7_video_f*.png` 残留）
- W7 的构建脚本改成从 `../W6_PCB_DefectProject/images` 取（那才是生成器住的地方）
- `W7_VisionMasterLite/README.md` 里那句「`images/` # 测试图(复用 W6)」是**假的**（是复制不是复用），一并改成实话

> 📌 这是本项目「抄副本」栽的**第五次**。前四次抄的是代码，这次抄的是**数据** ——
> 数据副本更隐蔽，因为它不会编译报错。
> 详见 `atomic/at-stale-data-copy-fakes-a-pass.md`。

### 7.3 【实测】顺带把「产物落进样本目录」也拆了

`W6_PCB_DefectProject/images/` 里躺着 4 个 `w6_inspect_*.png` ——
是 `inspect` 子命令的输出，而 `images/` 是**待检样本目录**。
W6 的批量报告得专门加一条「跳过 `w6_inspect_*`」的过滤规则兜着 ——
那条规则本身就是「输入目录和输出目录混用」留下的疤。

改法：`inspect` 的标注图改写 `out/`（和 OCR 中间产物一致，README 里早就这么写了），
`images/` 只剩生成器产出的样本。`report/report.csv` 也取消跟踪（`.gitignore` 早就声明过）。

### 7.4 【实测】一条断言依赖了「仓库里恰好有的脏文件」

删掉那些 `w6_inspect_*.png` 之后，W6 的 CLI 测试红了：

```
[FAIL] 有图被跳过(inspect 生成的叠加图)
```

这条断言测的是「report 遇到非样本文件会跳过并说明原因」，
但它用的是**仓库里恰好存在的残留文件**。哪天有人清理了 `images/`，测试就红，
而代码一行没改。

改成：测试**自己造**一张 `w6_inspect_probe.png` 放在临时目录里，再断言它被跳过、并且说清原因。
行为照测，依赖去掉。
