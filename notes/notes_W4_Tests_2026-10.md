## 2. 为什么它之前是 0 个测试

不是因为不重要，是因为**写不了**。

W4 的整条链写在 `main()` 里：

```
生成图 → 抠模板 → matchTemplate → minMaxLoc → 画红框 → imwrite → imshow
```

外面挂着 **4 个 `imwrite`（要写盘）和 4 个 `imshow` + `waitKey`（要显示器）**。
这两个都不是无头环境能做的，于是这一层**永远只能靠人眼看** ——
而「人眼看」和「没看过」在报告里长得一模一样。

所以补法的第一步不是「给 `main.cpp` 加个开关」，而是**把纯逻辑拆出来**：

| 文件 | 里面是什么 |
|---|---|
| `W4_TemplateFeature/feature_pipeline.{h,cpp}` | 生成图 / 抠模板 / 算相似度图 / 找最佳匹配 / 找全部匹配（带 NMS）/ 标注，**加全部常量**；ORB 检测 / 描述子 / 比率检验 / 单应性 |

`main.cpp` 和测试套件**链的是同一个 `.cpp`**（同一个源码进两个 CMake 目标），
和 W1 的 `pixel_ops`、W2 的 `color_pipeline`、W3 的 `edge_pipeline`、
W6 的 `w6_cli` 是同一个做法。

### 抽出来之后顺手治好的三件事

**一、裁剪越界会给出空图，而不是悄悄裁成半个。**

原来的 `main.cpp` 里裁剪是直接 `img(rect)`。
裁剪范围有一半在外面时，OpenCV **不报错**，它给你能裁的那一半。

而「半个模板」照样能匹配，而且**分数还挺高** ——
匹配的是**半个目标**，报告出去的是「找到了，0.98 分」。
那比「抠不到」糟得多。

现在 `cutTemplate` 的约定是：范围必须**整个**在图内，否则返回**空图**。
（这条是**测试逼出来的**：套件第一版断言写的是「越界要报错」，
实现没这么干 —— 修的是**实现**，不是断言。）

**二、生成器带上了种子。**

老的生成器用 `cv::randn` 却**没设种子** —— 两次跑出来的是**两张不同的图**。
「这张图长这样」这句话根本没法被引用，测试也就无从写起。

现在种子是**参数**（`generatePcbImage(seed)`），默认 20261029，
噪声走 `common/pcb_sim/pcb_sim.h` 里那个**已经带种子**的 `addNoise`。

**三、顺带发现的一处「抄副本」（第三份）。**

W4 原来的 `main.cpp` 里**内联抄了一份合成图**：
尺寸 640×480、8 个焊点的矩形、焊点颜色、板面底色、噪声强度，
**逐条与 `common/pcb_sim/pcb_sim.h` 相同** ——
而那行注释偏偏写着「**W3 同款 8 个金色元件**」。

⇒ **注释说同款，代码是抄的。**

这是「合成 PCB 图的事实」的**第三份**
（W2 抄过 W3 那份，W3 抄过 W2 那份，W4 又抄了一份），
而且**跨了三个项目** —— 谁也没跨过去看一眼，
三份各自的测试**都是绿的**（因为那时候 W4 还没有测试）。

收法：W4 从 `common/pcb_sim/pcb_sim.h` 取，一个常量都不自己写。

## 3. 断言从哪来：每个门槛都是**量出来的**

写断言最容易犯的错是**拍一个数**。
本轮所有非平凡的门槛都是**先量、再写**，而且**留了余量**。

| 量 | 实测 | 断言门槛 |
|---|---|---|
| 相似度图尺寸 | 561×401（= 640−80+1, 480−80+1） | 精确 |
| 独立金块模板 + CCORR_NORMED 的最佳分数 | **0.985996** | ≥ 0.98 |
| 独立金块模板 + CCOEFF_NORMED 的最佳分数 | **0.030943** | ≤ 0.10 |
| 两种 method 的分数差 | **0.955053** | > 0.5 |
| 8 个焊点的分数散布 | **0.985409 ~ 0.985996**（差 0.000587） | < 0.001 |
| 背景上的最好分数 | **0.982913** | 焊点最低分 > 背景最好分 |
| 朴素数像素（阈值 0.90） | **12376** 个 | > 1000 |
| NMS 之后的匹配数（阈值 0.90~0.98） | **8** | = 8（四个阈值都断） |
| 阈值 0.99 | **0** 个 | = 0 |
| NMS 半径 40/60/80/100 | **8** 个 | = 8（四个半径都断） |
| NMS 半径 10 | **104** 个 | > 20 |
| 纯色模板 + CCOEFF_NORMED 的分数图 | **每一处都是 1.0** | 精确 |
| ORB 模板高 60 | **0** 个关键点 | = 0 |
| ORB 模板高 80 | **162** 个关键点 | ≥ 50 |
| 文字模板的好匹配 | **127** 对 | ≥ 100 |
| 单应性还原四角的误差 | **0.76** 像素 | < 3.0 |
| 拿金块当 ORB 模板的好匹配 | **0** 对 | ≤ 5 |

### 门槛为什么留余量

余量不是为了「让测试好过」，是因为**噪声的实现细节可能随 OpenCV 版本变**。
门槛卡死在一个实测值上，就成了「只有这台机器成立」的断言 ——
那正是本仓库在 CI 第一次真跑时栽过的坑
（`notes/notes_CI_FirstRunnerRun_2026-10.md`）。

例外是**定义性**的量：分数图尺寸、分数图是不是全 1.0、
最佳位置是不是 (0,0) —— 这些是**算法的定义**，不是实现的巧合，
卡死是对的。

## 4. 最值钱的一条：「像」是什么意思，是 method 定的

W4 的 demo 一直用 `TM_CCOEFF_NORMED`，README 里也写着「**工业首选**」。

**那话对有纹理的模板成立，对纯色模板不成立。**

实测（**同一个**金块模板，**同一张**图）：

| method | 最佳分数 | 位置 | 看得见目标吗 |
|---|---|---|---|
| `TM_CCORR_NORMED` | **0.985996** | (200,100) | ✅ 落在焊点上 |
| `TM_CCOEFF_NORMED` | **0.030943** | (386,373) | ❌ 跑到**背景**上去了 |

**分数差了 0.955053。**

原因不是谁对谁错，是**两个 method 在回答两个不同的问题**：

- `CCORR`（相关性）**不去均值** ⇒ 「这块地方**长得像**这个模板吗」
- `CCOEFF`（相关系数）**去均值** ⇒ 「这块地方**的起伏**像这个模板吗」

纯色金块**没有起伏** —— 它的方差就是噪声。
去均值之后能比的只剩噪声，而模板的噪声和图上的噪声**是两回事**，
相关性本来就该接近 0。

⇒ **「形状一样」这件事，在 CCOEFF 的眼里根本不存在。**

而最难受的地方是：**它不报错**。
OpenCV 照样给你一张分数图、一个位置、一个看起来很正常的分数 0.03。
你不去看，就不会发现它指着一块**什么都没匹配到**的背景。

### 这条为什么值得单独开一张卡

它不属于「抄副本」，也不属于「门槛的产物」——
它说的是**更前面一层**的东西：

> **「像」不是一个客观事实，是一个被定义出来的量。**
> 定义它的是 **method**（减不减均值、归不归一化）+ **输入**（模板本身）。
> 换掉任何一个，「像」就变成另一个东西了。

而它的两个**极端**都在这一轮里出现了：

| 极端 | 实测 | 含义 |
|---|---|---|
| 分数 **1.0** | 自己抠的模板 → **1.000000**，就在它被抠下来那一点 | 这个分是**白送的**：任何图和自己匹配都是 1.0，它**不含任何信息** |
| 分数 **0.03** | 纯色模板 + CCOEFF → **0.030943**，位置在背景上 | 这个分**不含任何信息**：它比的是噪声 |

⇒ **1.0 不代表「找到了」，0.03 也不代表「没找到」。**
分数的大小**不告诉你**「像」这件事本身是怎么定义的。

新卡：`notes/atomic/at-the-method-decides-what-similar-means.md`。

### 顺带一条：极性取反了**不会报错**

`TM_SQDIFF` / `TM_SQDIFF_NORMED` 是**越小越像**，其余四种**越大越像**。
取反了 OpenCV 照样给你一张图 ——
只是那个位置是**最不像**的地方。

实测：`TM_SQDIFF` 的**最大**值 **290282720** 落在 (496,17)，
**背景里**；而**最小**值 **15307885** 落在 (200,100)，**焊点上**。

⇒ 这一层把「按 method 决定取哪个极值」收成了**一个函数**
（`higherIsBetter` / `bestMatch`），
不让每个调用方各自记一遍 —— 记错一次就是一次**静默的错答案**。

## 5. 多目标匹配：8 这个数，是**两个旋钮**共同定的

朴素做法「数一数分数超过阈值的像素」在阈值 0.90 时数出 **12376** 个。

为什么？因为**目标是一片区域，不是一个点** ——
一个 80×80 的焊点在分数图上占好大一块，过了线的像素当然多。

加了 NMS（贪心，半径 80）之后是 **8** 个，全落在焊点上。

### 但「8」这个数不能只是「8」

W3 那轮栽过一回：断言写的是「== 6」，而那个 6 是**面积门槛的产物** ——
门槛一改，结论就翻。

这一轮**同一个道理**：多目标的个数天然是**阈值和半径的产物**。

所以断的是**两个旋钮各自的范围**：

| 旋钮 | 动过的范围 | 结果 |
|---|---|---|
| 阈值 | 0.90 / 0.93 / 0.95 / 0.98 | **8 / 8 / 8 / 8** |
| 阈值 | 0.99 | **0**（上界写进断言里） |
| NMS 半径 | 40 / 60 / 80 / 100 | **8 / 8 / 8 / 8** |
| NMS 半径 | 10 | **104**（一个目标被拆成很多个） |

⇒ 「8」成立的范围被写成了**两段**，而不是一个孤零零的数。

## 6. ORB：两种「不报错」，两种后果

### 一、模板太矮 ⇒ 给你 0 个关键点

同样宽 380 的裁剪，高度不同：

| 高 | 关键点数 |
|---|---|
| 60 | **0** |
| 70 | 109 |
| 80 | **162** |

原因是 ORB 默认 `edgeThreshold=19`、`patchSize=31` ——
矮于这个尺寸，特征全被当边界扔了。

**它不报错。** 它给你一个空描述子矩阵，
你要是接着往下调 `findHomography`，才会撞上另一个错
（匹配点不够 4 对 ⇒ 算不出单应性）。

而这一层现在的约定是：**好匹配不足 4 对时返回空矩阵**，
不给一个假的 —— 给一个假的比不给更糟。

### 二、8 个一模一样的焊点 ⇒ ratio test 全毙掉

拿**金块**当 ORB 模板，好匹配 **0 对**。

不是 ORB 坏了，是这张图**分不出谁是谁**：
模板上的每个描述子，在图里都能找到 **8 个一样好的**候选 ⇒
次好距离和最好距离差不多 ⇒ **Lowe ratio test 把它们全毙了**。

⇒ 而**唯一**的那块文字当模板，好匹配 **127 对**。

> **模板唯一，才谈得上「匹配」。**
> 这是这一轮里和第 4 节同一个道理的两面：
> 「像不像」既是 method 定的，也是**候选的独特性**定的。

### 三、关键点的个数是**参数的产物**

`nfeatures` 是**上限**，不是承诺：
实测 50/100/200/500 → 各找出这么多；1000 → **960**（图上总共就这么多）。

所以「找到 N 个关键点」这句话**本身没信息** ——
N 是 `nfeatures` 的产物。

断的是**位置**：

> 用 `nfeatures=100` 找到的那些点，在 500 的那一遍里**也得在**
> （实测 **100/100** 命中，容差 1 像素）。

⇒ **位置是图的性质，不是参数的产物。**

## 7. 变异验证：6 条，6 条都红

绿着的测试证明不了任何事 —— 得先看它**红**一次，
而且红在**对的那条断言**上。

`build/probe/mutate_w4.ps1`（**gitignore 掉**，不入库）：

| # | 变异 | 期望 |
|---|---|---|
| M1 | `higherIsBetter` 永远返回 true | 平方差类的极性断言红 |
| M2 | NMS 半径判断改成 `<= 0.0` | 半径 10 那条红（104 → 8） |
| M3 | ORB 模板 80 → 60 | 「模板高 80 找得到一堆」红 |
| M4 | 单应性的 src/dst 对调 | 四角还原误差红 |
| M5 | Lowe ratio test 去掉 | 好匹配数红 |
| M6 | `pcb_sim.h` 里 `theRNG() = RNG(seed)` 被删掉 | 「同一个 seed 同一张图」红 |

结果：**6/6 红**，恢复后 **57/0 绿**。

> M6 改的是**共享核心里**的一行，不是 W4 自己的文件 ——
> 这正是「一个实现，两个调用方」的价值：
> 改一处，**两边**的测试都会红。

### 恢复的时候要记得改时间戳

`Copy-Item` **保留**源文件的时间戳 ⇒ 恢复后的文件比目标旧 ⇒
MSBuild 认为「已经是最新的」**跳过重建** ⇒
「恢复完毕」的那棵树其实还是被改过的那棵。

脚本在恢复之后**显式把 LastWriteTime 打到当前时间**。
这个坑是 W3 那轮踩过的，这里直接抄了做法。
