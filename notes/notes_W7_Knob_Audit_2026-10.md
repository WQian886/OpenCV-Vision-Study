## 一、为什么要做

起因是一个很朴素的疑问：**W7 的参数面板上，有多少个旋钮是"调了不生效"的？**

脚本扫完全部 16 个算子，答案是：

| 旋钮 | 声明的默认值 | `run()` 里的兜底 | 面板上的初值 |
|---|---|---|---|
| `blob_count.min_area` | 20 | **50** | 20 |
| `count_check.expected_min` | 1 | **0** | 1 |
| `count_check.expected_max` | 100 | **999** | 100 |
| `circle_fit.min_area` | 100 | 100 | 100 |
| `circle_fit.min_circularity` | 0.70 | 0.70 | 0.70 |
| `template_match.threshold` | 0.9 | 0.9 | 0.9 |
| `dl_infer.conf_threshold` | 0.25 | 0.25（编译期停用分支） | 0.25 |
| `dl_infer.nms_iou` | 0.45 | 0.45（编译期停用分支） | 0.45 |
| `image_source_camera.exposure` | 10.0 | 10.0 | 10.0 |

**三处已经漂了**，而且漂的方式正好是最阴的那一种：

- `blob_count.min_area`：参数 JSON 里缺这个 key 时，算子按 **50** 滤，
  面板上写的是 **20**。用户调的值和算子用的值不是一回事。
- `count_check.expected_min/max`：兜底是 **0 和 999**，
  而声明的是 **1 和 100**。`0..999` 几乎等于"不判定"——
  上游给什么数都判合格。
- `pcb_inspect`：`defaultParams()` 登记的是 `min_area = 80`（绝对像素），
  而 `run()` 读的是 `min_area_pct`（占全图 %）。
  **登记的和读的不是同一个 key**，于是：
  - `min_area` 成了**死旋钮**（面板上写着、调了不生效）
  - `min_area_pct` **从来没登记过** —— 它的默认值只活在 `run()` 的兜底里，
    写进流水线的参数 JSON 里压根没有这个 key。

> 「同一个数抄多处，改的时候一起改」这句话是**许愿**，不是工程。
> 本项目已经在这条路上栽过五遍（见 `notes/atomic/at-four-copies-of-one-number.md`）。
> 这一轮的做法是：**让第二份不存在**。

## 二、A2：默认值收成唯一一份

新建 `W7_VisionMasterLite/operators/operator_defaults.h`：

```
namespace w7 {
struct CircleFitDefaults {
    static constexpr int    kMinArea        = 100;
    static constexpr double kMinCircularity = 0.70;
};
...
}
```

一个算子一个 struct，成员就是它的旋钮默认值。
**16 个算子的全部默认值都在这一个文件里**（共 59 个常量）。

三个使用点全部改成引用它：

| 位置 | 原来 | 现在 |
|---|---|---|
| `defaultParams()` | `p["min_circularity"] = 0.70;` | `= CircleFitDefaults::kMinCircularity;` |
| `run()` 兜底 | `params.value("min_circularity").toDouble(0.70)` | `.toDouble(CircleFitDefaults::kMinCircularity)` |
| 面板 `buildUI()` | `m_minCircularity->setValue(0.70)` | `.setValue(CircleFitDefaults::kMinCircularity)` |

改的不是"记得一起改"，是**没有第二份可改**。

### 2.1 「读不到就用声明的默认值」这条规则补齐了 5 处

`run()` 里有几处 `params.value("x").toString()` **没有兜底** ——
key 缺失时得到空串，和声明的默认值不是一回事：

| 算子 | key | 补上的兜底 |
|---|---|---|
| `dl_infer` | `model_path` | `models/yolov8n.onnx` |
| `dl_infer` | `class_names` | COCO 类名表（原来**完全没有**兜底，缺 key 时框上只剩 `cls3` 这种编号） |
| `image_source_camera` | `camera_ip` | `192.168.1.10` |
| `image_source_dir` | `dir_path` | `images` |
| `image_source_video` | `video_path` | `images/sample.avi` |
| `template_match` | `template_path` | `templates/R.png` |

### 2.2 必填旋钮：**不**补默认值

有两处**故意不补**：

- `color_segment` 的 `hsv_low` / `hsv_high`
- `pcb_inspect` 的 `hsv_h_low` / `hsv_h_high` / `hsv_s_low` / `mask_v_mul`

这两个区间**就是**用户要调的东西，没有它们等于没配置。
补一个默认值会让用户以为自己的配置生效了 ——
那正是 `operators/hsv_params.h` 开头警告的
「配置看着对、结果全错」。两边都有测试钉着
（`test_detection_operators.cpp`「参数完全为空 → 报 error」、
`test_pcb_operators.cpp`「H 上界缺失 → 报错」）。

**必填与可选要分开**：全当必填，少个 key 整条算子罢工；
全当可选，用户填错的值会被悄悄换成默认值。

### 2.3 编译期停用的算子：旋钮置灰 + 写明原因

`dl_infer`（ONNX Runtime）和 `image_source_camera`（海康 MVS SDK）
没装 SDK 时，那部分代码**根本不参与编译**。
面板上那些旋钮当前**一个都不生效** —— 摆着能调但没用的旋钮 = 骗人。

做法：

1. 两个算子各加 `static bool runtimeAvailable()` 和
   `static QString runtimeUnavailableReason()`；
   `reason` 里写清楚**怎么修**（去哪下载、解压到哪、设哪个环境变量）。
2. 运行时缺失时，面板的旋钮**置灰**，并把原因显示出来。
3. `reason` 这一份字符串同时给三处用（面板提示 / `Run()` 时的 error /
   审计套件的断言）—— 只有一份，不会出现"面板说 A、Run 说 B"。

> ⚠ 这一步**没有自动化测试**：置灰是 QtWidgets 的行为，
> 无头测试构造不了真窗口。能测的是 `runtimeAvailable()` 本身
> 和审计里"豁免清单不能过期"那条断言。

## 三、A3：旋钮审计

六条用例，各自的能力边界都写在用例的注释里：

| 用例 | 查什么 | 手段 | 边界 |
|---|---|---|---|

| 1 | 死旋钮 | 源码 lint：登记了但当前构建的 `run()` 没读 | 只认 `params.value("x")` 这种读法 |

### 3.1 用例 1 的"当前构建"是什么意思

`dl_infer` 有两支 `run()`，只有一支参与编译。
审计要判"**这个构建里**读不读得到"，就得知道预处理分支走哪一支。

做法：自己算一遍 `#ifdef / #ifndef / #else / #endif`，
把不参与编译的行**清空**（保留行数），再在剩下的源码里找函数体。

而"这个构建有没有装 ONNX Runtime"不靠猜 —— **直接问算子自己**
（`DlInfer::runtimeAvailable()`）。问错的话分支整个认反，
比没有审计更坏。

### 3.2 豁免清单会互相校验

```cpp
static const Exemption kExemptions[] = {
    {"dl_infer",
     {"input_w", "input_h", "conf_threshold", "nms_iou", "class_names", "output_layout"},
     "本机没装 ONNX Runtime(环境变量 ONNXRUNTIME_DIR 未设置):"
     "真实推理路径整段在 #ifdef HAS_ONNXRUNTIME 里,没编进来;..."},
};
```

- **漏登记** → 用例 1 报红（有人新加了个停用分支，忘了登记）
- **过期了**（SDK 装上了，旋钮其实已经生效）→ 用例 4 报红（该删这条）

所以这份清单不会自己烂掉。

## 四、这一轮最值钱的发现：审计自己一开始是**恒真的空断言**

第一版审计套件，**全绿**。

但它其实**一个算子都没扫到**：

```
DEBUG 扫到 0 个算子源文件
```

三个 lint（用例 1/2/3）全部作用在空集合上，
于是"没有死旋钮"、"没有没登记的旋钮"、"默认值没有裸字面量"
—— **三条断言全是真的，但全是废话**。

这就是本项目记过的第 12 条教训的**升级版**：
守卫写成"打不开就 `return`"，它就变成恒真的空断言。
而这次更糟一层：**空断言长得很像通过**。

### 4.1 三个 bug，一个比一个隐蔽

**① 限定符卡在中间，函数体找不到**

```cpp
QJsonObject CountCheck::defaultParams() const {
                                       ↑ 这里有个 const
```

第一版 `functionBodies()` 只跳空白，遇到 `const` 就以为"这不是定义"，
于是 **17 个算子一个都没扫到**。

**② 算子名在头文件里，不在 .cpp 里**

```cpp
// count_check.h
QString name() const override { return "count_check"; }
// count_check.cpp —— 压根没有这一行
```

第一版在 .cpp 里找 `name()`，自然找不到。

**③ for 循环的自增吃掉了一个右括号**

```cpp
QJsonObject ImageSourceCamera::run(const QJsonObject& params,
                                    const QJsonObject& /*inputs*/) {
```

去掉块注释后，`for` 循环的自动 `++i` 会把 `*/` 后面的 `)` 一起吃掉：

```
run(const QJsonObject& params, const QJsonObject&  {      ← 右括号没了
```

括号配对数错 → 整个 `run()` 函数体找不到 →
**相机的三个旋钮全被误判成"死旋钮"**。

> 同一个逻辑的 Python 复刻是**对的** —— Python 的 `while` 循环不会自动自增。
> **复刻不等于等价**：两份实现连"自增在哪"都不一样。

### 4.2 修法：给审计自己加守卫

用例 0 就是为这次写的：

```cpp
check(ops.size() >= 15, "扫到至少 15 个算子源文件 —— 扫不到就是审计没在工作");
check(total >= 70,   "一共扫到至少 70 个旋钮 —— 解析器坏了的话这个数会掉下去");
```

外加每条 lint 开头都有：

```cpp
if (ops.isEmpty()) {
    check(false, "没扫到任何算子 —— 这条审计等于没跑(恒真的空断言)");
    return;
}
```

> **断言也会骗人**，如果它断言的东西本身是空的。
> 所以断言的对象不只是"代码的行为"，还包括"审计自己的输入"。

## 六、第二轮：审计扩到三处（欠账 1 收口）+ 欠账 6 收口

上一轮的审计只查 `defaultParams()` ——
但同一个默认值在源码里有**三个位置**：

| 位置 | 写的是什么 | 它决定的是 |
|---|---|---|
| `defaultParams()` | 写进流水线 JSON 的那份 | 参数 JSON 里的值 |
| `run()` 兜底 | `params.value("x").toInt(EXPR)` 里的 `EXPR` | key 缺了时算子按什么跑 |
| 面板 `buildUI()` | `setValue(EXPR)` 里的 `EXPR` | 界面上写着的那个数 |

第二、三个当时**没人看**。
这一轮把它们纳入审计，顺手把欠账 6 也关掉。

### 6.1 新增的三条 lint

| 编号 | 查什么 | 怎么查 | 边界 |
|---|---|---|---|
| 3d | 兜底不许抄第二份 | 扫 `run()` 里 `params.value("KEY").toXxx(EXPR)`：EXPR 不许有裸字面量；引用的 `*Defaults::` 必须是**本算子**的结构体 | 只看 `toXxx(...)` 的参数，套在外面的运算看不见 |
| 3e | 面板初值不许抄第二份 | 扫 `buildUI()` 里每个 `setValue(EXPR)`：EXPR 不许有裸数字 | 只看 `setValue`；`setRange`/`setSingleStep`/`setDecimals` 是量程不是值 |
| 3f | 字符串型默认值得露在面板上 | `defaultParams()` 引用字符串型常量时，`buildUI()` 必须引用**同一个**常量 | 只要求常量**出现**，不保证它被用作了控件初值 |

三条 lint 查的是**所有分支**的 `run()`，不只当前构建那一支 ——
`dl_infer` 那 6 个旋钮在当前构建里读不到（整段在 `#ifdef` 里），
但那一支的兜底是**装上 SDK 之后立刻生效**的代码。

> 规则设计上有一次**否决**：笔记原来建议"同一个字面量在同一个文件里出现 >1 次就报"。
> 实测**误报太多** —— `setRange(0, 255)`、`setSingleStep(10)`、`lo[0]` 全会被扫出来，
> 而它们一个是量程、一个是步长、一个是**下标**。
> 最后收成"**兜底/初值的表达式里不许有裸字面量**"：
> 判据更窄，但零误报。**规则宁窄勿宽 —— 误报的守卫会被下一个人关掉。**

### 6.2 这三条当场抓出 6 处真问题

| 算子 | 面板上的初值 | 声明的默认值 | 病 |
|---|---|---|---|
| `pcb_inspect` 金层区间 | `setValue(85/80/115/0.8)` | `pcbcolor::goldBand()` | 数字抄本 |
| `dl_infer.class_names` | placeholder `"person,bicycle,car"` | COCO 六个类名 | 抄本，**只抄了前三个** |
| `image_source_camera.camera_ip` | placeholder `"如 192.168.1.10"` | `"192.168.1.10"` | 抄本 + 框是空的 |
| `image_source_dir.dir_path` | placeholder `"如 images 或 D:/test_imgs"` | `"images"` | 抄本 + 框是空的 |
| `image_source_video.video_path` | placeholder `"如 images/sample.avi"` | `"images/sample.avi"` | 抄本 + 框是空的 |
| `pcb_inspect.mode` | `addItem(..., "known_site")` | `PcbInspectDefaults::kMode` | 抄本 |

金层那处值得单说：它和 `pcbcolor::goldBand()` 的数值**完全一致**，
所以从任何一次运行的结果上**看不出毛病**。

但它就是抄本 —— 校准值一改，面板就悄悄对不上了，
而界面上不会有任何提示。

### 6.3 「框是空的」也是一份默认值

`image_source_dir` 那三处的病比"抄本"还重一点：

```
defaultParams() 声明   dir_path = "images"
        ↓
面板 buildUI()         m_dirPath 是空的          ← 初值没给
        ↓
collect()              p["dir_path"] = ""        ← 把空串写回参数
        ↓
run()                  params.value("dir_path").toString("images")
                       → key 在,值是空串 → 返回空串,不是 "images"
        ↓
                       报错"目录不存在: "
```

**声明的默认值被面板吃掉了。**

它不是静默失效（它会报错），但报的是"目录不存在: "，
人会往**路径写错了**的方向查 ——
真实原因是"这个 key 压根没有默认值可用"。

修法统一成：初值直接取常量
（`new QLineEdit(QString::fromUtf8(ImageSourceDirDefaults::kDirPath))`），
提示语只留"例子"那一半。

### 6.4 欠账 6：审计扫的源码，必须是产品真在编译的那份

旋钮审计是**源码级**的 —— 它读 `operators/*.cpp` 的文本。
这套办法有个前提，从来没人写下来：

> **它读到的文件，必须是产品真在编译的那些文件。**

前提不成立时，审计**不会报错**，它会安静地查错东西。
最坏的一种：有人加了新算子但忘了加进 `CMakeLists.txt` ——
**主程序根本没编它**，审计却在查它的旋钮，还报"这个旋钮是死的"。

新增**用例 7**做双向核对：

- 磁盘上 `operators/*.cpp` 每个都必须在主程序的 `set(SOURCES ...)` 里
- `set(SOURCES ...)` 里列的每个都必须在磁盘上真的存在

⚠ 查 `CMakeLists.txt` 要按 **CMake 的注释规则**切（`#` 到行尾），
不能拿 C++ 那套（`//`、`/* */`）去切 ——
注释里写着 `operators/xxx.cpp` 的时候，那是**说明**，不是真的在编译。

### 6.5 欠账 5 的可测部分：运行时缺失必须说得出为什么

> ⚠ **这一节写错了一句，第六轮（第十一节）推翻了它**：
> 原文说"面板置灰本身测不了（QtWidgets 要真窗口，无头造不出来）"——
> **那是误判**。Qt 的 offscreen 平台插件可以在没有屏幕的机器上造出真的 QWidget，
> 本仓库另外 5 个套件早就在这么干了。第十一节把置灰本身也测了。

面板置灰本身测不了（QtWidgets 要真窗口，无头造不出来）。
但**另一半**能测：那句"为什么不能用"的文案。

新增**用例 8**：

- 运行时不可用 → 原因文案非空、点名了缺的是什么、说了要设哪个环境变量
- 运行时可用 → 不该挂着"缺失原因"文案

理由跟置灰一样：**摆着能调但跑不了的旋钮 = 骗人**。
光置灰，用户只知道"不让调"，不知道为什么；
只写"不可用"，等于把问题原样推回给用户 ——
那是**没写**，不是**写清楚了**。

## 七、第三轮：旋钮值"类型不对"时必须说出来（欠账 6 收口）

上一轮把面板上 6 份抄副本收掉了，但**抄副本只是表面**。
真正让"配置看着对、结果全错"发生的是另一件事：
**值类型不对的时候，算子静默按默认值算**。

### 7.1 先测 Qt 的行为，不照文档猜

改代码之前先探了一下 `QJsonValue::toInt(默认值)` 到底怎么表现
（一次性探针，跑完就删）：

| 值 | `toInt(77)` | `toDouble(77.5)` |
|---|---|---|
| 整数 `25` | **25** | 25 |
| 小数 `25.7` | **77** | 25.7 |
| 字符串 `"100"` | **77** | **77.5** |
| 字符串 `"abc"` | 77 | 77.5 |
| 布尔 / 数组 / 对象 / null / 缺失 | 77 | 77.5 |

两条反直觉的事实：

1. **字符串不会被解析** —— `"100"` 不是 100，是**默认值**。
2. **小数不会截断** —— `25.7` 不是 25，是**默认值**。

也就是说：**在 `QJsonValue` 眼里，"类型不对"和"缺失"是同一件事** —— 都返回默认值。

而这两种情况的**正确待遇完全相反**：

| | 该怎么办 | 理由 |
|---|---|---|
| **缺失**（用户没配） | 退到**声明的默认值** | 用户没填，退回去是诚实的 |
| **类型不对**（用户配了，但配坏了） | **报错** | 用户以为自己填的生效了，实际跑的是默认值 —— 「配置看着对、结果全错」 |

这条规矩 `operators/hsv_params.h` 里早就定下了（"形状不对就报错，不补默认值"），
只是**可选旋钮**那边一直没实现。

### 7.2 做法：新的 `operators/param_read.h` + 五个测量算子迁移

新建 `operators/param_read.h`：

- `jsonAsInt(v, &out)` —— 这个 JSON 值能不能当整数用（**带范围检查**：
  QJsonValue 能装 1e300，而 `static_cast<int>(1e300)` 是未定义行为，
  MSVC 上会得到 INT_MIN，不报错，直接算错）
- `readIntKnobs(params, keys, defaults, out, err)` —— 读一组整型旋钮：
  缺失 → 用 `defaults` 里声明的值；类型不对 → **报错**，点名是哪个 key
- `knobValueForWidget(v, defaults, key)` —— 面板用：
  类型不对 → 显示**声明的默认值**（不是 0）

五个测量算子（`line_fit` / `point_point_dist` / `caliper_dist` /
`point_line_dist` / `angle`）全部迁过去，顺手收掉三处副本：

| 收掉的东西 | 以前 | 现在 |
|---|---|---|
| 兜底值 | 每个算子手写 `.toInt(XxxDefaults::kX1)` | `readIntKnobs(..., defaultParams(), ...)` —— **声明值只有一份** |
| 键名 | `Form::kKeys[]`（面板）+ `params.value("x1")`（算子）**两份** | 一个文件里的 `kCoordKeys`，两边共用 |
| 面板读回时的兜底 | `toInt(0)` —— 和声明值不一致的第二份 | 声明的默认值 |

`caliper_dist` / `point_line_dist` 原来在 `run()` 里读 **double**、
面板上是 **QSpinBox（整数）** —— 面板和算子对"这个旋钮是什么类型"
本来就没对齐。现在两边统一成整数像素坐标。

### 7.3 新增 lint 3g：面板读回时的兜底也不许是另一份

`setParams()` 里从 params 读旋钮时，兜底必须是指名的常量。

这条特别要抓 **`toInt()` / `toDouble()` 不带参数** ——
看着像"没写兜底"，其实是 Qt 的默认参数 0，
而它是**隐式**的：源码里看不见那个 0，lint 也不看不见。

实测抓到 4 处：`blob_count` / `count_check`（两处）/ `image_source_camera` / `template_match`。
都改成了声明的默认值。

### 7.4 中途翻车：审计认不出新写法，它开始撒谎

迁移完一编译，审计立刻报 **28 条"死旋钮"**
（8+6+6+4+4，正好是五个测量算子的坐标旋钮个数）。

而这 28 个旋钮**明明被读了** —— 审计的 `parseReads()` 只认
`params.value("x1")` 这种字面量键名，而新读法把键名放进了常量：

```cpp
const QStringList kCoordKeys = {"x1", "y1", "x2", "y2"};
readIntKnobs(params, kCoordKeys, defaultParams(), &c, &err);
```

误报比漏报危险：漏报是"没查出来"，你会知道少了一块；
误报是"查出来了，而且很肯定" ——「angle.x1 是死旋钮」这句话完全可信，
但它是假的，下一个人会去查旋钮，**而旋钮好着呢**。

修法两处一起：

1. 审计学会新读法（解析源文件里的"键名清单"常量）。
2. **认不出的时候明说"我认不出"**，而不是判成"死旋钮"。

> 顺带记一笔：这次是靠**数字对得上**才反应过来是"审计没跟上"，
> 不是"代码写错了" —— 红的正好 28 条，和坐标旋钮个数一模一样。

### 7.5 新增行为用例 9：旋钮值类型不对时必须说出来

五个测量算子各 3 条：

- 存成**字符串** → 必须报错，且**点名是哪个旋钮**
- 存成**小数** → 同样要报（旧代码是**整个值丢掉**，不是四舍五入）
- **缺这个旋钮** → 不报错（用户没配，按声明的默认值算）

⚠ 这条只盯**已经迁移的那五个**。其余算子还是
`params.value("k").toXxx(默认值)`，类型不对时同样静默 —— 那是欠账。

### 7.7 收尾时又挖出来一处：有名字的常量**也**是抄副本

准备提交前复核 `template_match`，发现它的"匹配方法"默认值抄在**三处**：

```cpp
// defaultParams()
p["method"] = cv::TM_CCOEFF_NORMED;
// run() 的兜底
params.value("method").toInt(cv::TM_CCOEFF_NORMED);
// setParams() 的兜底
params.value("method").toInt(cv::TM_CCOEFF_NORMED);
```

三处写的都是同一个枚举，**值一样，所以没有任何一条规则报红**。

但它是抄副本：「默认用哪个匹配方法」是**这个算子自己的决定**，
那个决定写在算子文件里，就等于 `operator_defaults.h` 那份声明之外又多了一份。

而且它比裸字面量**更危险** —— 裸数字难看，`cv::TM_CCOEFF_NORMED`
看着像"引用库里的正规常量"，读代码的人不会去查它是不是唯一一份。
更巧的是它**不会漂**（三处都一样），恰恰因为不会漂，所以没人会去查。

> 教训：**"不是字面量"不等于"不是副本"。**
> 判断一份值是不是抄副本，要问的不是"它长得像不像常量"，
> 而是"**这个决定该由谁做**"。

收法：

| 位置 | 以前 | 现在 |
|---|---|---|
| 声明 | `cv::TM_CCOEFF_NORMED`（算子文件里） | `operator_defaults.h` 的 `TemplateMatchDefaults::kMethod` |
| `run()` 兜底 | 同上 | `TemplateMatchDefaults::kMethod` |
| `setParams()` 兜底 | 同上 | `TemplateMatchDefaults::kMethod` |
| 面板下拉框初值 | **"列表第一项恰好是它"**（巧合） | 按 `kMethod` 选那一项（声明） |

最后一行是顺带发现的第四处：面板那个下拉框的初值靠
「`TM_CCOEFF_NORMED` 恰好排在第一位」来当默认值 ——
那是**巧合**，不是声明。哪天改了默认值或者调了列表顺序，
面板上摆的方法和算子跑的方法就不是一回事了。

⚠ 同一个枚举在 `template_match.cpp` 里还会出现：合法**范围**检查
（`method < cv::TM_SQDIFF || method > cv::TM_CCOEFF_NORMED`）。
那是**范围边界**，不是默认值 —— 两者不是一回事，别混。

### 7.8 新增 lint 3h：兜底值不许是"从库里现抄的常量"

3d/3g 查的是"兜底值是不是裸字面量"，**查不出**上面那种写法。
所以补了 3h：**兜底表达式里不许直接出现 `cv::`**。

要用就在 `operator_defaults.h` 里声明一个具名常量，兜底引用那个。

这条**故意窄**：

- `pcbcolor::kDarkMul` 这类**共享**常量不算抄副本 ——
  `common/pcb_core/` 是 W6/W7 共用的唯一一份（见 `operator_defaults.h` 的"边界"一节）。
- 规则宁窄勿宽：误报的守卫会被下一个人关掉。

基线：**282 条断言**（上一节 279 —— 多了 3 条：
`kMethod` 收成一份之后，3b 多认出一个引用，3d 多认出一个兜底，3h 自己 1 条）。

| # | 变异 | 谁抓到 | 红了几条 |
|---|---|---|---|
| M20 | `setParams()` 的兜底改回裸枚举 `cv::TM_CCOEFF_NORMED` | 用例 3h | 1 |
| M21 | `run()` 的兜底改回裸枚举 `cv::TM_CCOEFF_NORMED` | 用例 3h | 2 |

## 八、第四轮：类型检查迁到**全部**旋钮

第三轮只迁了五个测量算子，其余算子还是"类型不对就静默按默认值算"。
这一轮把剩下的全迁了 ——
**16 个算子的 `run()` 里，再没有一个裸的 `params.value("k").toXxx(默认值)`。**

### 8.1 先把 helper 扩成三种类型

`operators/param_read.h` 原来只管整数。这一轮加了三样东西：

| 新增 | 干什么 |
|---|---|
| `KnobKind{Int, Double, Text}` | 这个旋钮该是什么类型 |
| `knobValueMatches(kind, v)` | **唯一判据**：这个 JSON 值能不能当这个类型用 |
| `readKnob(...)` | 核心：缺失 → 退声明值；类型不对 → **报错点名** |
| `readDoubleKnob` / `readTextKnob` | 两个便捷包装 |
| `knobDoubleForWidget` / `knobTextForWidget` | 面板侧：类型不对就显示**声明的默认值** |

⚠ 判据只有**一处**（`knobValueMatches`）——
算子读的时候用它，面板显示的时候也用它。
两边判据不一样的话，就会出现"面板显示 A、算子跑 B"。

### 8.2 两种读法：单个 / 一组

| 形式 | 什么时候用 | 长相 |
|---|---|---|
| **单个** | 旋钮少，或者类型不一样 | `readIntKnob(params, defaultParams(), "min_area", &v, &err)` |
| **一组** | 键多、类型一样，而且**键名本身是数据** | `readIntKnobs(params, kCoordKeys, defaultParams(), &v, &err)` |

"一组"那种把键名放进一个 `QStringList` 常量（算子和面板共用一份），
五个测量算子的坐标就是这么放的。
`pcb_defect_judge` 那 16 个判据阈值**没有**用"一组" ——
它们是十个各不相同的阈值，"一组"就得靠下标去对应变量，
读代码时得数着数才知道哪个是哪个。**可读性优先。**

### 8.3 面板那一侧：文本旋钮显示的是**空串**

旋钮的**算子侧**查了类型，**面板侧**也得对齐，否则变成另一种骗人：

```
存盘里 dir_path 存成了数字
  面板:toString() 不带参数 → 空串        ← 用户以为路径是空的
  算子:按声明值 "images" 跑              ← 实际跑的是另一个目录
```

用户点一下"应用参数"就把空串存进流水线了。
现在面板侧也走 `knobTextForWidget`（类型不对就显示声明值）。

整数和小数旋钮的面板侧**不用改** ——
`toInt(声明值)` / `toDouble(声明值)` 在类型不对时本来就返回声明值，
和 `knobIntForWidget` 一样。这不是巧合：Qt 的 `toXxx(默认值)`
语义就是"类型不对就用默认值"。

### 8.4 审计跟着升级（第三轮的教训：不能让审计开始撒谎）

第三轮踩过的坑：**代码换了读法，审计认不出，于是判成"死旋钮"** ——
28 条假"死旋钮"，而且撒谎的样子很像通过。

这一轮换了**两种**新读法，审计必须两种都认：

```cpp
readIntKnob (params, defaultParams(), "min_area", &v, &err)   // 单个
readIntKnobs(params, kCoordKeys,   defaultParams(), &v, &err)  // 一组
```

解析方式也换了：正则只用来**定位调用**，参数用
`matchBracket` + `splitTopLevel` 切 ——
因为参数里有括号（`defaultParams()`）、有引号（键名），正则切不准。
切不准就是"认不出"，而"认不出"会撒谎。

⚠ **"认不出"和"抄了第二份"必须分开报**：
前者是"审计的尺子不够"，后者是"代码有问题"。
混在一起，报出来的理由会指错方向。

### 8.5 规则搬家：3d 的检查从"兜底"搬到"声明"（新规则 3i）

这一轮最值得记的一件事。

3d 那条规则查的是"run() 的兜底引用的是**本算子**的 Defaults"。
迁完之后，兜底变成了 `defaultParams()` ——
**里面没有任何 `Defaults::` 引用了**，所以 3d 不红，它只是**从此什么都不查**。

> ⚠ 这比"规则变空断言"更阴：空断言还留着一个"扫到 0 条"的痕迹，
>   而这一种是**无声的** —— 断言数没怎么变、测试照样全绿、
>   规则还在跑，只是它检查的东西换了个位置。

收法是**搬家**，不是删掉：新增 **3i**
「`defaultParams()` 里引用的 Defaults 必须是本算子的」。
检查的内容一模一样，只是查的地方换了 ——
因为迁移之后，**声明才是兜底真正指向的地方**。

（这条单独写了一张 atomic 卡：`at-a-rule-that-moves-silently.md`。）

### 8.6 用例 9 扩到 23 个用例

第三轮只盯五个测量算子、只查"存成字符串"和"存成小数"两种坏值。
这一轮扩到 **23 个用例**，覆盖整数 / 小数 / 文本三类旋钮。

⚠ **"坏值"必须按旋钮类型分别取**，不能一个值打天下：

| 旋钮类型 | 坏值一 | 坏值二 |
|---|---|---|
| 整数 | 字符串 `"100"` | 小数 `25.7`（整数旋钮不能有小数） |
| 小数 | 字符串 `"0.9"` | `25.7` —— **合法！不许报错** |
| 文本 | 数字 `100` | 数字 `25.7`（数字不是文本） |

小数旋钮那一行是**反向断言**：25.7 对小数旋钮是合法值，
所以不但不许报错，还得专门查一条"不许报错"。
只查"该报错的时候报错了"会漏掉"不该报错的时候也报错"——
那同样是错的（用户填了合法值却被拒，而且没说是哪不对）。

## 九、第五轮：三条新能力（3j / 3k / 用例 1 的结构性护栏）

这一轮的目标很窄：**把三条早就想清楚的洞补上**，别再扩。
但写着写着又挖出两处（9.4、9.6），所以这一轮比计划的厚。

### 9.1 欠账 12 收口：新规则 3j

**病**：`operators/circle_fit.cpp` 里自己写

```cpp
constexpr int kMinArea = 50;      // 第二份默认值
...
p["min_area"] = kMinArea;         // 声明用的不是 operator_defaults.h 那份
```

**为什么以前查不到**：3a 查的是"表达式里有没有裸字面量"，
而 `kMinArea` 是个**标识符** —— 3a 看不见；
3b 查的是"`XxxDefaults::kY` 是不是真在 operator_defaults.h 里"，
而本地常量压根不是 `XxxDefaults::` —— 3b 也没东西可查。

于是它从两条缝里溜过去了。**两条规则都看不见一个标识符。**

**判据：不猜意图，只问「这个值从哪来」**：

| 情况 | 例子 | 判 |
|---|---|---|
| ① 值是字面量 | `const int kFooLocal = 50;` | 红 —— 这就是一份手抄的默认值 |
| ② 值指向**别的算子**的 Defaults | `const int kForeign = CircleFitDefaults::kMinArea;` | 红 —— 绕过 3i 的后门 |
| ③ 值指向**本算子**的 Defaults | `const QString kDefaultRecipe = QString::fromUtf8(PcbInspectDefaults::kRecipePath);` | 放行 —— 它就是那份唯一清单 |
| ④ 压根没有初始化 | `const pcbcore::JudgeParams kCore;` | 放行 —— 它不是值 |

第 ③ 条是这条规则能落地的前提：**本地常量这种写法本身是合法的**，
`pcb_inspect.cpp` 里那句 `kDefaultRecipe` 引用的是自己的 Defaults，
它不是抄本，只是给那份唯一清单起了个短名字。

⚠ **三处都要盯**（声明 / 面板读回 / `run()` 兜底）。
以前只盯前两处，`params.value("x").toString(kLocalConst)`
会同时躲过 3d（只查裸字面量）和 3h（只查 `cv::` 前缀）。

实测：扫了 **15 个算子**的本地常量，其中 **12 处**被当成了旋钮默认值。

> 这条规则写出来的过程值得单看：
> 难处在"怎么把抄副本和算法常量分开" ——
> `run()` 里全是算法常量（面积换算、像素偏移），光看"是不是裸字面量"分不出来。
> 改成看"名字像不像默认值"更糟 —— 那是在**猜作者意图**。
> 最后落到"值从哪来"才稳：四种情况**都不需要猜**，答案就在源码里。
> 配套的教训卡：`notes/atomic/at-the-verdict-must-be-about-the-value-not-the-name.md`。

### 9.2 新规则 3k：面板能设的旋钮，存盘里得登记，算子得读

审计一直只对着 `defaultParams()` 这一份清单查。
而 `collect()` 是**另一份独立的清单** —— 它写出去的每一个 key，
都意味着"用户能在这个面板上设这个旋钮"。

两份清单差一份，就出两种病：

- `collect()` 有、`defaultParams()` 没有
  → **存盘里压根没有这个 key**，它的默认值只活在面板初值里。
  用例 2 查不到它：用例 2 查的是"run() 读了却没登记"，
  而这个 key run() 压根没读（否则用例 2 会报）。
- `collect()` 有、`run()` 没读
  → **死旋钮**：界面上摆着，调了不生效。

实测：核对了 **76 个**面板旋钮。

### 9.3 用例 1 的结构性护栏：审计认不出时，明说「认不出」

**病**：用例 1 说"`x` 是死旋钮"，这句话其实混了两件事 ——
(a) 代码真的没读它；(b) **审计没认出来**这种读法。

以前两者是一回事，于是审计一旦认不出新写法，
就会把旋钮明明被读了的算子判成"死旋钮" —— 第三轮实测 28 条假"死旋钮"。

以前的兜底是"键名清单认不出来 → 明说认不出"，
但那只认得**两种**具体写法（`readIntKnob` / `readIntKnobs`）。
换个名字就兜不住了。

**这一轮改成结构性的**：不问"审计自己找到了几个 key"
（那是关于**工具**的问题），而问一个关于**代码**的事实：

> `run()` 到底碰没碰 `params`？

碰了，而审计一个 key 都没认出来 → 那不是旋钮死了，是**审计瞎了**。
红在一条诚实的理由上："这是审计认不出这处读法，不是旋钮死了，
得先把审计升级，别去改旋钮"。

⚠ **3k 也补了同一道护栏**。
不加的话，一旦有人写了新的读取封装，审计会同时喊两句话：
"我认不出这处读法"和"它是死旋钮" —— **两句互相打架，而后一句是假的**。
假的那句更危险：它会让人去查旋钮，其实旋钮好着呢。

变异 M32 专门验这一条（9.5）：把 `count_check` 的读法换成审计认不出的自定义 lambda，
红的理由必须是「认不出」，**不能**是「死旋钮」。

### 9.4 中途翻车：键名长得像值（3g 一口气报了 10 条假红）

3g 有一条一直挂着的不查：`toString()` 的兜底**一条规则都没管**。

- `toString()` 不带参数 → 隐式退成**空串**（不是 0）→ 看不见
- `toString("recipes/demo.json")` → 抄了一份路径 → 也看不见
  （3g 只查裸数字，而文本旋钮压根不收）

第五轮把 `toString()` 收了回来，顺手加了一条"兜底不许是裸字符串"。
**第一条跑出来就红了 10 条**：

```
[FAIL] pcb_defect_judge 的 setParams() 里 params.value("dark_min_pct")
       的兜底写的是裸字符串(d.value("dark_min_pct").toDouble())
```

**这 10 条是误报。** 真实代码是：

```cpp
const QJsonObject d = PcbDefectJudge().defaultParams();   // 声明值
m_darkMinPct->setValue(params.value("dark_min_pct").toDouble(
                           d.value("dark_min_pct").toDouble()));   // 正确的写法
```

`"dark_min_pct"` 是**键的名字**，不是值。它长得和"抄了一份路径"一模一样。

**收法**：先抹掉键名，再看还剩不剩字符串 ——
`exprWithoutKeyNames()` 只抹 `.value("...")` 这一种形态，
因为 `.fromUtf8("recipes/demo.json")` 里的字符串**是值**，抹了就抓不到真问题。

⚠ 这 10 条假红本身就是一条教训：
**一个对自家代码误报的守卫，下一个人只会把它关掉** ——
而守卫被关掉之后，连它本来能抓到的那一半也没了。
配套的教训卡：`notes/atomic/at-a-key-name-is-not-a-value.md`。

（顺带：文本旋钮的隐式兜底是**空串**，数字旋钮是 **0** ——
不是一回事，报错的措辞也得跟着分开。）

### 9.5 第五轮的变异：6 个，全杀

基线：**373 条断言**（上一轮 370 —— 多的 3 条是 3j 的两条守卫和 3k 的一条守卫；

18. **「压根没跑」的那一步，不算坏帧**（2026-10-24 新登记，
    欠账 17 那轮顺带查出来的）→ **2026-10-25 收了一半**。
    引擎里一步失败（`info.failed`）时**输出是空的**，
    所以「输出里带 error」那条判据**数不到它**。
    结果：存盘里写了个不存在的算子名 → 那个节点**被跳过**（`graphFromJson`
    跳过并记一条日志）→ 链继续往下跑 → 下游照样可能判 PASS。
    - ⚠ 这条债其实有**两个形状**，不是一个：
      | 形状 | 在哪 | 状态 |
      |---|---|---|
      | **运行期**：算子返回 false（压根没跑成） | `run_engine.h` 把输出置空，失败原因在 `info.error` | ✅ **已收**（2026-10-25）|
      | **加载期**：存档里写了不存在的算子名 | 解析层**不再跳过**，节点留在画布上标「未安装」，那一步会失败 | ✅ **已收**（2026-10-25，第五笔）|
    - **加载期那个怎么收的**（2026-10-25 第五笔）：
      **解析层别丢节点**。以前 `graphFromJson` 遇到没装的算子直接
      `continue` —— 节点没了，指向它的边**端点缺失**，边也没了，
      **链断成两截**，下游拿空输出兜底，数字看着正常，**静默判 PASS**。
      现在：节点**留在图上**（`known=false`）、uuid/op 名**照样登记**
      → 边接得上、链不断；画布上标成「未安装」；
      运行时那一步**失败** → 整批判 **ERROR**。
      > 这就是「**画布忠实度**」:用户存的什么,画布上就是什么。
      > 详见 `notes/notes_W7_ParseLayer_2026-10.md`。
    - **加载期那个怎么收（当时定的路子）**：
      P0-1「**解析层别丢节点**」——
      `pipeline_graph.h` 保留未知算子、标 `known=false`，
      而不是**直接跳过**。
      那样一来：① 画布上看得见那个节点（**画布忠实度**）；
      ② 它的边**不会因为端点缺失而连锁被跳过**（那是欠账 19 说的「链断成两截」）；
      ③ 「跳过一个节点该不该让整批作废」就有了**可测的判据**，
      而不是一句日志。
      > ✅ **2026-10-25 第五笔按这条路收掉了**（P0-1）。
      > 代价是「**链没断**」≠「**没事**」：
      > 链没断意味着下游拿到的是「**上游那一步失败了**」这个事实
      > （能被 `w7::isBadStep` 认出），而不是「上游安静地什么都不产出」。
      > 这一步**一次解三件事**：欠账 18 加载期 + 欠账 19 + 画布忠实度的定义。
    - **运行期那个怎么收的**：
      判据从「输出里带 error」扩成「**压根没跑成也算坏**」
      （`w7::isBadStep`，两种坏法都认），
      并且**采集也收成一份**（`w7::FrameErrorCounter`）——
      上一轮只抽了「分类」，「哪一步算坏」的判据两边还各写一遍，
      那就是**刚建好的架构里的裂缝**（本项目栽过六遍的「抄副本」的萌芽）。
      改口径之前量过风险面：17 个算子里只有 3 个会 `return false`，

      详见 `notes/notes_W7_BadStep_2026-10.md`。

      不是难，是**两边形状不对称**，硬做会引入**假阳性**——
      headless 是一次性的（`g.skippedNodes` 在手边，直接用），
      而 GUI 侧 Load 时跳过的节点**根本不在画布上**，
      要把「Load 时跳过了几个节点」带进判定，就得在 MainWindow 里存这个状态，
      而**用户一旦编辑画布，这个状态就过期了**
      （画布此时已经是一个完整可跑的流水线，却还会被判 ERROR）。
      所以修它得先定义一个概念：**「画布对不对得上用户存的那份」**。
    - **边界**：加载期这个洞**不是静默的** ——
      `graphFromJson` 会打一条日志（`[Load] 跳过未知算子: xxx`），
      GUI 和 headless **两边都会报**。
      所以它是「**报了但对判定无影响**」，不是「压根没人知道」。
      静默的是「它对最终判定没有任何影响」。
    - **重开条件**：**要定义「画布忠实度」的时候** ——
      也就是要决定「跳过一个节点，该不该让整批作废」的那一刻。

      让它跑的时候**像别的失败一样**被算成坏帧 ——
      那样两边天然一致，而且用户在画布上**看得见**少了什么。
      这和运行期那个是**同一套机制**。
19. **`PipelineGraph` 的三个字段「写了没人读」**（2026-10-25 新登记，
    还欠账 17 第二半时顺带发现的）。
    `PipelineGraph` 里有三个字段：
    - `skippedNodes` —— 加载时跳过了哪些未知算子
    - `skippedEdges` —— 因为端点缺失而跳过了哪些边
    - `defaultedSides` —— 哪些 pin 用了默认方向
    **三个全是「写了没人读」。**
    `defaultedSides` 连**测试都没碰过**。
    - **为什么这条比欠账 18 的加载期形状更严重**：
      欠账 18 说的是「跳过一个节点」，
      这条说的是「**跳过一个节点会让整条链断成两截**」：
      > 未知算子被跳过 → 指向它的**边端点缺失** → **边也被跳过** →
      > **链断成两截** → 下游拿**空输出** → 默认值兜底 →
      > 数字正常 → 判 PASS。
      也就是说，**缺一个算子**，伤的是**它后面所有算子**。
    - **和欠账 18 的关系**：根因**相同**（未知算子被跳过），
      **后果不同**（一个节点没了 vs 一条链断了），所以**分开登记**，
      但重开的时候要**一起做**。
    - **边界**：这条债**只关于**「跳过之后的链该怎么继续」，
      不涉及「跳过本身该不该发生」。
      眼下 `skippedNodes` 在 headless 侧**是有人读的**
      （`g.skippedNodes` 在手边，直接用），GUI 侧没有 ——
      而 GUI 侧 Load 时跳过的节点**根本不在画布上**，
      这正是欠账 18 那条「要先定义画布忠实度」的同一个坎。

      **要定义「画布对不对得上用户存的那份」的时候**。

      现在 `defaultedSides` 是**写进去就没人看**，
      连「它被读了没有」都验证不了。
      ⚠ 注意：**这条是「写了没人读」，不是「读了没用」** ——
      后者是设计，后者是**死代码**。

      因为「画布上多了什么、少了什么」正是**画布忠实度**要量的东西。
      > 一次同时解掉欠账 19 + 欠账 18 的加载期。
      > 这也是为什么它是 **P0**：它把两条债的**根因**一起动了。
    - ✅ **2026-10-25 第五笔，这条已收**：
      三个字段**改名**成诚实的名字
      （`skippedNodes` → **`unknownNodes`**、`skippedEdges` → **`brokenEdges`**，
      `defaultedSides` 不变），
      并且**都有人读了**：
      | 字段 | 谁读 | 读出来干什么 |
      |---|---|---|
      | `unknownNodes` | `describeLoadAnomalies`（纯层）+ headless 结果 JSON | 告诉用户「有 N 个算子没装」；CI 能查「为什么这批是 ERROR」 |

      现在有了**两处读者**（人话 + 机器可读）。
      > 名字也必须诚实:一个节点都不「跳过」了,还叫 `skippedNodes` 就是骗人。
      > **规则会搬家,但不许改口。**

## 十一、第六轮：面板置灰（欠账 5 收口）

### 11.1 先说清楚：笔记里那句"测不了"是**误判**

第二轮（6.5）记的是：

这句话当时没人去验 —— 它读起来像一个已经查清楚的**结论**。
但它其实只是一个**猜测**：写它的人默认"Qt 控件要屏幕"。

事实不是这样：Qt 的 `offscreen` 平台插件可以在没有屏幕的机器上

| 套件 | 用在哪 |
|---|---|
| `test_undo_redo.cpp` | 节点图交互 |

| `test_run_policy.cpp` | 运行策略面板 |
| `test_image_sources.cpp` | 图像源面板 |
| `test_pcb_operators.cpp` | PCB 算子面板 |
| `test_mainwindow_wiring.cpp`（2026-10-25 第六笔新增） | **主窗口本身** |

> ⚠ 第六笔把同一个借口用在**主窗口**上，又推翻了一次：
> `mainwindow.cpp` 一直用「它不在任何测试目标里」挡着 ——
> 做法是把它编成**静态库**，让 GUI 外壳和测试外壳**共用同一份实现**。
> 详见 `notes/notes_W7_MainWindow_2026-10.md`。

写法就两行：

```cpp

```

**「没法测」和「没测」是两回事** —— 前者是个结论，后者是还没干活。
写"没法测"之前该先问一遍：这条证据真的只有在有屏幕时才拿得到吗？

> 同一个道理在 CI 那边也栽过一次（"本机没有 runner 就没法验"），
> 已经写成 atomic 卡：`notes/atomic/at-no-runner-is-not-a-reason.md`。

### 11.2 这条用例查的到底是什么

前面 9 个用例查的都是**代码里有没有把旋钮接上**。
用例 10 查的是**界面上那个控件的状态**：用户到底能不能点它。

为什么值得单独查：

"旋钮在代码里读到了" ≠ "用户在面板上能调它"。
运行时缺失时，有些旋钮摆在那儿还能改，改完存进流水线，
跑起来一点用没有 —— 用户以为配好了，其实配的是空气。
这正是本项目最忌讳的那种"骗人旋钮"。

### 11.3 怎么测才不作弊

三条自律：

| 环节 | 做法 | 反面做法（作弊） |
|---|---|---|
| 期望值 | 来自**测试这边的登记表**（`kGreyRules` + 豁免清单） | 从被测代码里 grep 出"应该置灰的清单" |
| 观测值 | 来自**真造出来的面板**的 `QWidget::isEnabled()` | 从源码里 grep `"setEnabled(false)"` |
| 控件↔key 映射 | 靠**行为**：改控件的值，看 `collect()` 里哪个 key 跟着变 | 靠控件名字/类型猜 |

第三条最要紧。grep `setEnabled(false)` 只能证明**代码里写了那句话**，
证明不了那句话**落在了哪个控件上** ——
把 `m_inW->setEnabled(false)` 写成 `m_modelPath->setEnabled(false)`，
grep 一个字都发现不了，而用户看到的是反过来的（M36 那个变异）。

### 11.4 怎么拿到 `collect()`（它是 protected 的）

`ParamForm::collect()` 是 protected，测试碰不到。
但"应用参数"按钮点下去会 `emit valueChanged(collect())` ——
**信号把结果发出来了**，于是不用碰 protected 成员：

```cpp
connect(form, &ParamForm::valueChanged, probe,
        [this](const QJsonObject& o) { m_last = o; m_got = true; });
```

于是"这个控件写的是哪个 key"就从一个猜测变成了**可观测的事实**：
改这个控件 → 点应用 → `collect()` 的输出里哪个 key 变了 → 就是它。

> 踩过的坑：`connect(发信人, &PMF, 上下文, lambda)` 这个重载要求
> **上下文是个 QObject**。探针一开始不是 QObject，编译期挑不出这个重载
> （掉进 `const char*` 那个，报"无法把信号指针转成 const char*"）。
> 让探针继承 QObject 之后，顺带拿到"探针一析构连接自动断开"。

### 11.5 两份清单为什么不能合并

| 清单 | 判据 | `dl_infer` 的 6 个旋钮 | `image_source_camera` 的 3 个旋钮 |
|---|---|---|---|
| `kExemptions`（豁免清单） | 当前构建里**读不到** | 在（在 `#ifdef` 里，没编进来） | **不在**（在 `#ifdef` **之前**读，读了是为了区分"参数配坏了"和"SDK 没装"） |
| `kGreyRules`（置灰登记表） | 当前构建里**调了不生效** | 在 | 在 |

两者有交集但**不一样**。合在一起会看错：

- 把 camera 的 3 个旋钮塞进豁免清单 → 用例 1 就**不再查**它们到底读没读
  —— 白白放松一道守卫（豁免的含义是"这段代码没编进来，读不到"）。
- 只靠豁免清单 → camera 的 3 个旋钮就漏了（它们读到了，但没生效）。

所以：**期望置灰集合 = 豁免清单里该算子的 key ∪ 置灰登记表里"读了也没用"的那部分**。
一份定义只用一次，不抄副本。

### 11.6 `model_path` 为什么**不**置灰

`dl_infer` 的空实现里，`model_path` **真的被读**（用来区分"路径写错了"和"SDK 没装"）。
用户改它是有用的 —— 改了之后报错信息就变。
置灰它等于"连诊断都不让用户参与"。

用例 10 把这条钉住了：**运行时缺失也必须能编辑**。
（M38 那个变异就是"把整个面板一起灰掉"，被这条抓住。）

### 11.7 用例 10 的断言清单

| 断言 | 查什么 |
|---|---|
| 登记表非空 | 护栏：这条用例不许恒真 |
| 豁免清单里的算子必须在置灰登记表里 | 两份清单互相核对 |
| 同一个 key 不许同时"该置灰"和"该可编辑" | 两份清单不许打架 |
| 造得出面板 / 面板是 `ParamForm` / 有表单布局 / 只有 1 个按钮 | 前置条件 |
| **"应用参数"按钮必须能点** | 按钮灰了 = 用户什么都应用不了 |
| 面板上没有审计认不出的控件类型 | 认不出 ≠ 死旋钮 |
| **置灰的控件个数 == 期望个数** | 不依赖探针的独立证据（探针挂掉时它已经报过红） |
| 点"应用参数"能拿到 `collect()` | `collect()` 是 protected，得靠信号 |
| 每个输入控件都改得动 | 改不动的控件 = 审计认不出它是什么旋钮 |

| 面板上的旋钮集合 == 登记表登记的集合 | 多出来的 = 没人管它；少了的 = 控件被删了 |
| 该置灰的控件 `isEnabled() == false` | 核心 |

| 面板上写明了为什么置灰 | 置灰了但没说为什么 = 半个骗人 |
| 运行时可用时面板上不许有 ⚠ | 功能可用却吓人 = 另一种骗人 |
| 至少 2 个真面板 / 至少 10 个输入控件 / 每个控件都认出了 key | 护栏：这条不许空转 |

#### 变异抓出来的第二个东西：**红得对，但红得不够准**

M38 第一遍跑的时候红了 3 条，但红的是：

```
dl_infer 的面板点"应用参数"能拿到 collect() 的结果
dl_infer 的 collect() 返回空 —— 审计认不出这处读法
每个输入控件都认出了它写的 key(认出 3 / 共 10 个)
```

**杀是杀了，但红错了地方。**
真正的问题是"用户按不动'应用参数'，面板成了个死面板"，
而报出来的却是"审计拿不到 collect()"——听着像**审计自己坏了**。

于是补了两条断言：

1. **"应用参数"按钮必须能点**（`apply->isEnabled()`）——
   它是 `collect()` 的唯一出口，**也是**用户唯一的"把面板上的值写回流水线"的动作。
2. **置灰的控件个数 == 期望个数** ——
   放在**探针前面**（探针那条链路一旦断掉，后面一串检查会被 `continue` 跳过；
   而"灰了几个"跟探针无关，它必须已经报过红）。

```
[FAIL] dl_infer 的面板上'应用参数'按钮必须能点(它灰了 = 用户什么都应用不了)
[FAIL] dl_infer 的面板上应该正好有 6 个控件被置灰,实际 7 个
```

> **变异不只是用来证明规则有效，还用来发现规则红得不够准。**
> 一条断言能把 bug 逮住，不代表它把**病因**说清楚了。
> "审计拿不到 collect()" 听起来像审计坏了，"用户按不动应用" 才是真的。

### 11.9 变异脚本自己栽的坑：PowerShell 的 hashtable 是**引用**语义

第一遍跑变异脚本，7 个全"杀"了，但最后的工作树里三个算子文件**全是变异**。

原因：脚本里"保存原文件内容"用的是 hashtable，

```powershell
$orig[$file] = @{ Text = ...; Bom = ... }
$state[$file] = $orig[$file]        # ← 引用！不是拷贝
$obj.Text = $obj.Text.Replace(...)  # ← 改的是同一个对象
```

于是"原始内容"被就地改掉了，"还原"写回去的是**叠了全部变异**的内容。

修法两处：

1. 深拷贝：`Copy-State` 逐个新建 hashtable；
2. **还原完逐字节校验**（SHA-256 对比），对不上直接 throw。

> 教训和上一轮那次一样：**别去验一份副本，要验那件事本身** ——
> 这次是"别把原件当拷贝用"。一个"还原"步骤如果自己不验证，
> 它就只是一段看起来像清理的代码。

## 十二、第七轮：3j 的第四处 —— 面板初值（欠账 14 收口）

### 12.1 一个默认值在代码里有**四个**位置

| # | 位置 | 谁在盯 |
|---|---|---|
| ① | **声明**：`defaultParams()` 的右值 | 3a / 3b / 3i / 3j |
| ② | **面板读回**：`setParams()` 里把存盘的值读回控件时的兜底 | 3g / 3j |
| ③ | **run 兜底**：`run()` 里参数缺失时的兜底 | 3d / 3h / 3j |
| ④ | **面板初值**：`buildUI()` 里控件开箱时的值 | 3e（只查裸数字）/ **3j（这一轮补上）** |

第四处当时是空的 —— 于是这种写法能一路溜过去：

```cpp
constexpr int kMinArea = 20;              // 算子文件里自己定义的常量
m_minArea->setValue(kMinArea);            // 当面板初值
```

- 3e 看不见：它只查 `setValue(...)` 的参数是不是**裸数字**，
  而 `kMinArea` 是个**标识符**；
- 3j 也看不见（那时它只看前 3 处）；
- 3d / 3g / 3h 也都看不见（它们盯的是另外三处）。

**而 `20` 就是 `BlobCountDefaults::kMinArea` 的值** ——
声明值改了，面板上的初值不会跟着改，两边悄悄对不上。

第四处比前三处更容易漏，因为它有**两种形状**：

| 形状 | 例子 | 3e 看得见吗 |
|---|---|---|
| 数值型 | `setValue(EXPR)` | 只看得见裸数字，看不见标识符 |
| 文本型 | `new QLineEdit(EXPR)` | **压根不是 `setValue`，连看都不看** |

### 12.2 这一轮补的解析：面板初值的三种形状

```cpp
① setValue(EXPR)        —— 数值型旋钮的初值
② new QLineEdit(EXPR)   —— 文本型旋钮的初值
③ addItem(标签, EXPR)   —— 下拉框的**值**（第 2 个参数）
```

**为什么 `addItem` 只取第 2 个参数**：第 1 个是给人看的标签
（"YOLOv8 (1, 4+类别数, N)"），写错了顶多难看；
第 2 个（userData）是**值**，写错了就是"面板上摆的和算子跑的不是一回事"。

**为什么不收 `setText` / `setRange` / `setSingleStep` / `setPlaceholderText`**：
`setText` 在 buildUI 里只有提示文字（读回参数归 3g）；
`setRange` 那些是**量程**不是值；
`setPlaceholderText` 是**例子**不是初值
（`dl_infer` 的 `model_path` 初值是空的，placeholder 只是提示）。

### 12.3 判据还是同一个：问「值从哪来」

第四处用的是 3j 原有的判据，一字未改：

```
① 值是字面量                 → 手抄的默认值            → 红
② 值指向**别的算子**的 Defaults → 绕过 3i 的后门        → 红
③ 值指向**本算子**的 Defaults   → 放行（它就是那份唯一清单）
```

### 12.4 现状：这一侧**零违规**

```
第四处(面板初值)一共核过了 41 个初值表达式
第四处(面板初值)发现 0 处本地常量当默认值
```

41 个初值表达式（`setValue` / `new QLineEdit` / `addItem` 的值），
逐个核过，**一个本地常量都没有** ——
所有面板初值都指向 `operator_defaults.h` 或共享核心（`pcbcolor::`）。

这和欠账 14 当时的预测一致（"现状：零实例"）。

> ⚠ 但**零违规不等于规则在干活** ——
> "没找到"和"在看空气"在日志里长得一模一样，都是"没报红"。
> 所以下一节是必须的。

### 12.5 变异 M42~M44：两个该杀、一个该活

| 编号 | 注入 | 预期 | 实际 | 红了几条 |
|---|---|---|---|---|
| M42 | 面板初值用本地常量，它的值是**字面量** | 杀 | **KILLED** | 1 |
| M43 | 面板初值用本地常量，它指向**别的算子**的 Defaults | 杀 | **KILLED** | 1 |
| M44 | 面板初值用本地常量，它指向**本算子**的 Defaults | **活** | **SURVIVED** | 0 |

M42/M43 各自**只红 1 条**，而且红的是 3j 第四处 ——
**没有别的规则来抢功**，说明这一轮补的确实是新能力，不是已有规则的重复。

M44 那一行是这一轮最容易被省掉、但**不能省**的：

> **一个只会说「红」的规则不是规则，是噪音发生器。**
> 而误报的守卫会被下一个人关掉（这条本项目栽过五遍）。
> "该红的红"和"不该红的不红"，**两个都要验**。

于是给变异脚本加了 `Expect` 字段（`KILL` / `SURVIVE`），
跑完自动比对"预期 vs 实际"，不符就报 `unexpected results = N`。

（已写成 atomic 卡：`at-zero-violations-is-not-proof-the-rule-works.md`）

### 12.6 顺带栽了一次：`.ps1` 里写中文，把**一行代码**吃成了注释

第一遍跑变异脚本，三个**全对**的结果被报成"三个全错"：

```
BAD M42  expected=KILL  got=KILLED
BAD M43  expected=KILL  got=KILLED
BAD M44  expected=SURVIVE  got=SURVIVED
unexpected results = 3
```

真相：脚本无 BOM → PowerShell 5.1 按 GBK 读 → 中文注释被错解 →
错解出来的字节让 PowerShell 以为这行还没结束 →
**紧跟其后那行代码被并进了注释**：

```powershell
$expectedVerdict = if ($m.Expect -eq 'KILL') { 'KILLED' } else { 'SURVIVED' }
                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 整行变成了注释
```

变量恒为 `$null` → 每次比较都是 false → 每次都判"不符合预期"。

**同一个坑，两种死法**：
上一次（`at-build-failure-looks-like-mutation-survived.md` 记的那次）是
**响亮的**语法错误；这次是**安静的** ——
脚本跑起来了、跑得很自信、结论全错。**安静的那种更贵。**

规矩其实早就写在卡里了（`.ps1` 要么 UTF-8 with BOM，要么纯 ASCII），

## 十三、第八轮：旋钮压根没登记时必须说出来（欠账 13 收口）

### 13.1 欠账 13 记的是什么

`operators/param_read.h` 的 `readKnob` 里有一个分支：

```cpp
if (!params.contains(key)) {
    if (!defaults.contains(key)) {
        *err = QString("%1 既不在参数里,也不在声明的默认值里 —— "
                       "这个旋钮压根没登记,退成 0 只会让它拿着一个"
                       "从没声明过的值在跑").arg(key);
        return false;
    }
```

**这个旋钮压根没登记** —— 那不是"用户没配"，是**代码有问题**。
以前这一支是**静默退成 0** 的：算子拿着一个从没声明过的值在跑，
界面上看不出任何异常。改成报错之后，**没有测试专门盯它**。

### 13.2 为什么以前没测（不是"测不了"，是**绕远了**）

要触发它，得让某个算子去读一个没登记的 key；
而用例 2（没登记的旋钮）从**源码层**就把这种情况挡了 ——
那个算子根本不会被跑到。

于是这条分支是「双保险」里的**第二道**：
第一道（源码 lint）正常情况下根本不会让它走到。

> 「没测就没测，写下来免得下一个人以为"每个分支都有用例"」——
> 第四轮就是这么记的。这一轮把它补上了。

### 13.3 这一轮换个角度：**不绕道算子，直接测 helper**

`param_read.h` 是 header-only 的 `inline` 函数 ——
**调用方要用的东西，测试可以直接调**。

以前那条"绕远"的路（造一个算子去读没登记的 key）
在这一轮不需要了：直接调 `readIntKnob(params, defaults, key, ...)`，
把 `params` 和 `defaults` 都喂空的，第三个分支就到了。

### 13.4 用例 11 核的五个分支

| 分支 | 情形 | 期望 |
|---|---|---|
| A | key 不在 `params`，**在** `defaults` | 退声明值，不报错 |
| B | key **既不在** `params` **也不在** `defaults` | **报错**，点名 key，说清"压根没登记" |
| C | key 在 `params`，类型不对 | 报错，但说的是**类型** |
| D | 一组读法（`readIntKnobs`）走没登记的 key | 同样报错，同样点名 |
| E | `defaults` 自己装了个坏值 | 报错，措辞是"**声明默认值**类型不对" |

### 13.5 关键是**两件事都验**

只有 B 的话，断言会退化成"只要报错就过" ——
所以 C 是**对照组**：它保证 B 那几条断言真的在区分病。

> **「压根没登记」和「类型不对」是两种病，措辞必须分开。**
> 用例 9 从**算子那层**验过"类型不对"，这里补上另一半 ——
> 而且是**直接**对着 helper 验的，不绕道。

C 那两条断言是这么写的：

```cpp
check(err.contains("不是数字") || ..., "类型不对那一支该说的是类型");
check(!err.contains("压根没登记"), "类型不对不能写成\"压根没登记\" —— 那是另一种病");
```

B 那两条是对称的：

```cpp
check(err.contains("压根没登记"), "报错要说清是\"压根没登记\",不是别的病");
check(!err.contains("不是数字"), "这一支不该说成\"类型不对\" —— 两种病要分得清");
```

### 13.6 变异 M45 / M46：两个都杀

| 编号 | 注入 | 结果 | 红了几条 |
|---|---|---|---|
| M45 | 把"压根没登记"那一支改回**静默退成 0**（老行为） | **KILLED** | **69** |
| M46 | 去掉**声明那一侧**的类型检查（坏声明值直接用） | **KILLED** | 2 |

M45 红了 69 条 —— 因为那个改动让**所有**旋钮的兜底都变成 0，
用例 5（空参数 ≡ 声明的默认参数）当场就炸了一片。
这条比"只有用例 11 抓到"更有说服力：**它退化的不只是新用例，是整套行为**。

M46 只红 2 条（用例 11 的 E 分支）—— 精准。

> 顺带记一笔：**M45 第一遍是 BUILD-FAIL**。
> 我注入的 `{ ... }` 把大括号配平弄坏了。脚本把它报成 `BUILD-FAIL`
> 而不是"变异存活"—— 这正是 `at-build-failure-looks-like-mutation-survived.md`
> 那条规矩：**构建失败不是存活，是"这次实验没做成"**。

## 十四、第九轮：护栏要说清「哪些旋钮的读取状态未知」（欠账 3 收口）

### 14.1 欠账 3 记的是什么

欠账 3 的原话：

> **用例 1/2 只认 `params.value("x")` 这种读法**。
> …但**自定义的读取封装**依然看不见 —— 那需要更强的识别能力：
> 现在能说"我认不出这个算子的读法"，但说不出**是哪个 key** 没被读。

前半句第三、第五轮收了一半（"明说认不出"），
**后半句一直挂着**：能说"这个算子的读法我认不出"，
但说不出**是哪个旋钮**。

### 14.2 原来只有两档，中间那档被塞进了「死旋钮」

| 原来 | 判据 | 该改谁 |
|---|---|---|
| 豁免 | 在 `kExemptions` 里，写明了原因 | —— |
| 死旋钮 | 审计没认出它被读过 | 改旋钮 |

中间那档 —— **"审计认不出"** —— 没有自己的位置，
于是被塞进了「死旋钮」。

**那一句是假的**：审计没认出 ≠ 没人读。旋钮可能正被一个审计看不见的封装读着。

而且它是**看起来很肯定**地撒谎：

> circle_fit.min_area 是死旋钮：defaultParams() 登记了它，当前构建的 run() 却从来没读过它

读起来像个确凿的事实，实际上只是"我没看见"。

> 判死旋钮那句是假的，更危险 —— 它会让人去删一个好好着的旋钮。

### 14.3 现在是三档

| 档 | 判据 | 该改谁 | 红不红 |
|---|---|---|---|
| ① 确认被读了 | 审计认出来了 | —— | 不红 |
| ② 确认没被读 | 审计没认出来，**而且一点证据都没有** | 改旋钮 | 红 |
| ③ 读取状态**未知** | 审计没认出来，**但有证据**说明它被读了 | **改审计** | 红 |

②和③都红，但**理由必须分开** ——
理由分不开，下一个人就会把两条当成同一件事。

### 14.4 证据从哪来

判据：**当前构建的 `run()` 里，存在一次调用，它的参数位上带着这个 key**。

- 字面量：`fetchInt(params, "min_area", 10)`
- 键名清单常量：`fetchInts(params, kCoordKeys, defaultParams(), &out, &err)`

这正是"自定义封装"的样子。

**为什么这样切得干净**：

- 键名必须**整条**落在某个调用的参数位上。`qInfo() << "min_area"`（日志里提到键名）**不算** —— 那不是读。
- 认得出来的读法（`params.value("x")`、`readIntKnob(params, ..., "x", ...)`）**不进**这一档 —— 审计已经认出来了。
- 匹配用**字面量相等**，不是子串。

顺带解决了一个老问题：`matchBracket()` 不认字符串，
run() 里只要有一处字符串带半个括号，后面的配对就全错位 ——
新写的 `matchBracketSkipStr()` 跳过字符串字面量。

### 14.5 结构性护栏也要点名

第五轮那条结构性护栏（"审计一个旋钮都没认出来"）只说了"一个都没认出来"，
**没说清是哪些**。

现在两处（用例 1 / 用例 3k）都点名：

> circle_fit: 审计一个旋钮都没认出来(认不出的有 2 个:min_area, min_circularity)，可它的 run() 明明用了 params —— …

### 14.6 用例 12：直接测判定本身

新增用例 12，**11 条断言**，喂的是**合成出来的 run() 体**：

| # | 输入 | 期望 |
|---|---|---|
| ① | `fetchInt(params, "min_area", 10)` | 认得出 min_area |
| ② | `knobInt("min_area", 10)`（不带 params） | 也认得出 |
| ③ | `fetchInts(params, kCoordKeys, ...)` | 4 个坐标旋钮**一个都不落** |
| ④ | `params.value("min_area")` 且已认出来 | **不**报 |
| ⑤ | `qInfo() << "min_area"` | **不**报（那不是读） |
| ⑥ | 名单外的键 | **不**报 |
| ⑦ | 同一个键出现两次 | 只留一条证据 |
| ⑧ | 空 run() 体 | **不**报 |
| ⑨ | 括号不配对的调用 | **不**报 |

> **为什么用合成输入，不用真算子**：
> 真算子上"自定义封装"这一例现在是**零实例**（谁也没写这种封装）。
> 零实例的规则只能靠变异证明自己活着 —— 那证明的是"变异能被抓到"，
> 不是"规则判得对"。
> 用合成输入才能把规则的**两条腿**都钉住：该红的红、不该红的没红。
>
> 而且拿真算子当样本，这条就变成"审计自己审自己" ——
> 审计认错了，用例也跟着错，两边一起绿。

### 14.7 变异 M47 / M48：一个杀"新规则"，一个杀"没被新规则软化"

| 编号 | 注入 | 结果 | 红了几条 | 红在哪 |
|---|---|---|---|---|
| M47 | `circle_fit` 的 `min_area` 改走一个叫 `fetchIntKnob` 的封装（审计的正则只认 `readXxxKnob(s)`） | **KILLED** | 2 | 用例 1 + 用例 3k，**两条都是"读取状态未知"** |
| M48 | `circle_fit` 的 `min_circularity` 那次读改指向 `min_area`（那个旋钮真的没人读了） | **KILLED** | 3 | 用例 1 + 用例 3k 的**"死旋钮"**，外加用例 9 一条 |

M47 是这一轮的正主：

- 红了 —— 说明新规则在真算子上**认得出**自定义封装；
- 红的**理由**是"读取状态未知"而不是"死旋钮" —— 说明老那句谎话没了；

它红的正是老那句尖锐的"死旋钮"（`defaultParams() 登记了它，当前构建的 run() 却从来没读过它`）。

> 只做 M47 是不够的：那样的话，"新规则把什么都变成未知"也能通过。
> 两个方向都得钉住 —— 这就是 `at-zero-violations-is-not-proof-the-rule-works.md` 那条。

### 14.8 顺带栽了一次：**还原之后没重编**，跑出一条长得极像真失败的假红

M47/M48 跑完、源码按字节还原之后，我又写了个临时脚本**单独重跑 M48**，
它还原了源码但**没有重编**。

于是：

- `circle_fit.cpp`（还原后，17:51:51）比 `circle_fit.obj`（带变异的，17:51:50）**新**；
- 审计读的是**源码** → 这一侧是对的；
- 用例 9 跑的是**二进制** → 那一侧还留着 M48 的代码。

结果 ctest 报 `pass=446 fail=1`，红的那一条是：

> [FAIL] circle_fit 的 min_circularity 存成错类型(0.9) → 必须报错并点名这个旋钮(实际:"")

**这条长得极像一条真失败** —— 差点让人以为用例 9 坏了。
其实它是 M48 的症状**原封不动地留在二进制里**。

两个地方同时对不上，才把它揪出来：

- `ci.ps1` 用的是 `build/ci` 那棵**独立的树**（它从头重编，所以通过了）；
- 本机 `W7_VisionMasterLite/build` 这棵树是红的。

> **两边不一致时，先查二进制，再查规则。**
> 变异脚本的收尾必须是「还原 → **重编** → 再跑一次」，
> 少一步编译，前一次变异就还活着 —— 而且是以**假红**的形式活着。
>
> 这跟 `at-build-failure-looks-like-mutation-survived.md` 是同一族：
> **"没重编"和"构建失败"一样，都不是"变异存活"，而是"这次实验没做成"。**
>
> ⚠ 这条**早就记过**：`notes/atomic/at-stale-binary-fake-red.md`
> （那次是 `Copy-Item` 保留旧 mtime，这次是压根没跑构建 —— 落点一样）。
> 所以这次**没有另开一张卡** —— 教训搬进那张已有的卡里，
> 同一份教训只能有一处。
