## 2. 为什么它之前是 0 个测试

不是因为不重要，是因为**写不了**。

W3 的整条处理链写在 `main()` 里：

```
生成图 → 转 HSV → inRange 提金色 → 形态学开运算 → Canny → findContours → 面积过滤 → 标注
```

外面挂着 **3 个 `imwrite`（要写盘）和 3 个 `imshow` + `waitKey`（要显示器）**。
这两个都不是无头环境能做的，于是这一层**永远只能靠人眼看** ——
而「人眼看」和「没看过」在报告里长得一模一样。

所以补法的第一步不是「给 `main.cpp` 加个开关」，而是**把纯逻辑拆出来**：

| 文件 | 里面是什么 |
|---|---|
| `W3_EdgeContour/edge_pipeline.{h,cpp}` | 生成图 / 提金色 / 开运算 / Canny / 找轮廓 / 找焊点 / 标注，**加全部常量** |

`main.cpp` 和测试套件**链的是同一个 `.cpp`**（同一个源码进两个 CMake 目标），
和 W1 的 `pixel_ops`、W2 的 `color_pipeline`、W6 的 `w6_cli` 是同一个做法。

> **不让测试「自己抄一份」的理由**（和 W1/W2 那轮一模一样）：
> 抄出来的副本会随核心漂移 —— 改了核心的面积门槛，测试还在按旧门槛断言，
> 于是测试「绿着」而 demo 已经变了。
> **绿灯什么也没证明。**

### 顺带发现的一处「抄副本」

W3 原来的 `main.cpp` 里**内联抄了一份 W2 的金色 HSV 窗口**：

```cpp
// ===== 2. 转 HSV + 金色 mask(复用 W2 思路) =====   ← 注释说复用
cv::inRange(hsv, cv::Scalar(10, 100, 100), cv::Scalar(30, 255, 255), goldMask);
```

同一个文件里还留着**一整份注释掉的** `generatePcbLikeImage()`，
头部写着「同 W2, 8 个金色焊点 — ⏸ 已注释,保留作对照」。

⇒ **注释说复用，代码是抄的。**

这一遍**两份还没有漂**（数值一模一样），
但收它的理由和前十一遍**一个字没变**：
**没有东西保证它们一致**，
而**两边各自的测试都是绿的** —— 每一份都只对着自己那份图断言，
谁也没跨过去看一眼。

收法：事实只留一份，放在 `common/pcb_sim/pcb_sim.h`，W2 和 W3 都从它取。
W2 的公开入口（`padRects` / `padColor` / `backgroundColor` /
`goldHsvLower` / `goldHsvUpper`）**一个都没删** —— 它们现在是**转发**：
**名字还是那些名字，实现只剩一份。**

> 这一遍记在旧卡里当「复发」：
> `notes/atomic/at-the-copies-had-already-drifted.md` **第十二次**。

## 3. 断言从哪来：每个门槛都是**量出来的**

写断言最容易犯的错是**拍一个数**。
本轮所有非平凡的门槛都是**先量、再写**，而且**留了余量**。

| 量 | 实测 | 断言门槛 |
|---|---|---|
| 完整焊点被金色窗口罩住的像素比例 | **86.3% ~ 87.2%**（最差 86.3%） | ≥ 75% |
| 背景误选（8 块取样区） | **0.56%** | ≤ 2% |
| 开运算后剩下的金色 | **32379 → 24423（75.4%）** | ≥ 70% |
| 二值 mask 上的 Canny 边缘数 | **10117**（10/30、50/150、100/300 **三档一模一样**） | 断「三档相等」 |
| 灰度图上的 Canny 边缘数 | **112948 / 102476 / 5977**（10/30、50/150、100/300） | 单调且严格变小 |
| 开运算后的轮廓总数 → 过滤后 | **48 → 6** | 6 个 |
| 完整焊点（开运算后）的面积 | **3699 ~ 5289** | 落在 3000 ~ 6000 |
| 虚焊焊点的面积 | **2342** | 比完整焊点小 20% 以上 |
| 偏移焊点的质心 | **(257.0, 172.5)** | 离 (260,170) < 8，离 (240,140) > 8 |
| 面积门槛 100 / 300 / 600 / 1000 / 1500 / 2000 | **6 / 6 / 6 / 6 / 6 / 6** | 全都 == 6 |

门槛都留了余量，因为**噪声的实现细节可能随 OpenCV 版本变**。
卡死在一个实测值上的门槛，就成了「只有这台机器成立」的断言 ——
那正是本仓库在 CI 第一次真跑时栽过的坑。

### 为什么完整焊点的面积是一个「带」，不是一个数

五个**一模一样**的 80×80 焊点，开运算之后的面积从 **3699 到 5289** —— 相差 43%。

而**开运算之前**的 mask 覆盖率是均匀的（实测 5524~5580 / 6400）。

⇒ 差异是**开运算这一步**造成的：mask 里那 13% 的洞被腐蚀放大，
膨胀只能补回一部分，**补多少取决于洞怎么分布**。

⇒ 所以断言断的是**一个带**（3000~6000），不是一个数。

## 4. 这一轮真正抓到的东西：「6 个焊点」是门槛的产物

这一轮最值钱的一条，**不是**新写的测试抓到的，
而是**新写的测试逼出来的**。

### 4.1 现象

第一版断言写的是：

```cpp
check(pads.size() == 6, "找出 6 个焊点");
```

它**绿了**。然后我把面积门槛从 1000 改成 800 ——
**变成了 8 个**。

一个数，改一个参数就翻 ⇒ 它不是图的事实，是**那个参数的产物**。

### 4.2 真凶

去查那多出来的两块是哪来的，查到了**红色标记**。

W3 的缺陷图上，偏移焊点画在 (220,130)，它**应该在**的位置是 (200,100) ——
两个矩形**有 60×50 的重叠**。

而偏移标记画的是一个**完整的红色空框**，画在 (200,100,80,80) 上：

```cpp
cv::rectangle(img, offsetOriginal, cv::Scalar(0, 0, 255), 2);  // 红色空框
```

空框的**右边和下边因此压在焊点上面**，把那块金色切成了三块：

```
1602（角上那块，58×48）  +  918  +  876
```

后两块**刚好卡在 1000 的面积门槛下面**。
于是「找到 6 个焊点」这个数，是**门槛恰好落在 918 和 876 之间**的结果。

> **标注不该毁掉它要标注的东西。**

而且那个偏移缺陷，在轮廓这一层**根本认不出来**：
活下来的只是角上 58×48 的一块。

### 4.3 收法：两个一起改

**改图**：完整的空框换成**原位置左上角的 L 形角标** + 一根指向实际位置的短线
（**线头收在焊点外面 2 像素**，不许碰到焊点）。
改完实测：偏移焊点保持完整的一块，**面积 3816**。

**改断言**：`pads.size() == 6` 这条**不够**，
换成了**门槛在 20 倍范围里动，个数都不变**：

```cpp
for (double limit : {100.0, 300.0, 600.0, 1000.0, 1500.0, 2000.0}) {
    if (w3::findPads(mask, limit).size() != pads.size()) stableCount = false;
}
```

> ⚠ 上界为什么停在 2000：虚焊那个焊点的面积是 **2342** ——
> 门槛一高它先走（实测 3000 时只剩 5 个）。
> 「6 个」这个数成立的范围是 **100 ~ 2341**，
> 所以断言扫的是这个范围**里面**的一段（100~2000）。

这条断言专门用来抓「改一个阈值，结论就翻」这种病 ——
它断的不是「现在是 6」，是「**6 这个数不依赖门槛**」。

### 4.4 为什么这条值得单开一张卡

因为它是**断言写法**的问题，不是一个 bug：

> **一个只在一处成立的数，不是事实，是那一处的产物。**

写断言时，「结果是 N」几乎总比「结果在参数范围内稳定」好写 ——
于是后者很少有人写。而**一旦这个 N 依赖着某个参数，
断言就变成了给那个参数拍马屁**：改参数的人只要顺手把断言里的 N 改掉，
测试照样绿。

⇒ 新的卡：`notes/atomic/at-a-number-that-holds-in-one-place-is-not-a-fact.md`。

## 5. 一个看着像 bug 其实不是的现象：二值 mask 上换阈值，边缘数一个不变

第一版断言是这么写的：

```cpp
check(gLow > gDefault, "阈值越低边缘越多");
```

它**红了** —— 因为断的是**二值 mask** 上的 Canny。

二值 mask 的梯度只有 **0 和 255 两档**，三档阈值给出的边缘数**完全相同**
（实测都是 **10117**）。这不是 bug，是 Canny 在二值图上的**定义**。

⇒ 这条断言**本身是空的**：它想断「阈值起作用」，
但它挑的输入上阈值**根本不可能起作用**。

改法是**拆成两条**：

1. **二值 mask 上换阈值，边缘数不变**（断的就是这条不变性 ——
   它是**这一层的性质**，写下来是为了防止有人以后把它当成 bug 去"修"）；
2. **灰度图上降阈值确实加边缘**（实测 112948 > 102476 > 5977，
   而且 1000/2000 时一条都不剩）——
   这才是「阈值起作用」该有的样子。

> 这也是本仓库记过的一条：**断言要断「行为」，而且要断在**行为真的存在**的地方**
> （`at-the-assertion-measures-the-library-not-you.md`）。
> 一条在**任何输入下都恒真**的断言，看起来像在测阈值，
> 其实它连「阈值」都没碰到。

## 6. 变异验证：这个套件不是摆设

断言写完了，怎么知道它**真的在测**？

做法和仓库里已有的一样：**故意改坏实现，看套件会不会红**。
脚本在 `build/probe/mutate_w3.ps1`（每次跑都重建并跑套件）：

| 变异 | 改什么 | 结果 |
|---|---|---|
| M1 | 面积门槛 1000 → 10 | 🔴 红 |
| M2 | 金色窗口 S 下界 100 → 200 | 🔴 红 |
| M3 | Canny 阈值 50/150 → 500/900 | 🔴 红 |
| M4 | 形态学核 3 → 7 | 🔴 红 |
| M5 | 偏移焊点 (220,130) → (230,140) | 🔴 红 |

**五条变异，五条都把套件打红**，而且红在哪一条断言上是对的。

> 顺便记一个坑（和 CI 那次撞的是同一类）：
> 变异脚本改完文件要**把 mtime 顶上去**再重建 ——
> `Copy-Item` 会**保留源文件的 LastWriteTime**，
> MSBuild 于是认为「没变过」，**不重建**，
> 跑的还是**改坏之前那个二进制**。
> ⇒ **看到「变异没让测试红」，先确认你跑的是新二进制**
> （`notes/atomic/at-ninja-mtime-stale-binary.md` /
> `at-stale-binary-fake-red.md`）。

## 7. 断的是**这一层的行为**，不是 OpenCV 的行为

W2 那轮栽过一次：断言写的是 OpenCV 的行为，
于是「把 `bilateralFilter` 换成 `Gaussian`」这种改动测试**照样绿** ——
**绿灯什么也没证明**。

这一轮所有断言走的都是 `w3::` 的入口，
**不直接调 `cv::inRange` / `cv::Canny` 去断它们的行为**。
断的是**这一层自己的约定**：

- 窗口罩不罩得住焊点、背景误不误选；
- 开运算会不会吃掉焊点；
- 面积门槛是不是真的在过滤；
- **三个缺陷是不是真的被认出来了**（按**位置和形状**，不是按数量）；
- **以及这个数是不是门槛的产物**。

> 最后那一条是这一轮新加的。

### 「只数数量」的检查器等于没有检查器

一个**只数数量**的检查器，哪怕把图换成一张全是空白的图也能过。

所以这一层断的不只是「找到 6 个」，还有：

- **缺失焊点的位置上没有焊点**；
- **偏移的焊点是在偏移后的位置 (260,170) 附近被找到的**
  （实测最近 **3.9 像素**），**而且没有出现在它原来的位置 (240,140)**
  （实测最近 **36.6 像素**）；
- **虚焊的焊点**：找到了、面积比完整焊点小、外接矩形**仍然是整块**；
- **完整的焊点**：外接矩形都是 80×80、质心离矩形中心不到 8 像素。

### 两个断言不好写，只好换写法

- **「原位置几乎没有金色」**写不出来 ——
  偏移焊点**压在**原位置上，直接数原位置里的金色，数到的是它漏过来的那一块。
  ⇒ 写了一个 `pixelsInOutside(mask, rect, exclude)`，**先把压住的部分扣掉**再数。
- **「缺陷位上一个像素都不许有」**也写不出来 ——
  那三块地方是**带噪声的板面**，噪声本来就会被窗口误选一点（实测 0.56%）。
  ⇒ 改成断**误选率**（≤ 2%）。

> **「一个都不许有」和「不超过 2%」是两个不同的断言**，
> 后者才是**在这张图上**成立的那一个。
