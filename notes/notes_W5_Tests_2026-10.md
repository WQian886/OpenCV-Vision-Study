## 2. 它和 W4 不一样：**先说清楚，免得抄错模板**

W4 那轮的做法是「把纯逻辑从 `main()` 里拆出来，链进 demo 和测试两个目标」。
拿这个模板直接套到 W5 上，**会拆错东西**。

W5 的链是这么分的：

```
                 ┌──────────────────────────────────────────┐
                 │  common/qr_ocr/                          │
                 │  QR 解码 + tesseract 调用                 │
                 │  ★ **已经有自己的套件**（注册在 W7 的        │
                 │    qr_ocr 套件下，36 条断言）               │
                 └──────────────────────────────────────────┘
                                      ▲
                                      │ W5 / W6 / W7 共用
                 ┌────────────────────┴─────────────────────┐
                 │  W5 自己剩下的一层：「给人看」               │
                 │  画四边形 / 写串号 / 一行一个列 OCR 文字     │
                 │  ★ **从来没被测过** —— 而它就是 W5 的全部内容  │
                 └──────────────────────────────────────────┘
```

⇒ **共享核心那一层，W5 不重复测。**
重复测就是「抄副本」的另一种写法：改了核心，两份断言各说各话，
而两份都是**绿的**。

⇒ **W5 自己那一层**，才是这一轮该拆的：

| 文件 | 里面是什么 |
|---|---|
| `W5_OCR_QRCode/present_pipeline.{h,cpp}` | 串号的形状（**唯一一份定义**）、认串号、画 QR 四边形、写串号、画 OCR 框、分词、报告行 |

`main.cpp` 和测试套件**链的是同一个 `present_pipeline.cpp`**，
和 W1 的 `pixel_ops`、W2 的 `color_pipeline`、W3 的 `edge_pipeline`、
W4 的 `feature_pipeline`、W6 的 `w6_cli` 是同一个做法。

### 这一层天然适合无头测试

W4 那层外面挂着 `imwrite`（要写盘）和 `imshow`（要显示器），所以必须拆。

W5 这一层**不用拆就已经无头**了 —— 因为 `present_pipeline.cpp` 里
**只往内存里的 `cv::Mat` 上画**：不写文件、不开窗口、不读磁盘。

⇒ 「产物不许落源码树」这条规矩对它**天然成立**：
这一层的产物压根不落盘。

## 3. 断言从哪来：每个门槛都是**量出来的**

写断言最容易犯的错是**拍一个数**。
本轮所有非平凡的门槛都是**先量、再写**，而且**留了余量**。

| 量 | 实测 | 断言门槛 |
|---|---|---|
| 测试图尺寸 | **330 × 330** | 精确（报告行里也是这个数） |
| 右边那条线的厚度 | **5** 个像素（x=158,159,160,161,162） | 2..8 |
| OCR 框线的厚度 | **3** 个像素 | 2..6 |
| 框里 "OCR:" 那块区域的绿像素数 | **453** 个 | ≥ 50 |
| 真图解出来的号 | `PCB-2026-001-SN:A12345X` | 规则**认** |
| 形状不对那张图解出来的号 | `PCB-2026-01-SN:A12345X`（少一位） | 规则**不认** |
| 角点只有 3 个时画出的红像素 | **0** 个 | = 0 |

### 两处「拍数会栽」的坑（都是这一轮真踩的）

**一、量厚度的时候，窗口里混进了别的东西。**

第一版把「线的厚度」的测量窗口设成 `x∈[99,101], y∈[50,70]` ——
那个窗口**同时**套住了串号文字的**最下面一行** ⇒ 量出来是 **10**。

把窗口挪到**右边那条边**、只取**一行高**（`countRedInRect(marked, 150, 95, 170, 96)`）
之后，量出来是 **5**（x=158..162）—— 这才是 `kMarkThickness = 3` 加上斜线本身斜出去的结果。

⇒ **量出来是 10 的时候，先别写进断言，先看那个窗口里到底有什么。**

**二、「那几个字是绿的」这句话，写松了等于没写。**

第一版断言用的是「**附近**有没有绿像素」（半径 25 的邻近搜索）。
而那个邻近搜索**框自己就满足** —— 框是绿的 ⇒ 断言**恒真**。

换成**指定区域里数绿像素**（`countGreenInRect(marked, 5, 5, 140, 45)`，
一块**只含文字**的区域）才量到 **453**。

⇒ 这是本仓库的老病：
**量的是库，不是你** —— 见 `notes/atomic/at-the-assertion-measures-the-library-not-you.md`。
一个**恒真的断言**，比没有断言更坏：它占一个位置、报一个绿，
让人以为那一块**有人管**。

### 为什么留余量

余量不是为了「让测试好过」，是因为**实现的细节可能随 OpenCV 版本变**。
门槛卡死在一个实测值上，就成了「只有这台机器成立」的断言。

例外是**定义性**的量：图是不是空、标注后尺寸变没变、角点不够 4 个时
**一个像素都不许画**（= 0）—— 这些是**约定**，不是实现的巧合，卡死是对的。

## 4. 最值钱的一条：这一处**不能**收成一份

「PCB 序列号长什么样」，在仓库里有**两个地方**写着：

| 地方 | 是什么 |
|---|---|
| `W5_OCR_QRCode/present_pipeline.h` 的 `kSerialPattern` | **产品**这一边：W5 用它认解出来的号对不对 |
| `tools/check-ci-steps.ps1` 第 4 步的正则 | **CI 门禁**这一边：它在程序**输出**里搜「有没有一个像样的流水号」 |

两边的字面量是同一个东西：

```
PCB-\d{4}-\d{3}-SN:[A-Z0-9]+
```

### 这个仓库的默认教法，在这一处是**错的**

前面每一轮遇到「同一件事写了两遍」，教法都是**收成一份**
（`pcb_sim.h` 收成一份、`operator_defaults.h` 收成一份、判定口径收成一份……）。

**这一处不能收。**

如果让门禁去读产品那份 pattern ——
门禁就会去问产品：「这个号对不对？」
产品说「对」 ⇒ 门禁说「OK」 ⇒ **尺子给自己打分**。

⇒ 那正是「**量的是库，不是你**」那张卡说的病，
这里更糟一档：**量的就是它自己**。

⇒ 所以这两份**必须都留着**。它们不是「一份定义 + 一份拷贝」，
它们是**两个证人**。

### 那怎么防止它们漂

两份文字都会漂。所以要有**第三条**：一条**逐字**比较两者的断言。

套件从 `tools/check-ci-steps.ps1` 里**把门禁那条正则抠出来**，
和产品这一边**逐字比**：

```
两边认的是同一个形状(门禁那边 "PCB-\d{4}-\d{3}-SN:[A-Z0-9]+",这边 "PCB-\d{4}-\d{3}-SN:[A-Z0-9]+")
```

⚠ 注意抠法：套件是**按 `-match '` 这个记号**去找的，
**不是**去找「有没有我们的 pattern」——
否则就是「问门禁『你觉得这个形状对不对』」，又是尺子给自己打分。

### 第二半：字符一样，**还不够**

字符一模一样，两边**问的也可能不是同一个问题**：

| | 门禁（PowerShell） | 产品（C++） |
|---|---|---|
| 怎么用 | `-match 'PCB-\d{4}-...'` | `std::regex_search(payload, m, re)` |
| 是不是搜索 | **是**（整段文字里**含**一个就算） | **是**（`regex_search`，不是 `regex_match`） |
| 大小写 | `-match` **不区分** | `std::regex::icase`，**不区分** |

两边都在问「**这一段文字里含一个流水号吗**」⇒ 同一个问题。

⚠ 如果哪天产品那边改成「**整串**必须就是这个号」（`std::regex_match`），
**字符一个字都不用改**，但两边问的**已经不是同一个问题**了 ⇒
就会出现那种最难查的错位：

> **CI 绿着，产品说数据不对。**

⇒ 「字符一样」是**必要条件**，不是充分条件。
**充分条件是：两边问同一个问题。**

### 顺带一条：产品这一边也得**真的用**那个规则

如果产品只是把解出来的原文往上一打，门禁那句正则就变成了
「原文碰巧长得像」—— **门禁什么也没证明**。

所以 W5 的 demo 现在**先按规则认一遍**，再把认出来的号打出来：

```
===== QR 识别 =====
  尺寸: 330 x 330
  ✅ 解码: PCB-2026-001-SN:A12345X
  🔍 流水号: PCB-2026-001-SN:A12345X
```

⇒ 门禁搜到的那一行，是**规则认过的**那一个 ⇒ 两个证人真的在各自认同一件事。

新卡：`notes/atomic/at-two-witnesses-must-ask-the-same-question.md`。

## 5. 端到端：拿仓库里**真有的图**跑一遍

套件的最后一段不是「用造出来的字符串喂函数」，是**读真图**：

| 图 | 在哪 | 解出来 | W5 自己的规则 |
|---|---|---|---|
| 真图 | `W5_OCR_QRCode/images/qrcode_test.png` | `PCB-2026-001-SN:A12345X` | **认** |
| 形状不对的那张 | `tools/fixtures/qr_wrongshape.png` | `PCB-2026-01-SN:A12345X` | **不认** |

⚠ 第二张图**已经在仓库里了** —— 它是 CI 门禁第 3g 步（C 变异）用的**那张 fixture**。
⇒ 不用再造一张，也不用新提交一个二进制文件。

⚠ 少的那一位是 `2026-01`（**3 位**，不是 4 位）⇒ 形状不对 ⇒ 规则不认。
而 CI 门禁搜的是**同一个形状** ⇒ 两边对这张图的判断**必然一致**。

> 这也顺带说明了「**端到端**」这一段的价值：
> 前面那些断言认的是**字符串**，这一段认的是**真的图**。
> 「规则对」和「图对」是两件事，只有连起来才算数。

## 6. 变异验证：8 条，8 条都红

绿着的测试证明不了任何事 —— 得先看它**红**一次，
而且红在**对的那条断言**上。

`build/probe/mutate_w5.ps1`（**gitignore 掉**，不入库）：

| # | 变异 | 期望红在哪 |
|---|---|---|
| M1 | `corners[(i + 1) % 4]` → `corners[(i + 2) % 4]` | 四条边的中点那条（画成蝴蝶结了） |
| M2 | `\d{3}` → `\d{2,3}` | 「只有 2 位不认」那条 |
| M3 | 去掉 `| std::regex::icase` | 「小写的也认」那条 |
| M4 | 门禁那条正则末尾加个 `X` | 「两边认的是同一个形状」那条 |
| M5 | 去掉 `if (!token.empty())` | 「空的那几个丢掉」那条 |
| M6 | `cv::Rect(0,0,img.cols,img.rows)` → `img.rows/2` | 「下边是绿的」那条 |
| M7 | 报告行里的串号去掉 | 「那一行里有串号」那条 |
| M8 | `out.text = m.str(0)` → `out.text = payload` | 「认出来的是那一段，不是整串」那条 |

结果：**8/8 红**，且**每一条都红在它该红的那条断言上**
（脚本按断言消息里的 ASCII 记号定位，**不是**「只要有红的就算」）。

恢复后：**59 / 0 绿**，而且两个被改过的文件 **SHA256 逐字节一致**。

⚠ **M4 改的是门禁脚本、不是 W5 自己的文件** ——
这正是「两个证人」的另一个好处：
**改一个证人，另一个证人的测试就会红。**
（如果收成一份，M4 这种变异**根本造不出来** —— 因为只有一份可改。）

### 恢复的时候要记得改时间戳

`Copy-Item` **保留**源文件的时间戳 ⇒ 恢复后的文件比目标旧 ⇒
MSBuild 认为「已经是最新的」**跳过重建** ⇒
「恢复完毕」的那棵树其实还是被改过的那棵。

脚本在恢复之后**显式把 LastWriteTime 打到当前时间**，
这个坑 W3 那轮踩过，W4 抄了做法，这里再抄一次。

## 7. 顺手改掉的漂移

**一、`NOTES_W5.md` 里的串号是旧的。**

它写着 `qr.add_data("PCB-2026-001")`，
而 `gen_qr.py` 现在生成的是 `PCB-2026-001-SN:A12345X` ——
**少了一整段**。照着 `NOTES_W5.md` 敲一遍，跑出来的号和门禁认的形状**对不上**。

**二、`.gitignore` 管不住 W5 的产物。**

已有的规则是 `**/images/w6_inspect_*.png`、`**/images/w7_*.png` ——
**没有 W5 的**。而 W5 的 demo 会往 `W5_OCR_QRCode/images/` 写
`w5_qr_result.png` / `w5_ocr_result.png` ⇒ 在源码树里跑一次 demo，
`git status` 就脏了。

⇒ 补 `**/images/w5_*.png`。

**三、结项报告里那个「累计变异 224」，其实**不是全仓的数**。**

这一轮改结项报告的表时顺手看了一眼那张**变异战绩**表：
21 轮、224 条，每轮都有脚本结尾那句 `unexpected results = N` 可查 —— **行本身都对**。

但它在当前快照那张表里的行名叫「**累计变异**」，
而那一行的邻居是「全仓套件 / 断言」「atomic 卡」「C++ 文件 / 行数」 ——
**都是全仓口径** ⇒ 读者会以为**全仓只跑过 224 条变异**。

**其实不是。** 后面几轮**别的线**的变异各有各的账：

| 那条线 | 条数 |
|---|---|
| 普查门禁（Step 3f） | **4** |
| 三道文档门禁（Step 3g） | **12** |
| 三道 CI 步骤（Step 3h） | **12** |
| W1 / W2 套件 | **3** |
| W3 套件 | **5** |
| W4 套件 | **6** |
| W5 套件（本轮） | **8** |

⇒ 加起来 **50** 条。

⚠ **但不能把它们塞进那张战绩表** ——
那 21 轮跑的是**同一套协议**（一句 `unexpected results = N`，N 必须是 0），
所以「杀 / 活 / 编译期」三栏**有定义**。
而后面这几条线里**有的不是「杀或活」**：
Step 3g / 3h 各自的 **D** 是**尺子坏了**（门禁**必须绿**）——
既不是「杀」也不是「活」，是**第三种**（RULER）。
⇒ 塞进去，就得给那 21 轮之外的变异**编轮次号** ——
而轮次号是**那 21 轮的编号**，不是全仓的编号。

⇒ 改法是**划作用域**，不是改数：
行名从「累计变异」改成「**W7 那 21 轮的变异**」，
战绩表的小标题也加上「（W7 那条线）」，
另加一段把上面那七条线**各自的数**列出来，并说明**为什么分开记**。

> 这就是老卡 `at-a-historical-snapshot-looks-like-a-current-claim.md` 的**另一半**：
> 那张卡说「**历史快照**长得和当前声明一模一样，得划作用域」；
> 这一处是**反过来** —— 一张**当前**的表，行名**暗示着更大的范围**。
> **两种都靠划作用域治，而且划的是同一个东西：这句话到底管哪一块。**

**四、这一轮 CI 第一次红，红的是**变异脚本自己的锚点**。**

第一次跑 `tools/ci.ps1` 就红 —— 但**红的不是产品代码**：
`tools/mutate-census.ps1` 和 `tools/mutate-gates.ps1` 里
**硬编码了「文档现在引的是哪个数」**：
本轮指针数 190 → 193、C++ 行数 45,272 → 46,113
⇒ **四处锚点全部过期**。

锚点过期时脚本**不是**安静地跳过，而是**喊**：

```
mutation A: expected exactly one '190 个章节指针' in ...README.md, found 0
```

⇒ 抛异常、退出码 1、CI 立刻红。
⇒ **这正是它该有的样子**：一个变异**悄悄什么都没做**，
和「它跑了、没意见」在日志里**长得一模一样** ——
所以这里宁可**吵闹地拒绝**，也不能安静地假装做过。

⚠ **但根因在我这边**：改根 README 的时候，我把**一整句话改写了**，
而**那个指章节的指针就住在那句话里** ⇒ 改写散文 = **悄悄删掉一条指针**。
（它没有报错，因为那条指针**不是必须存在的东西** ——
门禁查的是「**指着的章节还在不在**」，**不查**「该指的地方指了没有」。）

⇒ 修法不是「记得把锚点搬一遍」，是**把锚点从「哪句话 / 哪个数」
改成「指针的形状」**（一个文件名 + 一个章号），
**章号是唯一被改的东西**。
⇒ 以后文档改数、散文改写，锚点**不用搬**。
