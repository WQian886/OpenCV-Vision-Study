# 一条 lint 扫到 0 个对象，样子和"通过"一模一样

## 核心
2026-10-21 给 W7 写「旋钮审计」套件（扫算子源码，查死旋钮 / 未登记旋钮 / 抄副本的默认值）。

第一版**全绿**。

但日志里写着：

```
DEBUG 扫到 0 个算子源文件
```

三个 lint 全部作用在**空集合**上，于是：

- 「没有死旋钮」—— 真，因为一个算子都没看
- 「没有没登记的旋钮」—— 真
- 「默认值没有裸字面量」—— 真

**三条断言全是真的，全是废话。**

## 为什么危险
本项目早就记过这条教训（守卫写成「打不开就 `return`」→
恒真的空断言）。这次是它的**升级版**：

> 空断言长得很像**通过**。

它没有红，没有警告，甚至比真正抓到问题的断言更"好看" ——
因为它一条都不报。

## 它是被什么抓到的
**变异验证**。第一轮跑 8 个变异，其中 3 个（造一个死旋钮 /
把默认值抄回裸字面量 / 豁免清单漏登记）**活着**。
按项目的老规矩，变异活下来先怀疑尺子 —— 于是去看了尺子，
才发现尺子量的是空气。

## 修法
给审计自己加一条守卫（用例 0）：

```cpp
check(ops.size() >= 15, "扫到至少 15 个算子源文件 —— 扫不到就是审计没在工作");
check(total   >= 70,  "一共扫到至少 70 个旋钮 —— 解析器坏了的话这个数会掉下去");
```

外加每条 lint 开头：

```cpp
if (ops.isEmpty()) {
    check(false, "没扫到任何算子 —— 这条审计等于没跑(恒真的空断言)");
    return;
}
```

## 教训
> 断言的对象不只是"代码的行为"，还包括**审计自己的输入**。

一条断言要能同时回答两个问题：
1. 我断言的东西是不是**非空**的？
2. 我断言的**尺子**是不是量得到我要量的那个量？

第 1 问最容易漏 —— 空集合上，所有"不存在坏东西"的断言都成立。
