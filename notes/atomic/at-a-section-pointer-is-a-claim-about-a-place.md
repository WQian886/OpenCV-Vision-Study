# 章节指针是关于「位置」的主张

## 一句话
> **链接说的是「那个文件还在」；章节指针说的是「那一章还在」。**
>
> 前者改文件名就看得出来，后者**改的是编号** ——
> 而指针本身**一个字都没变**，读是读不出来的。

## 现象（2026-10-27，给文档加第四道门禁那一轮）

上一轮刚给文档加了链接检查器（CI 的 Step 3d，
`at-a-link-does-not-know-its-target-is-gone.md` 那张卡）。
写完以后量了一下，发现**还有一类东西它看不见**：

```
文档里说「那份笔记的第十节」
```

—— 这是一条**关于位置**的主张，和链接是**不同的形状**。

| | 链接 | 章节指针 |
|---|---|---|
| 主张的是 | 一个**文件** | 一个**位置** |
| 现实怎么变 | 文件被删/改名 | 那一章**被重新编号** |
| 指针本身 | 一个字都没变 | **一个字都没变** |
| 怎么发现 | 跟着走一遍 | **也得跟着走一遍** —— 但要走「章」这一层 |

关键在第三行：
**两种情况下指针本身都没变。**
链接坏了还能靠「文件列表里没有它」想起来；
而「第十节」这个说法**在改编号之后依然读得通**，
只不过它现在指的是**另一节**。

## 爆炸半径：不是 1 个，是 60 个

这一轮量到的：

```
190 个章节指针
  ├─ 71 个 跨文件（说的是「那份文件的第 N 节」）
  └─ 71 个 同文件
其中 60 个指向同一个文件：
  notes/notes_W7_Knob_Audit_2026-10.md（欠账台账，唯一登记处）
```

⇒ `notes/notes_W7_Knob_Audit_2026-10.md` 的第十章**一旦被重新编号**，
**60 个指针里的 37 个**当场失效 ——
而**没有一个**会自己发出声音。

变异测试量了这件事：把那个标题从 `## 十、` 改成 `## 十一、`，
（**只改一个标题**），**37 个指针变红**。

> 一个改动，37 处**读起来完全正常**的散文开始指错地方。
> 这就是为什么它需要一个**门禁**，而不是「以后小心点」。

## 第一版规则太宽松 —— 而且它的后果比漏报更坏

检查器的第一版规则是：

> 指针在**它所在的那个文件**里找不到，就去**这一行提到的文件**里找；
> 两边都没有，才算坏。

看起来很体贴。量出来的结果：

| 规则 | 37 个断裂里逮到几个 |
|---|---|
| 宽松（当前文件优先，再看提到的文件） | **18** |
| 严格（指针只认**它前面**那个文件） | **37** |

**少逮到的 19 个去哪了？**

它们**没坏** —— 它们被绑到了**读者自己那一篇的同号章节**上。

> 读者打开「欠账台账第十节」，看到的是**自己那篇的同号章节**。
> 他不知道自己走错了，而且**没有任何东西会告诉他**。

⇒ **一个安静指错地方的指针，比一个明显断掉的指针更贵。**
明显断掉的会被人看见；安静指错的会**被人当成对的**。

⇒ 修法：**指针只认它前面那个文件名**。

```
`notes/notes_W7_Knob_Audit_2026-10.md` 第十节   ← 绑到前面那个文件
第 9.6 节 + `notes/atomic/at-xxx.md`            ← 文件在后面，是「相关链接」，
                                                   指针说的是当前文件
```

**顺序就是语义。** 一行里「谁在前面」决定了指针说的是谁。

## 教训

### 1. 主张的对象变了，检查器就得换

链接检查器**结构上**看不见章节指针：
它找的是 `](...)`，而「第 N 节」里没有 `](`。

⇒ **每加一类主张，就要问一句：现有检查器看得见吗？**
看不见就**新加一道**，别指望老的顺带管了。

### 2. 判据失败时，是**报出来**，还是**猜一个别的解释**？

这和 `at-a-format-test-is-not-a-membership-test.md` 是**同一个形状**：

| | 那张卡（连边） | 这一轮（章节指针） |
|---|---|---|
| 本来该是什么 | 一条**坏边** | 一个**坏指针** |
| 猜成 | 「大概是旧格式吧」 | 「大概是指当前文件吧」 |
| 后果 | 线接到了**别的地方** | 指针指到了**别的一节** |

> **判据失败的时候，正确的动作是报出来，不是替读者猜。**
> 猜错的后果不是「没查到」，是「查到了一个**错的**」。

### 3. 一个检查器的规则，要先问「有几个解」

> **这条主张，正确的答案是唯一的吗？**
>
> 唯一 ⇒ 判据必须**只认那一个**，不许有兜底。
> 不唯一 ⇒ 才谈得上「挑一个，而且说出来挑了哪个」。

本项目的链接检查器**早就**拒绝过加兜底
（「再加试试仓库根目录」会把错的路径反而找到），
`at-the-fallback-must-say-which-one-it-picked.md` 讲的是同一件事的代码版。

这一轮是它的**检查器版**：
**候选不止一个时，「宽松」不是体贴，是把断裂换成静默的指错。**

## 检查清单

- [ ] 这条主张的**对象**是什么？（文件？位置？数？结论？）
      现有检查器**看得见**这个对象吗？
- [ ] 判据失败的时候，我是**报出来**，还是**猜一个别的解释**？
- [ ] 我的规则有**几个解**？唯一的话，不许有兜底。
- [ ] 规则里「**谁在前面**」是不是**语义的一部分**？
- [ ] 这个改动的影响面**量过**吗？（改一个标题，37 个指针断）
