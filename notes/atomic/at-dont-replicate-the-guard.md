# 想回答「某个守卫过没过」,别去复刻守卫

## 问题
一个判据里有个守卫:`if (areas.size() >= 4) { ...emit metric... }`。
需求不是改它,而是回答一个**测量问题**:

> "这条规则在 mcu 板上到底跑了没有?"

规则本身不吐"我跑了没有",只吐算出来的数。所以最顺手的做法是:
**把守卫的逻辑抄一遍,在探针里自己数一遍连通域**。

## 真相
连栽三次,三次都是**重算不可信**:

| 次 | 我怎么重算的 | 错在哪 |
|---|---|---|
| 1 | 传了个 `gold_v_min` 参数 | 这个参数**根本不存在**,我凭印象编的 |
| 2 | 在 ROI 裁片上建 HSV 掩膜 | `run()` 是**全图建掩膜再裁**,范围不同 → 像素集合不同 |
| 3 | 面积按 ROI 算 | roiArea 取错,连**基准板**都对不上 |

第 3 次是关键:如果连**已知答案的那块板**都对不上,
说明是尺子坏了,不是被测对象有毛病。**这个检查必须做,而且要在相信任何数字之前做。**

## 替代办法(两条都不重算)

### ① 反推:用被测对象自己的输出当证据
守卫过了,才会 append 一个 metric。于是:

> **metric 出现 <=> 守卫过了。所以"没出现"就是"没过"。**

不重算任何东西,直接读它的输出。
而且这是**双向的强证据** —— 反过来我在 demo 板上确认 metric 确实出现了,
说明这个推断方向没搞反。

### ② 对照实验:把守卫的输入推到极端
想区分"守卫挡住了"还是"阈值太高",不用推,做实验:

```
把噪声门槛 pad_min_pct 从 0.46 压到 0.01
  -> metric 仍然不出现
  -> 结论:不是阈值问题,是 areas.size() 不够
```

一个实验就把根因**钉住**了,不是"分析出来的"。

### ③ 双重否证
第三种办法交叉验证用:
- 办法① 说"没跑"
- 办法② 说"没跑"
- 办法③(换个口径重算的)说"**跑了**" → 打上 `[!! 与办法A矛盾,重算不可信 !!]`,
  **丢掉办法③的全部数字**,只留它顺带佐证的那部分计数。

## 通用教训
1. **能不重算就不重算。** 被测对象自己的输出是最可信的尺子 ——
   它不可能"编"出一个和代码逻辑不一致的数。
2. **必须重算时,先与被测对象在一组已知样本上对齐。**
   对齐不上,不是"重算有误差",是**重算整个作废**。
3. **先问测量手段能不能回答那个问题。**
   "守卫过没过"和"守卫算出什么"是两个不同的问题,后者需要复刻,前者不需要。
4. 允许多种手段并存,但**必须有一致性检查**。
   我这次的一致性检查不是事后补的,是每个探针**自带**的 ——
   结论是探针自己推翻自己的,不是我看完了才发现。
