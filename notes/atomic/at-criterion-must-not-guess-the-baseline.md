# 判据不猜：期望值必须由「知道真相的那一方」登记

## 现象
判据要拿实测值和某个**期望值**比。期望值从哪来？

直觉答案是「判据自己按类型推一个」—— 电容负极标左、二极管阴极标右，看起来是通例。

## 为什么「猜」是错的
猜错的后果不是"少判一个"，是**把好板判成废板**。

| 方向 | 后果 | 可发现性 |
|---|---|---|
| 漏检（废板判成好板）| 流到下工序 | 难 —— 但"已知漏检"清单能兜住 |
| 误报（好板判成废板）| 停线追一个不存在的问题 | **更难** —— 没有清单会告诉你"这里判错了" |

「已知漏检」是**可以登记**的；误报没有登记表。

所以：**期望值必须由知道真相的那一方给，不能由判据猜。**

## 真相在谁手里
在**生成器**手里 —— 它画极性条的那一行代码，知道自己画在了哪边。

于是让生成器**自己登记**：

```python
POLARITY_SIDE[(cx, cy)] = "left"    # 画极性条的这一行,顺手登记一笔
```

导出脚本只负责**原样搬**，不维护第二张表。

> 📌 导出脚本里往往已经有一张"kind → 参数"的表了，
> 它的注释常常自承"这是一份会漂的副本"。
> 再加一张，就是抄副本的下一轮。

## 粒度：按坐标，不按类型
一开始想按 `kind` 登记（`CAP_SMALL` → left）。实测不成立：

**同一块板上，同一个 kind，有的元件有极性条、有的没有。**

按 kind 登记会把"这个具体位置的元件有没有极性条"丢掉。
所以键是**元件中心坐标**。

> 📌 通则是：登记粒度要细到**能把例外装下**。
> 按类型登记省事，但类型不是物理事实，位置才是。

## 写错的值必须报错
配方里 `"polarity_side": "up"` 这种值：

- 当"没写"处理 → 判不了极性 → 报"没查"，**诚实**
- 拿去和实测比 → 可能把好板判成反装，**静默误报**

所以**必须报错**，而且错误消息要能直接定位到人：哪个站点、写的是什么值。

## 检查清单
- [ ] 这个期望值是谁给的？判据自己猜的吗？
- [ ] 猜错的后果是漏检还是误报？（误报更难查）
- [ ] 期望值的登记粒度，够装下所有例外吗？
- [ ] 登记的那一方是不是**唯一**知道真相的那一方？
      （中间环节有没有维护第二份表？）
- [ ] 期望值写错的时候，是报错还是被当成"没写"？
- [ ] "没有这个东西"的元件，配了这条检查吗？
      （配了 → 报告里全是"没查"的噪音，淹掉真正该看的）
