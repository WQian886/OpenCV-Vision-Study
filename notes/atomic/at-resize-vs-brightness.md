# 亮度轴 ≠ 分辨率轴：混用会造出假缺陷

## 核心
两个 API 看起来都是"处理图像"，改的东西完全不同：

| 操作 | 改什么 | 连带的 |
|---|---|---|
| `cv::resize(img, s, k, k)` | **分辨率** | 像素数、连通域数量、面积统计全变 |
| `img.convertTo(s, -1, k, 0.0)` | **只改亮度**，尺寸不变 | 只有像素值变 |

**混用 → 测出一堆"只在某个缩放下出现的缺陷"。**

## 实际栽过的地方
第一版探针用 `cv::resize` 做"亮度扫描"，表头还标着"亮度"。

结果表里"几何跨 7 档完全相同？NO"——
看着像 bug，其实是**归一化在正常工作**（分辨率变了，元件框当然变）。

我自己当时也差点把这行当缺陷报上去。

> 报告里标错轴名，比数字错更坏：
> 它会让读者去修一个本来正确的实现。

## 更细的坑：插值方式也是变量

```cpp
cv::resize(img, r, cv::Size(), s, s,
           s < 1.0 ? cv::INTER_AREA : cv::INTER_LINEAR);
```

缩小用 `INTER_AREA`（面积平均），放大用 `INTER_LINEAR`。
**用错会引入不同的伪影**，实测数据不可比。

缩小统一用 `INTER_AREA` —— 其它插值在降采样时会跳过/重复像素。

## OpenCV 里哪些量随哪个轴变

### 只随亮度变（HSV 的 H/S）
OpenCV 的 H 和 S 从 max/min 导出，全局乘 k **严格不变**（实测）：

```
BGR(50,90,40)    k=0.5 → H=66 S=142 V=45
                 k=1.0 → H=66 S=142 V=90
                 k=1.5 → H=66 S=142 V=135
```

只有 V（= max 通道）缩放。**这就是为什么去绝对化只需要动 V。**

⚠️ 但 `saturate_cast` **会削波**：`BGR(200,200,200) ×1.5` → V=255。
削波破坏色相信息，是另一条判据失效路径 —— 实测 k=1.55 时错色像素已 99.6% 削波。

### 随分辨率变（几乎所有几何量）
- 面积阈值、连通域数量
- **形态学核尺寸**（固定 3×3 在 2× 图上等于噪点大一倍）
- 距离阈值（聚类半径）

## 做法
### 1. 造扰动图时，两个轴分开做
```
亮度轴：convertTo(s, -1, k, 0)      尺寸不变
分辨率轴：resize(s, k, k)           亮度不变
```
如果要"既变亮又变清晰"，**分两次测**，不要一次叠加。

### 2. 报告里把轴名写清楚
表格列头写"亮度 k"还是"缩放 s"，不要含糊写"变换系数"。

### 3. 阈值跟着哪个轴就要跟着哪个轴变
只随亮度变的判据 → 相对式（×板面色）
随分辨率变的判据 → 相对式（×图像尺寸）**或**按基准分辨率归一化

> 混了两个轴的阈值，最后谁也归一不了。
