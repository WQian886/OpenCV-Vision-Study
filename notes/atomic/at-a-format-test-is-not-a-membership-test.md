# 「是什么格式」和「有没有这个东西」不是同一个判据

## 一句话
> **重构里改判据 = 改功能。改判据的时候没人发现，是因为夹具跟着改了。**

## 现象

把 W7 的读盘逻辑从 `pipeline_serialize.cpp` 抽成纯解析层
（`pipeline_graph.h`）—— 抽的时候顺手把「这条边是不是新版格式」
的判据从

```cpp
// 原代码（pipeline_serialize.cpp）
const QUuid fromId = QUuid::fromString(fromKey);
const QUuid toId   = QUuid::fromString(toKey);
const bool useUuid = !fromId.isNull() && !toId.isNull();
```

改成了

```cpp
// 抽层时写的
if (uuidIndex.contains(fromKey) && uuidIndex.contains(toKey)) {
    ...   // 键用原始字符串
}
```

单元测试**全绿**。

## 真凶：两个判据回答的是两个不同的问题

| 判据 | 回答的问题 | 性质 |
|---|---|---|
| 「这两个键能解析成 UUID 吗」 | 这是**标识符**，还是**算子名**？ | **格式** |
| 「这两个键在节点表里吗」 | 这个标识符指的东西**存在**吗？ | **内容** |

原代码判的是**格式**。抽层时改成了**内容**。

于是有两种边被区别对待了：

| 边的两端 | 原判据（格式） | 抽层后的判据（内容） |
|---|---|---|
| 都是真 UUID，且都在表里 | 新版，按 UUID 接 | 新版，按 UUID 接 |
| 是真 UUID，但**有一个不在表里** | 新版 → 查不到 → **坏边**：跳过 + 报出来 | 判成**旧格式** → 退回按算子名 FIFO 兜底 → **接到了别的地方** |
| 不是 UUID（算子名） | 旧格式，按算子名 FIFO | 旧格式 ✅ |

第二行就是全部的麻烦。

## 混起来的后果不是"接错"，是更隐蔽

一个 UUID 形状的键指向一个不存在的节点 —— 那是一条**坏边**，
本来就该被跳过并报出来。

判成"旧格式"之后，它会去按算子名兜底。
而如果那个算子名**恰好存在**（比如两个节点都叫 `pcb_inspect`），
兜底就配上了另一对节点 ——

> 线接到了**别的地方**。
>
> 工程打开看着挺正常，线也在，画布也像那么回事，
> 跑出来的结论却是错的。

坏边被当成旧格式，坏边的后果被换成了一条**更坏的**边。

## 为什么没人发现

因为**夹具也跟着改了**。

第一版的测试夹具用的是 `"u-src"` 这种随手编的键 ——
它不是 UUID，所以在新旧两种判据下**行为一样**
（都被当成旧格式，都因为算子名对不上而接不上）。

于是判据改了，测试照绿。两边同时漂移，
中间那道缝没有任何东西看得见。

（夹具那半的完整故事见
`notes/atomic/at-a-fixture-must-look-like-the-product.md`。）

## 教训

### 1. 判据变了就是行为变了

哪怕这次改的结果"看起来更合理"，它也是一次**功能修改**，
不能自称重构 —— 重构的定义就是**行为不变**。

真要改，就要有意识地改，并且：
- 写清楚为什么
- 让测试**先红后绿**（先改判据，看测试红不红；不红，说明测试没护住它）

### 2. 格式判据和存在性判据要分开

> 「这是什么」和「有没有」是两个问题。
> 一个判据只回答其中一个。

坏边的正确处理是：**报出来 + 跳过**。
它不该被解释成"那大概是旧格式吧" —— 那是**替用户猜**，
而猜错的后果是把线接到别的地方。

### 3. 判据被改了，测试必须**钉住它**

现在的用例 14 专门钉这条判据：

```
非法 uuid 没被当成身份(它压根不是 UUID)
接不上的边被报出来了(静默丢一条线最难查)
这条边没有偷偷接上别的节点(判据错了的话它会接上)
写法不同的同一个 UUID -> 跑通
uuid 存规范化过的(和 GUI 那边一致)
```

变异 M69 就是"把判据改回去"的那个 —— 它红了 **5 条**。

### 4. 用 `QUuid` 当键，不是因为好看

```cpp
QHash<QUuid, int> uuidIndex;      // 不是 QHash<QString, int>
```

文件是人也会改的：加花括号、改大小写，都还是同一个 UUID。
按字符串比就漏了，而漏掉的代价是**这条边接不上**。
用例 14 里有一条专门钉这个：
节点写 `{A1B2C3D4-...}`、边写 `a1b2c3d4-...`，**必须**接得上。

> ⚠ 顺带一个反例：`QUuid::isValid()` **不等于** `!isNull()`。
> `isValid()` 还查 RFC 的 variant 位，`{A1B2...}` 这种
> 首字节最高位是 1 的 UUID 会判成**不合法**。
> 要判"是不是能解析成 UUID"，用 `!isNull()`。
