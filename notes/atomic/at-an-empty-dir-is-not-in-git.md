# 空目录不在 git 里

## 核心

> **git 只带文件，不带目录。**
>
> ⇒ 一个**空目录**是「**这台机器的一个事实**」，
> 不是「**仓库的一个事实**」——
> 而构建步骤读它的时候，它就成了一颗雷。

## 现象（2026-10-26，CI 第一次在真 runner 上跑）

W1–W4 五个项目各有一条构建步骤：

```cmake
add_custom_command(TARGET w1_imageio POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_directory
        ${CMAKE_SOURCE_DIR}/images
        $<TARGET_FILE_DIR:w1_imageio>/images
)
```

runner 上：

```
 Error copying directory from ".../W1_ImageIO/images" to ...
 ... error MSB3073: The command "cmake.exe" -E copy_directory ... failed
```

**整个 build 挂掉。**

## 根因：三个事实凑在一起

```
① W1_ImageIO/images/ 在本机存在（但是空的）
② git 不跟踪空目录 ⇒ 干净克隆里这个目录**根本不存在**
③ cmake -E copy_directory 的源目录不存在 ⇒ 它**报错**，不是跳过
```

> **本机永远看不见这个 bug** ——
> 因为 ① 一直成立。
>
> 它不是「代码写错了」，是「**这句话只在某些机器上为真**」。

## 怎么验（别靠推断）

**真的 clone 一份，在里面 build。**

```powershell
git clone <repo> <tmp>
# 在克隆里 build，然后看它报什么
```

2026-10-26 实测：克隆里 `W1_ImageIO/images` **不存在**，
build 报**跟 runner 同一个错**（MSB3073）。根因坐实。

> ⚠ 探针自己先栽了一次：
> 第一版调的是裸 `cmake`，而它**不在那个子进程的 PATH 上** ——
> 命令**压根没跑**，`$LASTEXITCODE` 停在 0，
> 探针于是报了一句 **"build OK"**。
>
> **一个没真的跑东西的探针，报绿比没有探针更坏。**
> 修法：先把工具**找出来**（找不到 = 硬失败），
> 再**验产物在不在**（exe 没生成 = 失败，不看退出码）。

## 修法

**两条腿**：

1. **让目录进 git** —— 放一个 `.gitkeep`：

   ```
   W1_ImageIO/images/.gitkeep
   ```

   这不是「为了让 build 过」——
   W2/W3/W4 的代码在图缺失时会**自动生成**一张：

   ```cpp
   if (img.empty()) {
       img = generatePcbLikeImage();
       cv::imwrite(imgPath, img);   // ← 目录不存在,这步也失败
   }
   ```

   **`imwrite` 不会替你建目录。**
   所以目录不存在 ⇒ **兜底路径本身也是坏的**。

2. **别让构建读一个 git 不保证的路径** ——
   能改成「目录不在就跳过」就改；
   至少要知道**这条依赖的边界在哪**。

## 推广：还有哪些地方有同一个雷

判据一句话：

> **凡是构建步骤**读**某个目录**，
> 那个目录要么有文件（git 会带），要么有 `.gitkeep`（人为带）。**
>
> 第三种状态（「本机有、仓库没有」）**在构建里就是一颗雷**。

同一个仓库里的例子：

| 目录 | git 里的状态 | 后果 |
|---|---|---|
| `images/`（根） | 有 `.gitkeep` ✅ | — |
| `datasets/`（根） | 有 `.gitkeep` ✅ | — |
| `W1_ImageIO/images/` | **什么都没有** ❌ | runner 上 build 挂 |
| `W2/W3/W4/images/` | **什么都没有** ❌ | 同上 |
| `W5_OCR_QRCode/images/` | 有 2 个 png ✅ | — |
| `W6_PCB_DefectProject/images/` | 有 24 个文件 ✅ | — |

> 注意 `.gitignore` 里**早就写着**这条约定
> （「datasets/ 和 images/ 目录本身用 .gitkeep 占位」）——
> 根目录照做了，**W1–W4 漏了**。
>
> ⇒ **约定写在注释里 ≠ 约定被执行。**
> 差的那几个，正是**没人验证过的那几个**。

## 又复发了一次（2026-10-29）：`build\ci` 这个目录

CI 脚本在跑之前要把**源码树的快照**写成一个文件，
好让最后那一步（源码树有没有被写脏）在**另一个进程**里读它。
那个文件写在 `build\ci\` 底下。

而 `build\ci` 是**构建**建出来的 —— 构建在**后面**才跑。

⇒ **干净克隆上，那个目录那一刻还不存在。**
⇒ 往一个**不存在的目录**里写文件，**抛异常**；
⇒ 而 `$ErrorActionPreference = 'Continue'` 把异常**吞了**；
⇒ **16 分钟之后**，最后那一步才说「baseline file not found」。

本机是绿的，因为本机**早就 build 过** ——
`build\ci` 是**上一次构建**留下的。

> 这一次比「空目录」还多一层：
> 连「**本机绿**」都是**假的** ——
> 它绿是因为**上一次**的构建留了个目录，
> 而 CI 问的是「**这一份克隆**能不能过」。
>
> ⇒ 「我这儿是绿的」这句话，必须补一句：
> **「在哪儿绿的」**。

⇒ 修法也是同一条：**别依赖一个 git 不保证的路径** ——
要么**自己建**（写之前 `CreateDirectory`），
要么**写到一定在的地方**，再**当场检查**它写成功了没有。

## 教训

推论一：

> **「本机能过」和「仓库能过」是两个问题。**
>
> 本地那个空目录**一直在**，
> 所以本地永远不回答第二个问题。
>
> ⇒ 要回答它，只有两条路：
> **推上去让真环境说**，
> 或者**在本机 clone 一份再说**。
> 后者便宜、快，而且**能定位到具体那一步**。

推论二：

> **兜底路径也需要前提。**
>
> 「图不存在就自动生成一张」听起来很稳，
> 但它**把「目录存在」当成了前提** ——
> 而这个前提是 git 不保证的。
>
> ⇒ 兜底代码要问一句：**我要写进去的那个目录，一定在吗？**

推论三：

> **「我机器上有」这句话，要问的是「**仓库里有**吗」。**
>
> 差一个字，差的是**另一个人 clone 下来能不能跑**。

推论四（跟这一笔的另一半有关）：

> **在干净克隆上跑一遍，是最便宜的一类回归测试。**
>
> 它不需要任何测试数据，
> 只要**换一份树**——
> 而它抓到的正是「本地彩排永远抓不到」的那一族。
