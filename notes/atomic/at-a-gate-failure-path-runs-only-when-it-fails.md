# 门禁的失败路径，只有在它失败的时候才被验证

## 一句话
> **一条从没跑过的失败路径，就是一条坏路径。**
>
> 而「跑一遍 CI」**永远不会**跑到失败路径上 —— 因为树是绿的。

## 现象（2026-10-27，给文档加第四道门禁那一轮）

新写的 `tools/check-sections.ps1`（CI 的 Step 3e）在真实的那棵树上**跑通了**，绿。

然后**故意**让树红一次（把欠账台账的「第十章」改成「第十一章」，
**只改一个标题**）—— 门禁本该报 **36 条红**。
它报出来的**不是红**，是一串：

```
Cannot convert value "System.Object[]" to type
"System.Management.Automation.SwitchParameter"
```

⇒ **门禁在它唯一该说话的那一秒，死了。**
⇒ 而且**没有人会发现**：那棵树本来是绿的 ⇒ **失败路径从来没被执行过**。

## 为什么它能一直坏着

| | 成功路径 | 失败路径 |
|---|---|---|
| 什么时候跑 | 每次 CI | **只有树红的时候** |
| 谁会跑它 | 所有人 | **只有故意制造红的人** |
| 从没跑过的后果 | —— | **没人知道它坏了** |

⇒ **CI 绿 ≠ 门禁是对的。** CI 绿只说明**成功路径**是对的。

## 第二个坑：测的地方，和出问题的不是同一个地方

第一版隔离测试是这么写的 —— **在函数里**：

```powershell
function Test-SameName() {
    param([switch]$List)
    $list = @(1, 2, 3)      # <- 在这里，它不报错
}
```

**它不报错。** ⇒ 「测的时候看起来是好的」⇒ **一个绿色的假象**。

原因：**在函数里，赋值会新建一个子作用域的变量**，根本碰不到那个参数。
而**在脚本作用域里**，那个参数是**带类型约束的变量**：

```powershell
param([switch]$List)
$list = @(1, 2, 3)
# Cannot convert value "System.Object[]" to type "System.Management.Automation.SwitchParameter"
```

**同一个赋值，两个地方结果相反。**

⇒ 这已经是本项目**第二次**栽在「测的地方和出问题的不是同一个地方」
（上一次是**旧二进制**）。
⇒ **判据必须落在出问题的那一处**（脚本作用域），不是「差不多的那一处」。

## 排查：报错信息指向了错的地方

报错指向 `Sort-Object`，**没有**指向真正的原因。排掉的三个假设：

1. 数据不对？—— 同一份数据在别处跑得好好的。
2. 表达式不对？—— 同一个表达式在别处跑得好好的。
3. 「这个脚本里第一次调用」？—— 排除。

**真正把它分开的判据，是把赋值目标改个名字**：`$warm` 行，`$list` 不行。

⇒ **当报错和原因隔着好几层，先找一个能把它们分开的判据**
（改个名字、换个数、换个作用域），而不是盯着报错本身看。

## 修法

1. **局部的名字不许和带类型的参数同名。**
   （参数改名 `-ShowSkips`，局部改名 `$chapList`）
2. **顺序是装饰，红才是重点。** 那个排序加了保护：排序坏了就退回原顺序 ——
   排序**不该有能力弄死这条消息**。
3. **故意让门禁红一次**，把它当**测试**的一部分，不是当**故障**。

## 教训

> **一个门禁的失败路径，只有在它失败的时候才被验证。**
>
> ⇒ 「CI 是绿的」**不能**当成「门禁是对的」的证据。
> ⇒ 每写一道门禁，都要**故意制造一次它该报的错**，看它**报得出来**。
> ⇒ 用**真的东西**去触发：这一轮改的是**真的**一个标题，
> 报出来的 **36 条**就是**真的**断了 36 个指针 ——
> **红的条数和坏的条数对得上**，才算触发对了。

## 顺带：这一轮的门禁，现在**每次 CI 都跑那四条变异**

这张卡写的是「失败路径只有在它失败的时候才被验证」。
而**没人制造失败**，失败路径就永远没人走过。

⇒ 这一轮的普查门禁（`tools/check-sections.ps1`）现在把这件事**接进了 CI**
（**Step 3f**）：每次 CI 都跑那四条变异，跑在**树的副本**上（真树一个字都不碰）：

| 变异 | 改了什么 | 期望 |
|---|---|---|
| A | 引用的**指针数**漂一个 | **红** |
| B | 引用的**宽松规则数**漂一个 | **红** |
| C | **检查器自己注释**里的数漂一个 | **红** |
| D | **尺子坏了** | **绿**（0 条红） |

⇒ **D 那一条最要紧**：它证明 A/B/C 的红是**尺子**报的，不是碰巧。
**尺子坏了 ⇒ 0 条红** —— 这一条也红，就说明尺子量的是空气。

⇒ 而脚本本身住在仓库里（`tools/mutate-census.ps1`），**谁都能重跑**；
它还自己判定「A/B/C 必须红、D 必须绿」，对不上就**报错退出**。

## 复发第二次（2026-10-27）：这次是**尺子只坏了一边**

这张卡说的是「失败路径只有在它失败的时候才被验证」。
这一轮 Step 3f 真的上了真 runner，第一次就红。

先说一个**看起来是好的**结果：本地 D（尺子坏了）**绿**了。

⇒ 但这个绿**不能算数**：副本是**原封不动**的，
无论尺子好着还是坏了，**都不会有红**。
⇒ **一棵没坏的树给出的绿，不是「尺子坏了」的证据，是「树没坏」的证据。**

runner 上 D 是红的，55 条红 = 50 条「查不了」（副本不是树）
+ **5 条**「块断言还是把数抓住了」。

那 5 条说明什么？⇒ **D 只坏了一把尺子。**

普查的数有**两种**查法：

- **块断言**：`if ($nums[$g].Value -ne [int]$claim.Expect[$g]) {`
- **行断言**：`if ($got -ne $want) {`

D 只断了**行断言**那一处 ⇒ 块断言还在 ⇒ 还剩 5 条红。

> 变异名叫「尺子坏了」，它其实只坏了一把。
> **名字是主张，代码才是事实**
> （[断言的红字不是断言那张卡](./at-the-message-is-not-the-assertion.md)）。

### 修法：期望要说成**正面的话**

| | 改之前 | 改之后 |
|---|---|---|
| D 的期望 | 「别出现 `SECTIONS OK`」 | 「**它说 SECTIONS OK，并且一条红都没有**」 |
| A/B/C 的期望 | 「至少一条红」 | 「**至少一条红，而且零条「查不了」**」 |

改之前那种写法有个洞：**检查器崩了也满足**（崩了就没有 `SECTIONS OK`）。
⇒ 「没看见症状」不是「症状没出现」，是「没看见」。

⇒ 而「至少一条红」也有洞：**树坏了也会红**，
那种红**不是尺子报的**，是**树报的**。
⇒ 所以 A/B/C 的判据里必须加一条：**零条「查不了」** ——
查不了的指针说明副本不是树，那是**脚本的错**，不是**门禁的功劳**。

另外每一处替换都要**断言只替换了一处**：
替换了 0 处 = 变异没发生 = 一个假的绿。

最后：D 现在**两把尺子一起断**，断完必须是**零条红**
（不是「普查那几处没有红」——**指针也要零**）。

## 复发第三次（2026-10-28）：这道门**第一次真跑**就派上用场了

上一轮加的那道「先认副本，再信它」的门
（副本的相对路径集合必须和真树**逐个相等**），
在它**第一次上真 runner** 的时候就响了：

```
THE COPY IS NOT THE TREE: the copy does not hold the same files
   missing from the copy (142): notes\atomic\at-a-blind-reading-cannot-watch.md, ...
   extra in the copy (142): ine\notes\atomic\at-a-blind-reading-cannot-watch.md, ...
```

⇒ 一边干净，一边每个都多三个字符 ⇒ 副本**不是那棵树** ⇒ **拒绝给结论**。

### 没有这道门会怎样

脚本会拿着一个**放错了位置**的副本跑那四条变异，
然后**照样报一个结论** —— 而那个结论说的是**另一棵树**。

（根因：相对路径是**拿字符串长度切**出来的，
而 runner 上 `$env:TEMP` 是 8.3 短名、provider 枚举时给的是**展开后**的名字 ——
**同一个目录，两个字符串**。详见
[门禁被指错了树那张卡](./at-a-checker-pointed-at-the-wrong-tree-still-says-ok.md)。）

### 这张卡现在多了一层意思

⇒ **失败路径的门（Step 3f）自己，也有一条失败路径** ——
「副本不是那棵树」这一条，它自己也得**在该红的时候红**；
否则它会默默拿着错的副本，给出一个关于错的树的结论。

⇒ 而**红的还是脚本，不是门禁** —— 这是第三次了。
⇒ 前两次的门（失败路径、尺子两把）都在**第一次真跑**上就露了馅，
⇒ 所以「先上一次真 runner」不是形式主义：
**本地绿的脚本，第一次上真机器就红，是常态。**
