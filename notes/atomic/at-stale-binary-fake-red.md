# 复制回来的文件带着旧时间戳，于是你在验证上一轮的二进制

## 现象
单步执行的 5 个变异全部杀掉、代码改回去之后：

```
build_all.bat     → exit=0        （看着是编过了）
ctest -C Release  → run_policy 失败，直跑同一个 exe → 全绿
```

矛盾：刚编出来的二进制不可能和源码不一致。**那就是它根本没编。**

## 真凶
`Copy-Item` **保留源文件的 LastWriteTime**。

```
备份 step_scope.h.bak  ← 变异开始前那一刻的时间
...
变异 5 轮，每次 build（obj 是新的）
Copy-Item *.bak → step_scope.h     ← 时间戳还是「变异前」，比 .obj 还早
MSBuild：step_scope.h < obj  → 「不需要重编」→ 跳过
ctest 跑的是**带 M5 的旧二进制**
```

M5 是"跳过的节点数少报一个"，所以失败信息里精确写着
`跳过后面的 -1 个节点`。

> ⚠️ 比假绿更危险：**假红会把你推向改已经正确的代码。**
> 看到"跑了 ctest，红了"，最自然的结论是"哦变异没杀干净"，
> 然后去动一段根本没坏的代码——越修越坏。

## 定位靠的不是"红了"，是"红的具体内容"

我本来会把这次当成 M5 没杀干净。是失败信息里的 `-1 个节点`
和 M5 的改动**字面对上**，才回头去看构建。

```
假红 + 说不清为什么红   → 别信，先怀疑验证本身
假红 + 能指出具体是哪条  → 拿它和最近的改动逐条比对
```

**报错文本本身就是判据。** 只看红绿，就把唯一有用的信息丢掉了——
这和 [[at-test-self-ub-looks-like-flake]] 里
「报错稳定指向同一条断言时，那是线索不是噪声」是同一条。

## 对策
- [ ] 复制/还原源码之后 **强制 touch**：`(Get-Item x.h).LastWriteTime = Get-Date`
- [ ] 或者删掉对应的 `.obj`，别和构建系统猜时间戳
- [ ] 变异验证的**最后一步**（还原 + 全量 ctest）必须 touch，
      否则你测的是最后一轮变异，不是基线
- [ ] 报错内容和最近的改动对不上时，先怀疑**验证对象**，再怀疑被测代码

## 一句话
> **变异验证的最后一次绿灯，证明的可能是"我备份还原得很干净"，
> 而不是"基线是好的"。**
> 还原路径和被验证的代码一样需要验证。

## 复发第二次(2026-10-22)：这次不是 mtime，是**压根没重编**

变异的机制不一样，但落点一模一样。

那次是：脚本按字节还原了源码（SHA-256 校验过），
后来又写了个**临时脚本**单独重跑一个变异 ——
它还原了源码，**但没有跑构建**。

于是：

- `circle_fit.cpp`（还原后，17:51:51）比 `circle_fit.obj`（带变异的，17:51:50）**新**
  —— 时间戳这次是**对的**，MSBuild 下次会重编；
- 可**这次没有"下次"** —— 没人跑构建；
- 于是 `w7_knob_test.exe` 里留着的，还是**带变异的那个 `circle_fit`**。

结果 ctest 报 `pass=446 fail=1`，红的那一条是：

```
[FAIL] circle_fit 的 min_circularity 存成错类型(0.9) → 必须报错并点名这个旋钮(实际:"")
```

**这条长得极像一条真失败** ——
它其实是上一轮变异的症状**原封不动地留在二进制里**。

> 所以 touch 时间戳**不等于**"还原路径被验证过了"。
> 还原路径要验证的是**它被编进去了**，不是**它的时间戳对了**。

### 这次是靠"两棵树对不上"揪出来的

- `tools/ci.ps1` 用的是 `build/ci` 那棵**独立的树**（它从头重编）→ 通过；
- 本机 `W7_VisionMasterLite/build` 这棵树 → 红。

**同一个源码，两棵树，两个结果** —— 这一条就足以说明问题不在源码上。

> **两边不一致时，先查二进制，再查规则。**
> 规则改了没生效、和规则没改，是两回事 ——
> 先分清是哪一种，再动手。

### 对策要加一条

原来那张清单只要求"还原后 touch"，
但 touch 只是让**下一次**构建会重编。
这一轮补上：

- [ ] 还原之后**跑构建**，然后再跑测试 ——
      touch 是给构建系统看的，**构建才是给测试看的**；
- [ ] 临时脚本也得守同样的规矩 ——
      它没人 review，活得更久，出错时没人认得它是谁
      （这次它就替我把"没重编"藏了 20 分钟）；
- [ ] 两棵树给出不同结果时，先怀疑**验证对象**，再怀疑被测代码
      （见上一节"定位靠的不是'红了'，是'红的具体内容'"）。
