# 链接不知道它的目标已经没了

## 核心

2026-10-26，给 W1 / W2 补测试那一轮的收尾：
一张 atomic 卡被**删掉**了（它和另一张卡讲同一个概念，内容被折叠进旧卡
当「复发 N 次」一节）。

**删掉是对的** —— 一卡一概念，两张卡讲同一件事等于同一件事有两个版本。

但**三张别的卡还指着它**。

而且**没有任何东西报过错**：

- 链接的文字还是那么好看；
- markdown 还是照常渲染；
- CI 是绿的。

## 关键：链接**不会自己漂**

`at-the-table-nobody-checks-drifts.md` 那张卡讲的是
「没人检查的**表**会漂」——
表里的**数**和现实对不上，是有人改了现实没改表。

链接是**另一个形状**：

> **链接本身一个字都没变。**
>
> 变的是**它指的那个文件没了**。

所以**盯着链接看是看不出来的** ——
链接写得完全正确，它只是在说一个不再存在的东西。

| | 表漂了 | 链接断了 |
|---|---|---|
| 变化发生在哪 | 表里的数 | 目标文件 |
| 链接/表本身 | 变了（没跟上） | **一个字都没变** |
| 怎么发现 | 拿现实对一遍 | **跟着走一遍** |

⇒ **链接只能靠「跟着走」来检查，读是读不出来的。**

## 顺带抓到的第二个：一个**从来没被点过**的坏链接

写完检查器，第一次跑就逮到**另一个**坏链接 ——
而且它跟这一轮毫无关系，是**早就坏在那儿**的：

`W7_VisionMasterLite/README.md` 里写着

```
[operator_library_groups.h](W7_VisionMasterLite/operator_library_groups.h)
```

而这个 README **就在 W7_VisionMasterLite/ 里面**。

于是那个链接指的是

```
W7_VisionMasterLite/W7_VisionMasterLite/operator_library_groups.h
```

—— **多了一层目录**，不存在。

它想指的是 `W7_VisionMasterLite/operator_library_groups.h`（在上一层）。

> 这就是**相对路径的经典坑**：
> 从 `W7_VisionMasterLite/README.md` 出发，
> `W7_VisionMasterLite/x.h` 里的 `W7_VisionMasterLite/` 是**再来一遍**。
>
> 写成 `./operator_library_groups.h` 才对。

**它坏了多久？不知道。** 反正比这一轮久。

## 修法：让检查器**跟着走**

`tools/check-links.ps1`（CI 的 Step 3d）：

- 遍历仓库里**所有** `.md`（工作区，不是 git index ——
  **刚写出来、还没 `git add` 的笔记也得查**）；
- 跳过**围起来的代码块** ——
  C++ 的 `operator[](qsizetype i)` 里也有 `](`，
  它不是链接，是个函数调用；
- **相对链接按「所在文件」解析** ——
  这正是 markdown 渲染器做的事；
- **不加「再试试仓库根目录」的兜底** ——
  那个兜底正好会**盖住**这类错误（错的路径在根目录下反而能找到）。

### 两条自己定的规矩

**① 外部链接不查，但要说出来。**

`https://` 指向仓库外面，这个脚本**不知道**它活着还是死了。
假装查了就是**「一个看不见的审计开始说谎」**（`at-an-audit-that-cannot-see-starts-lying.md`）。

⇒ 跳过的数量**打印出来**：
「skip 5 个外链」是**一句实话**，
「查了 5 个外链」是**一句假话**。

**② 一条链接都没查到 = 失败。**

如果检查器一个相对链接都没找到，那要么是**树指错了**，
要么是**它的正则不匹配了** ——
这两种情况看起来**都像通过**。

> 一个找不到东西的检查器，比没有检查器更坏：
> 没有检查器，你知道那里没查；
> 找到 0 个的检查器，你会以为那里查过了。

## 变异验证：这个检查器**自己**不是摆设

新写的检查器**自己也是可能错的**，
所以照例**故意把链接改坏**，看它会不会叫：

| # | 改了什么 | 期望 | 实测 |
|---|---|---|---|
| 1 | 指向 `./at-no-such-card-exists.md` | 红 | **红 ✓** |
| 2 | 链接写成 `W7_VisionMasterLite/operator_library_groups.h`（多一层） | 红 | **红 ✓** |
| 3 | C++ 里的 `](` （`auto hook = [&](...)`） | **绿** | **绿 ✓** |

第 3 条是**反向**的验证：
如果检查器把代码块里的 `](` 当成链接，
它会**误报** —— 一个天天误报的检查器，
大家会学会忽略它，然后它就等于不存在。

> **误报和漏报一样致命**：
> 漏报是「本该红没红」，误报是「本该绿报红」——
> 后者更隐蔽，因为它会**训练人忽略这个检查**。

### 检查器自己也被这个坑绊了一次

写完检查器，第一次跑 —— **它报错了，而且错的是它自己**：

```
FAIL: at-a-link-does-not-know-its-target-is-gone.md:
      link 'qsizetype' does not resolve
```

那个 `qsizetype` 来自**这张卡自己**里的一行 C++：

```
C++ 的 `operator[](qsizetype i)` 里也有 `](`，
```

两个 bug：

1. **行内代码没被跳过** ——
   围起来的代码块跳过了，**行内的 `...` 没跳**；
2. **裸目标里有空格时**，
   `qsizetype i` 被切成了 `qsizetype` ——
   而 markdown 里**裸目标根本不能带空格**
   （要带就得写成 `<qsizetype i>`）。

⇒ 改法：**行内代码也算代码**，
**目标后面跟的东西必须是带引号的标题**，否则它就不是链接。

> 这就是**为什么新写的检查器要立刻变异验证**：
> 第一版跑出来是**红的**，而那个红是**它自己的 bug** ——
> 如果我当时只看「报错了」，就会去改文档，
> 把一段**正确的 C++ 代码**改成能骗过检查器的样子。
>
> **「检查器报错了」的第一反应应该是「检查器错了」**，
> 不是「文档错了」。

## 教训

> **删一个文件，不只是删一个文件。**
>
> 它还删掉了**所有指向它的地方** ——
> 而那些地方**不会自己知道**。

⇒ **推论**：
> **每一次删除/改名，都要跟着一次「谁在指它」的搜索。**
>
> 改代码的时候没人会忘（编译会报错），
> **改文档的时候没人会忘** —— 因为**没有编译器**。

而**最省事的办法**不是每次记得搜，
是**让机器每次都查**。
