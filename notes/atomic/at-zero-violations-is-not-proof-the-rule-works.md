# 「零违规」不能证明规则在干活

## 核心

2026-10-22，第七轮给旋钮审计的规则 3j 补上**第四处位置**（面板初值）时遇到的。

规则 3j 盯的是"旋钮的默认值只能来自 `operator_defaults.h`"，
它盯四个地方：声明 / 面板读回 / run 兜底 / **面板初值**。

第四处是这一轮新加的。补完之后，实测结果是：

```
第四处(面板初值)一共核过了 41 个初值表达式
第四处(面板初值)发现 0 处本地常量当默认值
```

**一个违规都没有。** 干净。

但这时候有个问题：**"没有违规"和"规则在看空气"，在日志里长得一模一样。**
两个都是"没报红"。

## 为什么不能就此收工

断言只能回答「**没找到**」，回答不了「**找得到**」。

规则刚补上的时候，解析器可能压根没认出 `new QLineEdit(...)` 这种形状；
本地常量的正则也可能匹配不到；
"41 个初值表达式"这个计数也可能数的是别的东西。

**这些全都不会红。** 规则越"安静"，越可能它只是**安静**。

## 收法：用变异证明它抓得到

注入它**该抓**的东西，看它红不红：

| 编号 | 注入 | 预期 |
|---|---|---|
| M42 | 面板初值用了一个本地常量，它的值是**字面量** | **红** |
| M43 | 面板初值用了一个本地常量，它指向**别的算子**的 Defaults | **红** |
| M44 | 面板初值用了一个本地常量，它指向**本算子**的 Defaults | **不红** |

M42/M43 证明规则**抓得到**；M44 证明规则**不乱抓**。

> ⚠ M44 是这一轮最容易被省掉、但**不能省**的一个。
> 一个只会说「红」的规则不是规则，是**噪音发生器** ——
> 而误报的守卫会被下一个人关掉（这条本项目栽过五遍）。
>
> "该红的时候红"和"不该红的时候不红"，**两个都要验**。
> 只验前一半，等于只验了尺子的一半。

## 顺带把变异脚本改了

脚本原来只有"杀了 / 活了"两档。这一轮给每个变异加了一个 `Expect` 字段：

```powershell
@{ Id = 'M42'; Expect = 'KILL';    Steps = ... }
@{ Id = 'M44'; Expect = 'SURVIVE'; Steps = ... }
```

跑完自动比对"预期 vs 实际"，不符就报 `unexpected results = N`。

（第一版写的时候踩了个小坑：期望写的是 `KILL` / `SURVIVE`，
判定出来的是 `KILLED` / `SURVIVED`，字符串对不上 ——
结果三个**全对**的变异被报成"三个全错"。
**尺子自己坏了的时候，它也会用最自信的语气告诉你结论。**）

## 教训

> **规则要能回答两个问题：**
> **① 该红的红了吗？② 不该红的没红吗？**
>
> 第一个问题靠变异验，第二个问题也靠变异验 ——
> 而且第二个问题最容易省，省了就等于留下一颗**定时炸弹**：
> 等哪天有人把合法写法也判成红，守卫就被关掉了，
> 连带着第一个问题也不再有人问。

> 配套的一条：**"没报红"不是证据，"报红了"才是。**
> 一条规则刚补上时，它的价值不在于现在抓到了几个，
> 而在于**它抓不抓得到**这件事被验过了。
