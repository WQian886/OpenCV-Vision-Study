# 静默失效的共同形状：越靠近"成功"越不报错

## 一句话
> **条件恒假 → 中间量变 0 → 下游阈值把关掉 → 结果变 PASS**

四种不同的 bug，同一个根。这是排查顺序该用的线索。

## 为什么排序上它比崩溃更危险

崩溃会给你一个栈、一个异常码、一次复现。
静默失效给你**一个看起来完全正常的结果**：
状态点是绿的，日志干净，流程跑得动。

**没有任何东西会提醒你。**

## 四个实例（同一个根）

| # | 恒假的东西 | 怎么恒假 | 后果 |
|---|---|---|---|
| 1 | 白色丝印掩膜 | `neutralness = max/min` 恒 ≥ 1.0，阈值调到 0.98 → 掩膜全空 | 极性反的板报 PASS |
| 2 | 错色判据 | `1.6×板面G` 在高亮度下算出 259，uint8 到不了 | 报 PASS |
| 3 | 规则匹配 | 中间量 0 → `white% = 0 < 阈值` → 规则整条不跑 | 报 PASS |
| 4 | 参数守卫 | 默认值形参让"忘传参数"变静默 | 旋钮半失灵 |

### 实例 1 的实测断崖
```
neutralMax = 1.15 → 4.21%    1.02 → 4.10%    1.00 → 4.05%
neutralMax = 0.98 → 0.00%    0.92 → 0.00%    0.80 → 0.00%
```
不是渐变，是 1.00 处的**断崖**。
这告诉我们：判据有个**数学地板**，不是标定出来的经验值。

### 实例 2 的量程上限
8 位色深上限 255。临界亮度 = 255/(1.6×90) ≈ 1.77，
与实测塌点吻合。**阈值和量程要一起算。**

## 排查手法

### 手法一：给判据配边界守卫
越界时**拒绝判定并报错**，不要硬撑一个 PASS。
和已有的「没有判定依据就拒绝判定」是同一条原则。

### 手法二：数学边界要证明，不能标定
"这个阈值能不能取到 0.5 以下"这种问题，
应该**穷举或证明**，不是试几组数觉得"太严了"。

> 区别：阈值偏严 → 少判（能发现）；
> 判据被证伪 → 永远不可能成立（发现不了）。

### 手法三：自检问三问
已有「恒判合格比恒判不合格危险」的三问清单，
这里补一条**定位**用的：

> 出问题时，先看**哪个中间量变成了 0**。
> 恒假的判据往下游走，第一个表现一定是某个统计量归零。

## 推论
找**共同形状**比逐个打补丁有效。
本项目四种静默失效，逐个修是四次；
认出形状后，新增判据时就知道该配什么守卫。
