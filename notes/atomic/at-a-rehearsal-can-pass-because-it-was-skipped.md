# 「彩排通过」可能只是因为整段被跳过了

## 核心

> **一段代码「没报错」和「被执行过并且是对的」，在日志上长得一模一样** ——
> 尤其当它**根本没被执行**的时候。
>
> ⇒ 彩排必须报出**「我执行了哪几段」**，而不只是**「我没报错」**。

## 现象（2026-10-26，推上 GitHub 之前）

`tools/ci-deps.ps1` 里装 Qt 那一步的形状是：

```powershell
if (-not (Test-Path (Join-Path $qtDir 'lib\cmake\Qt6'))) {
    ... aqt --dry-run ...
    ... aqt install-qt ...
}
```

**这台机器上 Qt 早就装好了** ⇒ 整个 `if` 块**被跳过**。

于是：

- 彩排一直是绿的（它只报告「没报错」）；
- 而**块里的 dry run 从来没跑过**；
- 块里那句 `python -m aqt` —— **脚本从头到尾没装过 aqtinstall**。

## 实测：那一步**在这台机器上本来就是红的**

把 Qt 那块绕过去（`-SkipQt` 不行，Qt 就在那段里），
直接调 aqt（2026-10-26 实测）：

```
WARNING : The py7zr module failed to load. Falling back to '7z'
ERROR   : Fallback 7zip command executable does not exist: '7z'
```

这台机器**既没有 7z**（不在 PATH、不在 `C:\Program Files\7-Zip`）
**也没有 py7zr**。

⇒ **不是「这段代码有 bug」，是「这段代码从来没被执行过」。**

## 为什么本地彩排看不出来

彩排跑的是 `-VerifyOnly`，它报的是「我没报错」。

但**被跳过的那一段**，既不报错、也不说话：

```
Qt 早就装好了
  └─ if 块整个跳过
       ├─ dry run（包名解析）      没跑
       ├─ aqt install-qt（真装）   没跑
       └─ aqt 依赖 aqtinstall      没人提这件事
```

**而这两段恰恰是**「新 runner 上会死」的那两段。

> 这是本项目栽过好几次的那一族：
> 「**没人在没跑过的东西上签字**」。
> 只不过这一次签字的不是人，是**彩排**。

## 判定实验：把「跳过」变成「可见」

不用推演，两个办法任选：

1. **对照跑**：把 HEAD 那版脚本原样取出来，和改完那版**同样地跑**，
   看红的位置一样不一样（这次：两版**红得一模一样** ⇒ 不是我改坏的，
   是**本来就红**）。
2. **把环境还原成坏的那一半**：把 Qt 装好的状态去掉 / 把模块卸掉，
   让那段代码**真的被执行**。

第二个办法顺带逮到一个更贵的错 ——
见 `at-the-detector-must-not-die-on-what-it-detects.md`：
**检查模块在不在的那个函数，在模块不在时把脚本带走了。**

## 修法

三件，缺一不可：

1. **依赖要自己装**：脚本不能假设 runner 上有 `aqtinstall` / `py7zr`
   （本机恰好有，那只是**这台机器的事实**）；
2. **bootstrap 要放在 dry run 之前** ——
   dry run 的作用正是「把 2 GB 下载换成一句精确的错误」，
   它本该是那道保险，**不能是第一个倒下的砖**；
3. **彩排要报出执行了哪几段** ——
   被跳过的那段必须**显式说出来**（「skipped」不算失败，但要算**被说出来**）。

## 教训

推论一：

> **「没报错」是关于**过程**的陈述，
> 「跑过了」是关于**覆盖**的陈述。**
>
> 它们不能互相替代。日志只给前者。

推论二：

> **「这台机器恰好有」是关于这台机器的陈述，
> 不是关于**目标环境**的陈述。**
>
> ⇒ 目标环境（runner）上**有什么**，要么去查清单，
> 要么**让脚本自己装**。
> 两条路都比「假设它有」强。

推论三：

> **被跳过的代码是「还没写过的代码」。**
>
> 它和「写错了的代码」在日志上没区别 ——
> 但在**后果**上差很远：
> 写错的会被抓到，跳过的**连抓的机会都没有**。

推论四：

> **要证明一段代码能跑，得先制造一个「它必须跑」的环境。**
>
> 而不是「在一个它可以不用跑的环境里，看它有没有报错」。

## 检查清单

- [ ] 这段彩排/测试，**有没有整段被跳过**的可能？
- [ ] 被跳过的路径，**说出来了吗**？
- [ ] 脚本依赖的东西，是**它自己装的**，还是「目标机器恰好有」的？
- [ ] 我要验的这段代码，**这一轮真的被执行了吗**？
- [ ] 判据是「我没报错」，还是「**它跑过了，而且结果对**」？
