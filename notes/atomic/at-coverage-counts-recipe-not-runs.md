# 报告说「已覆盖」≠ 规则真的跑过

## 现象
输出 JSON 里有个字段 `withRules`,列出这次判定覆盖了哪些规则:

    "withRules": ["missing", "bridge", "polarity", "insufficient", ...]

报告上白纸黑字写着 `insufficient` **已覆盖**。
实测:7 个站点里它**只跑了 1 个**。

## 根因:`withRules` 数的是「配方里写了什么」
它遍历的是**配置/配方** —— 也就是"我打算查什么",
不是"我真的查了"。两者在有守卫的系统里必然分叉:

    配方请求 6 个站点  ->  withRules 写 "insufficient x6"
                         ↓
              守卫 areas.size() >= 4
    实际执行 1 个站点  ->  报告毫无异样

**而且它说得特别像结论**:数字齐全、格式统一,没有任何"这一条我没查"的余地。

## 为什么藏了这么久
它不是在某一轮坏的,是**一直这样坏,没人查**。
真正让它藏住的是两件事叠加:

1. 早期还有真值图的时候跑过,后来换了板型就没再复查
2. 覆盖度报告本身是**绿的** —— 它报的确实是"配方写了 6 个"

于是"报告说查了" + "没发现坏结果" = 看起来没问题。

## 修法:第三种状态必须显式存在
判定的结果空间本来只有两个:`PASS` / `FAIL`。
加上守卫之后变成三个,而第三个被丢了:

    PASS          查了,没查到缺陷
    FAIL          查了,查到缺陷
    **没查**      ← 必须被说出来

```cpp
output["skipped"]       = skipped;        // 每条:component / rule / reason
output["skipped_count"] = skipped.size();
if (!skipped.isEmpty()) {
    output["warning"] += "另有 N 条规则被守卫跳过(见 skipped),"
                         "这些**没查**——不等于合格。";
}
```

`reason` 里要带**实测数**,不是一句"被跳过":

> "金层连通域只有 3 个(< 4),取不了焊盘中位数,本规则不判定"

这样看报告的人一眼能自己判断这个跳过一次要不要紧。

## 配一条不变式,而不是钉今天的数字
钉具体数字只能防今天,代码一改就失效。真正管将来的是**不变式**:

> **配方请求的每一条规则,必须出现在 `metrics` 或 `skipped` 里。**

少了任何一个,测试变红。这条断言审的是**两个集合的并集**,
所以它对将来新增的规则、新的守卫都有效。

## 附带:注释承诺了代码没做的事
`polarity` 那个守卫上面有一句注释写着"记一笔" ——
**代码里什么也没记**。注释和代码一样会过期,
但注释过期不产生编译错误,测试也不会红。

- [ ] 结果空间是 2 态还是有守卫?3 态的话第三态报出来了吗
- [ ] `reason` 带实测数了吗,还是只有一句"被跳过"
