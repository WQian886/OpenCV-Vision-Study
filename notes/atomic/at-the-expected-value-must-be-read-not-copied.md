# 期望值要**读**出来，不要**抄**一份

## 核心

2026-10-26，W7 结项之后还的第七笔（欠账 11）遇到的。

要给「文档里的数和现实对不对得上」加一道门禁。
第一反应当然是**在 CI 里写死**：

```powershell
if ($measured -ne 2371) { Fail "the assertion count changed" }
```

**那样做就正好犯了本项目一直在治的病。**

```
硬编码的期望值  =  第二个副本  =  下一个会漂的东西
```

## 为什么「写死」比「读出来」差这么多

差别不在「哪个更准」，在**门禁把矛头指向谁**。

| | CI 里写死 2371 | 期望值从文档读 |
|---|---|---|
| 代码改了、文档没改 | CI 红 | CI 红 |
| 修的时候该改哪 | **CI 里的数** | **文档** |
| 那个数会不会自己过期 | **会**（没人记得改） | 不会（只有一份） |
| 文档里那个数错了 | **CI 不知道** | **CI 红** |

第三行是要命的那行：CI 里写死一份之后，
**改代码的人看到 CI 红了，只会想「改 CI 里的数」** ——
因为那是他**唯一看得见**的那个数。
而**文档**里的那个数他根本不知道存在。

⇒ 门禁把矛头指向了**错误的方向**，
而且**主动**把人往「让门禁闭嘴」那边推。

## 正确的做法

> **期望值从文档里读出来，和实测比。**
> 文档是那个数的**唯一**存放处；
> 检查器**只知道去哪儿找**，不**知道它应该是多少**。

于是：

- 文档过期 → 检查器红 → 人去改文档；
- 检查器认不出文档（措辞改了） → 检查器**也红**，
  而且说清「**锚点该更新了**」。

> ⚠ **「认不出就说认不出」在这里是硬要求。**
> 一条规则停下来不报，比它报错更贵 ——
> 「检查器不再认识自己的文档，然后什么都不说」，
> 那是本项目一直在付的学费
> （`at-an-audit-that-cannot-see-starts-lying.md`）。

## 但有个坑：读出来的东西**不是数**，是**位置**

「从文档读期望值」听起来简单，做起来要解决一件事：
**读哪一处？**

文档里同一个数出现**很多次**（散文里、表格里、总结里）。
读错了地方，就把**历史快照**当成当前声明。

⇒ 解法是**锚点**：检查器里写「去哪个文件、哪个形状的那一行读」。
锚点只用 **ASCII** 标记（因为 `.ps1` 必须是纯 ASCII，
中文锚点会变乱码，而**乱码的匹配不报错，是静默不匹配**）。

⇒ 配套：`at-a-historical-snapshot-looks-like-a-current-claim.md`。

## 教训

> **凡是要拿一个数当「期望值」，先问：这个数在仓库里存了几份？**
>
> 一份 → 从它读出来比。
> 多份 → **先把它收成一份**（或者每一份都查），
> 然后再比。
>
> **在检查器里写死一份，等于把「抄副本」这条老毛病
> 从产品代码搬进了门禁。**
>
> 门禁是**照抄别人的**数来判对错的，
> 它比产品代码更需要一个**单一来源**。
