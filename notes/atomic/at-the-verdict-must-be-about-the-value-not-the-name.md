# 判据要问「这个值从哪来」，不要问「这个名字像不像默认值」

## 核心
2026-10-21，第五轮（给旋钮审计补三条新能力）遇到的。

欠账 12 记着这样一条病：

> 「文件里自己 define 一个常量当默认值」这一类抄副本，审计查不到。

难处在**怎么把「抄副本」和「算法常量」分开**。
`operators/circle_fit.cpp` 里全是常量：

```cpp
const double area = std::fabs(cv::contourArea(ctr));   // 算法常量
const int    minArea = 50;                              // 抄本？
```

光看「是不是裸字面量」分不出来 —— 前者也是裸字面量（`0.8` 之类）。
而如果改成看「名字像不像默认值」（`kMinArea` 像，`area` 不像），
那就变成**猜意图**，而猜意图的规则必然两头不讨好：
名字取得巧的抄本漏掉，名字取得像算法的真常量误报。

## 收法：判据问「值」，不问「名字」

不去猜作者想干什么，只问一个**可观察的事实**：

> **这个常量的值，是从哪来的？**

```cpp
// ① 值是字面量        → 它就是一份手抄的默认值        → 红
const int kFooLocal = 50;

// ② 值指向别的算子    → 绕过规则的后门                → 红
const int kForeignMin = CircleFitDefaults::kMinArea;   // 另一个算子的

// ③ 值指向本算子      → 它就是那份唯一清单            → 放行
const QString kDefaultRecipe = QString::fromUtf8(PcbInspectDefaults::kRecipePath);

// ④ 压根没有初始化    → 它不是值                      → 放行
const pcbcore::JudgeParams kCore;
```

四种情况**全都不需要猜意图**，每一种都能从源码里直接读出来。
而且第 ③ 条特别重要：它让「本地常量」这种写法**合法**了 ——
`pcb_inspect.cpp` 里那句 `kDefaultRecipe` 引用的是**自己**的 Defaults，
它不是抄本，只是给那份唯一清单起了个短名字。

## 为什么这条判据能同时做到「不漏报」和「不误报」

漏报和误报不是两种相反的运气，是**同一个原因**：
判据问的问题**没有唯一答案**。

- 问「是不是抄本？」→ 没有唯一答案（作者意图）→ 规则必然在猜 → 两头错
- 问「值从哪来？」→ 答案就在源码里 → 规则不用猜 → 唯一答案

> **一条规则能不能同时不漏报不误报，取决于它问的问题有没有唯一答案。**
> 有唯一答案的问题，再难也能写出来；没有唯一答案的问题，
> 写得再巧也只是在猜 —— 而猜测的准确率是靠不住的。

## 配套：三种"值从哪来"都要看得见

问对了问题，还得**看得见**答案。第五轮就补了三处：

| 位置 | 以前 | 现在 |
|---|---|---|
| `defaultParams()` 的声明 | 3i 盯着 | 3j 盯着 |
| `setParams()` 的兜底 | 只查裸数字 | 3j 盯着（含文本旋钮） |
| `run()` 的兜底 | 3d 只查裸数字 | 3j 盯着 |

⚠ 少一处就漏一类。`params.value("x").toString(kLocalConst)`
同时躲过 3d（只查裸字面量）和 3h（只查 `cv::` 前缀）——
**两条规则都看不见一个标识符**。

## 教训

> **写规则时先问自己："我这个问题有唯一答案吗？"**
>
> 有 → 直接写，答案在源码里，不用猜。
> 没有 → 这条规则一定在两头出错：
> 猜得像的那边漏掉，猜不像的那边误报。
>
> 误报尤其危险：**一个对自家代码误报的守卫，下一个人只会把它关掉** ——
> 那时候连原来能抓到的那一半也没了。
