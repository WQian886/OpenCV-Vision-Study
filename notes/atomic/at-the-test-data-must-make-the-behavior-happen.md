# 测试数据要让被测的行为真的发生

## 一句话
> **数据太小 / 太规整 → 被测的行为压根没发生 → 用例绿着，但它什么都没验。**

## 现象

写 `image_source_camera` 的 Bayer 用例时，我用了一张 **4×4** 的图，
原始像素 `10, 20, 30, 40, ...`。

用例要验的是「算子有没有按**实际像素格式**选对去马赛克的转换码」
（RG / GR / GB / BG 四种排布各用各的码）。

第一条断言是「先确认一下：同一份原始数据按 RG 解和按 BG 解**确实不一样**」。

**它红了。**

```
[FAIL] 先确认一下:同一份原始数据按 RG 解和按 BG 解**确实不一样**(不然这条用例是恒真的)
```

第一反应是「算子又选错转换码了」。不是。

## 真相比那更麻烦：OpenCV 在 4×4 上**根本没做去马赛克**

```
[DIAG] norm(RG,BG) = 0   asRG[0]= 60 , 60 , 60   asBG[0]= 60 , 60 , 60
[DIAG] 16x16 norm(RG,BG) = 128   bRG[0]= 93 , 157 , 221   bBG[0]= 221 , 157 , 93
```

- 4×4：RG 解和 BG 解结果**一模一样**，而且解出来是**灰的**（三个通道相等）
- 16×16：两者差 128，解出来是**真正的颜色**

也就是说：**4×4 的图上，"选对转换码"这件事根本没发生。**

更要命的是，用例里那句「用的是**自己那个**转换码(和期望差 0)」当时是**绿的** ——
因为算子和测试**用的是同一个 OpenCV 函数**，两边一起退化，差值自然是 0。

> **两个都错，反而没人看得出来**（和片 4 那张「形状和数据要对账」是同一个道理）。

## 教训

### 1. 恒真的用例比没有用例更坏

没有用例 = 没人以为这里被验过。
恒真的用例 = **有人以为这里被验过了**，而且测试报告是绿的。

恒真怎么来的？**被测的行为压根没发生。**

常见来源：

| 数据问题 | 后果 |
|---|---|
| 太小（4×4 这种） | 某些算法退化 / 边界分支走不到 |
| 太规整（纯色、全 0） | 差异被抹平，两个分支结果一样 |
| 刚好落在特例上 | 走的是另一条分支 |

### 2. 断言之前先断言「这个测试有牙」

```
// 先确认一下:同一份原始数据按 RG 解和按 BG 解**确实不一样**(不然这条用例是恒真的)
check(cv::norm(asRG, asBG, cv::NORM_INF) > 1.0, ...);
```

这一条**不是**在测产品，是在测**这套测试自己**。
它红了，才让我去查「为什么不一样」，然后查出了 4×4 的退化。

> 这就是「零违规不能证明规则在干活」的另一个马甲：
> **零失败也不能证明断言在干活。**

### 3. 「期望值和实现用同一个函数」要格外小心

期望值 = `cv::cvtColor(raw, COLOR_BayerRG2BGR)`，
实现 = `cv::cvtColor(bayer, COLOR_BayerRG2BGR)`。

同一个函数、同一份数据 → **只要那个函数退化了，两边一起退化，断言恒真**。

这种"用同一个工具当标尺"的测法**不是不能用**（它验的是「有没有选对那个工具」），
但必须配一条**独立**的守卫：

> 「两个分支的结果**确实不一样**」—— 这条用的是 `norm(asRG, asBG)`，
> 它不依赖被测代码，也不依赖哪个分支正确。

### 4. 顺手记一笔：真相机不受影响

4×4 的退化只发生在**小图**上。真实相机出的是几百万像素的图，
所以这不是生产 bug —— 但它**是测试数据 bug**，
而测试数据 bug 会让人以为"测过了"。

## 检查清单

- [ ] 测试数据**够大**吗？（某些算法在小图上退化）
- [ ] 测试数据**有区分度**吗？（纯色/全 0/对称图案会让分支结果一样）
- [ ] 用例里有没有一条**自检**：两个分支的结果确实不一样？
- [ ] 期望值如果是"用同一个库算出来的"，有没有配一条**不依赖那个库**的守卫？
