# 记录一次修复，把那个缺陷又写了一遍

## 一句话
> **「原来那一句是坏的」——这句话本身，会不会也是一句坏的主张？**
>
> ⇒ **修法的说明书，和产品代码一样，是被检查的对象。**

## 现象（2026-10-27，给文档加第四道门禁那一轮）

新写的章节指针门（`tools/check-sections.ps1`，CI 的 Step 3e）
第一次在真树上跑，**逮到了它自己的说明书**。

被逮到的是 `notes/notes_SectionPointers_2026-10.md` 第 3.5 节的一张表 ——
那张表的第三批记的是**上一个修复**（把本节自己举的那个假例子换成真有的文件）。
表里有一列叫「原来」，那一列**原样抄了修复前的那句话**：

```
「`x.md`。见第 3 节」
```

而按这一轮定的规矩（规则 7）：
**引号里的指针不是主张 —— 除非引号里自己点了名。**

这一句**点了名**（`x.md`）。
⇒ 于是它**不是引文，是一条主张** ⇒ 它说的是 ``「`x.md` 有第 3 节」``
⇒ 而 `x.md` **不在这棵树里** ⇒ **那一轮门禁报的是红**：

```
notes\notes_SectionPointers_2026-10.md:298: pointer '第 3 节' is bound to 'x.md',
  which is not in this tree -- so it cannot be checked
```

> ⚠ 上面那两行是**那一轮门禁的原话输出**（**历史快照**），
> 不是现在还红着 —— 现在**绿的**。

⇒ **修复记录里的那句坏话，把那个缺陷又造了一遍。**

## 为什么：一段散文里的「形状」就是它的**语法**

门禁读的是**形状**，不是**意图**。
这两句话在门禁眼里**完全一样**：

| 散文 | 门禁怎么读 |
|---|---|
| 「这里原来有个坏指针」 | 描述，**不是主张** |
| ``「`x.md`。见第 3 节」`` | **一条主张**（点了名） |

⇒ 差异必须写进**形状**里，不能靠「我的意思不是这个」。

三种把区别写进形状的办法：

| 办法 | 怎么写 | 门禁怎么看 |
|---|---|---|
| **写成代码**（这次用的） | 引用包在行内代码里 | **字面量**，不是主张 ✅ |
| **不点名** | 只说「那个坏例子」，不写文件名 | 引文，不是主张 ✅ |
| **划作用域** | 用锚点把历史段落隔开（历史快照那招） | 不在检查范围内 ✅ |

> 第一种最省事，而且**顺手把「我引用的就是这句话」写清楚了** ——
> 引号只表示「引文」，行内代码还表示「**原样**」。

## 修法：把引号改成**行内代码**

```
原来那一句是 ``「`x.md`。见第 3 节」``
```

⇒ 里面那个指针落进**代码**那一档（代码是字面量，渲染器原样显示）。
⇒ 量的结果（**当场量的，不是推的**）：

| | 改之前 | 改之后 |
|---|---|---|
| 行内代码里的指针（跳过） | 3 | **4** |
| **查不了**的指针 | **1** | **0** |

⇒ 门禁从红回到绿，而**规矩一个字没改**。

## 教训

> **记录一个修复，也是一次「写入主张」。**
>
> ⇒ 写下「这里原来有个 X」之前，问一句：
> **门禁会不会把这句话当成真的？**
> 尤其当你写的是**关于一个坏东西的句子**时 ——
> 那句话里**最像主张的部分，恰恰是你要引用的那个坏名字**。
>
> ⇒ 而这一轮还多了一层：
> **修法的说明书，本身就是被检查的文档。**
> 门禁不是来检查你写了什么的，它是来检查**你写的每一句话**的 ——
> 包括你**为了说明自己修了什么**而写的那句。
>
> ⇒ 所以：改判据的代价要当场付（这一轮已经是第三次付了），
> 而**代价里就包括「修法的记录本身要重新改一遍」**。

## 检查清单

- [ ] 我写的这句关于「坏东西」的引用，**点了名**吗？
      点了名 ⇒ 它就是主张 ⇒ 要么写成**代码**，要么**不点名**。
- [ ] 这条记录本身，**过门禁**了吗？
- [ ] 我是不是在用「我只是举个例子」当豁免的理由？
      （**不是**豁免的理由 —— 见
