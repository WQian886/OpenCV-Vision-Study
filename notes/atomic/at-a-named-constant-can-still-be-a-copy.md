# 有名字的常量也可能是抄副本 —— `cv::TM_CCOEFF_NORMED` 不是字面量，但它仍然是"另一份默认值"

## 核心
2026-10-21，第三轮收尾时发现的。

审计规则 3d / 3g 查的是**兜底表达式里不许有裸字面量**：

```cpp
params.value("x1").toInt(0)                      // ← 裸字面量，抓得到
params.value("method").toInt(cv::TM_CCOEFF_NORMED) // ← 不是字面量，抓不到
```

第二种写法看着比第一种"正规"得多 —— 它有名字，来自库，不是随手写的数字。
但它**仍然是抄副本**：

> 「默认用哪个匹配方法」是**这个算子自己的决定**。
> 那个决定写在算子文件里（`operators/template_match.cpp`），
> 就等于 `operator_defaults.h` 那份声明之外又多了一份。

实测 `template_match` 的匹配方法默认值抄在**三处**：
`defaultParams()` 的声明、`run()` 的兜底、`setParams()` 的兜底。
三处写的都是 `cv::TM_CCOEFF_NORMED` —— 值一样，所以**没有任何一条规则报红**。

## 为什么它比字面量更危险

字面量至少**难看**。`cv::TM_CCOEFF_NORMED` 看着像个"引用库里的正规常量"，
读代码的人会认为"这是标准做法"，不会去查它是不是唯一一份。

而且它**不会漂** —— 恰恰因为它不会漂，所以没人会去查。
等项目里出现"改了默认值但只改了一处"的场景时，它才会一次性爆开。

## 教训
> **"不是字面量"不等于"不是副本"。**
>
> 判断一份值是不是抄副本，要问的不是"它长得像不像常量"，
> 而是"**这个决定该由谁做**"：
>
> - 旋钮的默认值 → 该由唯一那份清单（`operator_defaults.h`）做
> - 合法范围（比如 `method` 的上下界）→ 该由**范围**那件事做，写在范围检查里就诚实
> - 共享参数（比如 `pcbcolor::kMaskVMul`）→ 该由共享核心做，那**就是**唯一一份
>
> 同是 `cv::` 开头，**含义不同，待遇就不同** —— 所以不能一刀切禁掉 `cv::`，
> 要先把每个常量归到"谁该决定它"那三类里。

## 落到本项目怎么做的

1. `template_match` 的默认值收进 `operator_defaults.h`：
   `TemplateMatchDefaults::kMethod = cv::TM_CCOEFF_NORMED`，
   声明 / `run()` 兜底 / `setParams()` 兜底三处都引用它。
2. 面板那个下拉框的初值**改成按 `kMethod` 选**，而不是"列表第一项恰好是它"。
   （原来靠"TM_CCOEFF_NORMED 排在第一位"当默认值 —— 那是**巧合**，不是声明。）
3. 新增 lint **3h**：兜底表达式里不许直接出现 `cv::` ——
   要用就在 `operator_defaults.h` 里声明一个具名常量，兜底引用那个。
   故意只查 `cv::`：`pcbcolor::` 那类**共享**常量不算抄副本
   （`common/pcb_core/` 就是唯一一份），规则**宁窄勿宽**。

## 但这条仍有边界（写下来免得下一个人以为查全了）

- 3h **查不出**"文件里自己 `constexpr int kMethod = 3;` 再在兜底里用它" ——
  那也是抄副本，是另一类形态，还没查。
- 3h **查不出**合法范围里的 `cv::`（那是**范围**，不是默认值，本来就该写在那儿）。
- 两者都不能靠"看起来像不像默认值"来判断 —— **要看这个值在回答什么问题**。
