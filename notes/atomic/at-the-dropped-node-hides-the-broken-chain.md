# 丢掉一个节点，断掉的是整条链

## 核心

2026-10-25，W7 旋钮审计还欠账 19 时解决的（欠账 18 的**加载期**形状）时遇到的。

W7 读工程文件时，遇到**当前机器上没装的算子**，解析层**直接丢弃**那个节点：

```cpp
// pipeline_graph.h（2026-10-25 之前）
if (!def.known) {
    logFn(QString("[Load] 跳过未知算子: %1").arg(opName));
    ++skipped;
    continue;          // ← 节点没了
}
```

看着很合理：算子没装，留着一个也跑不了，跳过就完了。

## 但丢掉一个节点，是**连锁**的

```
未知算子被跳过
  → 指向它的**边端点缺失**
  → **边也被跳过**
  → **链断成两截**
  → 下游拿**空输出**
  → 默认值兜底
  → 数字正常
  → 判 PASS
```

> **存盘里少一个算子，伤的是它后面所有算子。**

而且这条链上**没有一环会报错**：
不崩、不异常、退出码 0、GUI 和 CI **两边都是绿的**。

日志里确实有一行「[Load] 跳过未知算子: xxx」——
但那是**日志**，不是**画布**：
画布上那个节点**压根不在**，连线也**压根不在**。
用户看到的是一条**少了一半**的流水线，跑出来**判 PASS**。

## 最毒的一层：它有一条**绿着的**测试

`test_headless_runner.cpp` 当时写着：

```cpp
check(ok, "有未知算子 -> 其余的照跑");
check(!rec->opOrder.contains(QStringLiteral("不认识的算子")),
      "不认识的算子**没有**被跑");
```

`test_undo_redo.cpp` 当时写着：

```cpp
checkEq(cv3.nodes().size(), 2, "未知算子被跳过,只留下 2 个真节点");
```

两条都在**断言那个 bug**。
它们是绿的 —— 一条**绿着的**用例，给 bug 发了通行证。

> **「有测试」不等于「测的是对的东西」。**
> 一条断言如果写的是「跳过是对的」，那它就**锁死**了跳过这件事。
> 而且它让 bug 看起来像**规格**。

## 教训

> **「处理不了的东西」有两种做法：**
> **丢掉它**，或者**留着它但说清它处理不了**。
>
> 丢掉它 = 让**下游**替它背锅 ——
> 而且下游**不会知道**自己背了锅（它拿到的是空输出，不是错误）。
>
> > 静默失效比崩溃难查。
> > 而「丢掉一个节点」是**最贵的那种静默失效**：
> > 它不是让**一个**节点出错，是让**一整段**链在背一个没人知道的锅。

### 具体到「留着但说清」

这一轮的做法（`pipeline_graph.h`）：

| 做法 | 效果 |
|---|---|
| 节点**留在图上**，标 `known=false` | 画布上看得见（**画布忠实度**） |
| 它的 uuid / op 名**照样登记** | 指向它的边**接得上** → **链不断** |
| 画布上标成「未安装」（灰底 + 虚线框） | 用户**一眼**看得出少了什么 |
| 运行时那一步**失败** | 整批判 **ERROR**，不是静默 PASS |

链没断 ≠ 没事。
链没断的意思是：**下游拿到的是「上游那一步失败了」这个事实**，而不是「上游安静地什么都不产出」。

## 推论：三个「处理不了」要分清

这一轮顺手分清了三件事。以前它们混在一个 `skippedEdges` 里：

| 情况 | 端点 | 怎么办 |
|---|---|---|
| **算子没装** | **在**（只是跑不了） | 留着，标出来，那一步失败 |
| **端点真不存在** | 不在 | 跳过，**报出来** |
| **文件里没记方向** | 在 | 按默认画，**说一声** |

> 分不清这三件事，就只能给它们起一个**笼统**的名字
> （`skipped`），而笼统的名字会**掩盖差异** ——
> 然后处理方式只能取最保守的那个：**全丢掉**。
