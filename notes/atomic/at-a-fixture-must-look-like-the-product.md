# 测试夹具的形状，必须和产品写出来的形状一样

## 一句话
> **随手编一个键名，测的就是一个磁盘上根本不存在的世界 —— 而且它是绿的。**

## 现象

给 W7 的 headless runner 写第一版测试。造流水线 JSON 的时候，
节点的 uuid 是随手编的：

```cpp
mkNode("src",   "u-src")
mkNode("judge", "u-judge")
mkEdge("u-src", "u-judge")
```

套件全绿。**117 条断言，一条没红。**

然后 CI 的冒烟步骤第一次真跑一条完整流水线，红了：

```
[Load] 边的端点缺失: smoke-inspect → smoke-judge
[Load] 完成: 创建 2 个节点(跳过 0),连线 0 条(跳过 1)
[Run] 跑完: 1 帧,PASS 0,FAIL 0,判定 ERROR(有 1 步报错)
```

退出码 3。而 `pipelines/smoke.json` 里的 uuid 写的是
`"smoke-inspect"` / `"smoke-judge"` —— **和测试夹具一模一样的错**。

## 真凶

产品存盘写的是：

```cpp
nj["uuid"] = n->uuid().toString(QUuid::WithoutBraces);   // 真 UUID
```

解析层判断「这条边是不是新版格式」靠的是：

```cpp
const QUuid id = QUuid::fromString(fromKey);
const bool useUuid = !id.isNull() && !toId.isNull();
```

`"u-src"` **解析不出 UUID** → 判成**旧格式**（两端存算子名）
→ 去算子名表里查 `"u-src"` → 查不到（表里是 `"src"`）
→ 边被丢掉，报「端点缺失」。

所以在**真实语义**下，测试里那条边从头到尾就没接上过。
测试测的是"一种假想的格式能不能跑通"。

## 为什么这个坑特别安静

- 不红
- 不崩
- **全绿**

而且它绿得很有说服力：断言一条条都验到了自己造的那个世界，
断言本身没毛病 —— 毛病在**夹具和产品对不上**。

最贵的地方在于：这条测试是**新增的**，本来是来护住新代码的。
结果它护住的是"如果有人改了那个判据，测试会红" ——
而判据一改，夹具也跟着改，测试就跟着改坏 ——
**两边同时漂移，中间那道缝没人看得见。**

## 同一个错在真数据上又犯了一遍

`pipelines/smoke.json` 是 CI 冒烟跑的那条流水线，也是手写的，
uuid 同样写成了 `"smoke-inspect"`。

同一个错，一个在夹具里（无声），一个在真数据里（CI 冒烟抓到）。
但真数据那次的**症状极具误导性**：

> 报出来的是"流水线判定 ERROR"，像是流水线内容有问题；
> 真相是"文件里的键写错了"。
>
> 查的方向完全不同 —— 而这正是最贵的那类 bug 长得最像的样子。

## 教训

### 1. 测试数据本身是有**契约**的

造测试数据之前，先看一眼**产品真的产出什么形状**：

| 想测什么 | 产品真的写什么 | 随手编的会怎样 |
|---|---|---|
| 节点身份 | `QUuid::WithoutBraces` | `"u-src"` → 当成算子名 |
| 边方向 | `from_side` / `to_side` 整数 | 漏掉 → 走默认重画 |
| 端点语义 | uuid 字符串 | 算子名 → 走旧格式 FIFO |

随手编的键名，是"看起来没问题"里最常见的一种。

### 2. 绿色的断言要问一句"它护的是真东西吗"

零违规不能证明规则在干活（见
`at-zero-violations-is-not-proof-the-rule-works.md`）。
一条断言绿了，要问的是：**它对着的东西，是产品会产出的那种东西吗？**

### 3. 夹具那一份比真数据那一份更要紧

真数据错了会红（CI 冒烟抓到了）。
夹具错了**不红** —— 它只是让所有断言都在一个假世界里自洽。

### 4. 手写的数据文件要有人守

`pipelines/smoke.json` 现在有一条纯解析层的单元测试钉着
（`test_headless_runner.cpp` 用例 15）：

```
edges 的两端都是真 UUID
没有边被跳过
每个节点的 uuid 都是真 UUID
```

几毫秒，而且能说清是哪个文件 —— 比"CI 冒烟红了、日志说端点缺失"省事得多。

## 检查清单

- [ ] 测试数据里的 id / 键，是产品**真的会写出来**的形状吗？
- [ ] 造夹具时，抄的是产品的**输出**，还是你的**想象**？
- [ ] 断言全绿时，问一句：它护的是一个**存在**的格式吗？
- [ ] 手写的数据文件（不是生成的）有没有自己的测试？
- [ ] 同一个错在夹具和真数据里各犯一遍 —— 先修夹具那份
