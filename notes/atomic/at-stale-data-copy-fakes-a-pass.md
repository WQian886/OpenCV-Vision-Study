# 陈旧的数据副本会让测试「判得对」——判的是旧东西

## 现象
改完判据、跑测试，红了。

改判据之前，同一个测试是绿的。按理说「改判据 → 测试变红」是对的，
但这次的红的**不像判据的错**：断言消息里写的读数和改判据前完全对不上。

查下去发现：**测试根本没跑到新代码要用的那张图**。

## 病根：数据也有副本
本项目抄过四遍代码，第五遍抄的是**数据**：

```
W6_PCB_DefectProject/images/     ← 生成器住的地方（真的那份）
W7_VisionMasterLite/images/      ← 一份副本，2026-09-14 之后就没人动过
```

两份**都进了 git**。改图只发生在 W6 那份上，W7 那份静悄悄地停在原地。
W7 的构建脚本从**自己那份**拷测试图，于是测试一直拿旧图。

## 为什么它特别贵
**旧图 + 新判据，结论照样自洽。**

短路判据的输入是「图里两个端子之间有没有金属」——
旧图里那两个端子之间也是没有金属的（那是**旧**的短路图，短路画在别处），
所以判据给出的读数虽然不对，但**结论是自洽的**：好板不像短路图。

于是现象变成：
- 看起来像「判据写错了」
- 实际上「数据没跟上」
- 两者查的方向**完全相反** —— 一个改代码，一个改数据

数据副本不会编译报错，不会类型不匹配，只是**安静地过期**。

## 怎么认出来
一行命令，比推理快：

```powershell
Get-ChildItem <候选的两处> -Filter '*.png' |
  Select-Object FullName, Length, LastWriteTime
```

**大小和时间戳对不上**，就是它。
（本次实测：真源 13092 字节 / 16:36，副本 12744 字节 / 09-14 上一轮。）

## 怎么修
1. **删掉副本**，只留一份，放在**唯一知道真相的那一方**（这里是生成器）。
2. 构建脚本的取数路径改成指向那一份。
3. 文档里写「复用」的地方，如果实际是「复制」，**改成实话**。

> 📌 副本删掉之前，先确认没有别的路径依赖它。
> 本次 W7 的 GUI 应用也拷了一份图到 exe 旁边，改路径时一起改掉了。

## 顺带一条
「测试工作目录里暂存的数据」也是同一类问题：
暂存是**拷贝**，拷贝就会过期。
所以暂存必须**每次构建都重拷**（`add_custom_target` 没有输出文件，
CMake 永远认为它过期），不能挂在 `POST_BUILD` 上。

## 检查清单
- [ ] 这个数据有几份？谁在写？
- [ ] 测试读的那份，和被测逻辑要用的那份，是同一份吗？
- [ ] 数据副本会不会比源头**更旧**，而且没人发现？
- [ ] 改数据之后，**不用改代码**的路径上，测试会不会自动跟上？
- [ ] 文档里写「复用」的地方，真的没有复制吗？
