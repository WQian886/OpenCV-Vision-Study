# 相对判据的右端也必须带 k，否则"相对"是假的

## 补充关系
09-15 的「cv::inRange 阈值取样原则」讲的是
**阈值怎么定**（先取样本、逐通道填、不要凭直觉写对称范围）。

本文讲的是下一层：**定完之后，怎么让它随环境缩放。**

## 核心
相对判据只有**两边都带 k** 才叫相对。

```cpp
// ❌ 假的相对：右边是常量，等式右边没有 k
isDark = pixel < 0.6 * REF_BOARD_V;      // REF_BOARD_V 是某张图量出来的

// ✅ 真相对：右边也是当前这张图的量
isDark = pixel < 0.6 * estimateBoardBase(img);
```

**拿参考图的板色当常量写进配置，"相对"只是名字。**

## 这个坑是怎么被抓住的
探针第一版就把 `k=1.0` 时量到的板色 (50,90,40)
传给**每一档亮度**去测。结果它和绝对阈值表现**一模一样**。

> 如果你的"相对化"在实测里和绝对版没区别，
> 几乎一定是右端没跟着变。

## 参考值必须逐图估计，且估计量要选对

### 用中位数，不用均值
板面基色 = **逐通道中位数**。

| | 均值 | 中位数 |
|---|---|---|
| 被元件/丝印拉偏 | 会 | 不会 |
| 对全局乘 k | 不等变 | **保序 → 等变** |
| 抗削波 | 会被拉 | 会 |

实测：8 张样本 × 25 档亮度（k=0.40~1.60），
基色稳在 (50,90,40)×k，色度漂移 **k≤0.95 时恰好为 0**。

### 抽样的两个细节
- 隔行隔列抽（实现成本），但**逐通道**各取一个中位数，
  不要取"整体"中位数。
- min 为 0 的像素要单独处理（比值无意义），
  本项目返回极大值 = 明确判成"有彩色"，不去做 0 除法。

## 配套：每个系数都要留覆盖入口
否则"这个系数上下动 30%，结论变不变"这件事**没法扫**。

做法：把系数做成**带默认值的形参**，
生产代码走默认，测试和调参走覆盖，**两边共用同一份定义**。

```cpp
inline bool isWhiteSilk(const cv::Vec3b& p, const cv::Vec3b& base,
                        double brightMul = kBrightMul,     // ← 覆盖入口
                        double neutralMax = kNeutralMax) {
```

> 复制一份判据出来扫 = 又一次抄副本，
> 而抄副本的后果是两份定义慢慢漂开（这个项目栽过四次）。

## 配套：默认值形参的反面教训
形参默认值也会咬人：
调色掩膜传了参数，另一处却走了默认值 →
**调旋钮时一半生效一半不生效，且不报错**。

> 参数一改，所有用到它的地方必须同步。
> 不要在调用点依赖默认实参。

## 参数改名也是设计
绝对阈值改相对时，`min_area=80` 这种旧名字**不能留**：
老存档里的 80 会被当成"80 倍板面色"，判据永远不成立。

改名的收益是**旧配置暴露出来**，而不是被悄悄误解。

## 一条检查清单
写完相对判据，问：
1. 右端的 k 从哪来？**是当前这张图量出来的，还是某个常量？**
2. 这个估计量对乘 k **等变**吗？
3. 每个系数都有覆盖入口吗（能扫敏感性）？
4. 参数改名了吗（旧名字会不会被误解成新语义）？
