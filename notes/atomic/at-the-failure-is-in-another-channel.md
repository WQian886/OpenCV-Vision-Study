# 失败记在一个通道，判据去另一个通道找 —— 于是失败等于没发生

## 一句话

> **信息**存在，但**判据读的是另一个地方**。
> 于是「报错了」和「没人看见」同时成立 —— 而系统认为没报错。

## 现象（W7，2026-10-25）

W7 的引擎里，一步失败时是这样记的：

```cpp
// run_engine.h
if (!ok) {
    info.failed = true;
    info.error  = err;                    // ← 失败原因写在这里
    frame.outputs[step] = QJsonObject();   // ← 输出被**置空**
    ...
}
```

而判「这一步算不算坏」的判据，两边都是同一句：

```cpp
if (info.output.contains(QStringLiteral("error"))) ++frameErrors;
```

**判据读的是 `output`，而失败写在 `error` 里。**

于是算子返回 `false`（压根没跑成）时：

- `info.output` 是空对象 → `contains("error")` 是 false → **数不到**
- 这一步被吞掉，链继续往下跑
- 下游拿到**空的上游输出**，再用自己的默认值兜底
- 数字看着正常，判定节点照样说 PASS

## 两种坏法，判据只认一种

| | 算子怎么表现 | 输出 | 失败原因在哪 | 以前数得到吗 |
|---|---|---|---|---|
| 形状 1 | 返回 `true`，但输出里带 `error` 键 | **有内容**，明明白白写着 error | 输出里 | ✅ 数得到 |
| 形状 2 | 返回 `false`（压根没跑成） | **空的** | `info.error` | ❌ **数不到** |

**形状 2 才是危险的那个** —— 形状 1 至少在输出里**写着** error，
任何人翻一下输出都能看见。形状 2 里，失败**只存在于一个没人读的字段**。

## 后果链条（实测复现）

```
src 算子返回 false
  → 这一步被吞
  → 链继续往下跑
  → judge 拿到**空的上游输出** → 自己的默认值兜底 → 数字正常
  → judge 说 PASS
  → 那一帧算 PASS → 整批结论 PASS → 退出码 0
  → CI 说「过了」
```

整条链上**没有一个红点**：

- GUI 那边只有一行 `❌` 日志，对判定毫无影响
- headless 那边 `errorCount` 是 **0**

而用户存的那条流水线**压根没跑成**。

## 为什么以前没人发现

因为**用例只断言了一半**：

> 「那一步失败被报出来了」（`sawFailed == true`）✅ 有断言
> 「那一步失败**影响了判定**」 ❌ **没有断言**

第一条成立不等于第二条成立 —— 而第二条才是产线看的那一条。
这就是「测了不等于测全」的又一个实例：**门在那儿，只有半扇门**。

## 修法

### 1. 判据要覆盖**全部**坏法

```cpp
inline bool isBadStep(bool failed, const QJsonObject& output) {
    if (failed) return true;                          // 压根没跑成
    return output.contains(QStringLiteral("error"));   // 跑成了但报了错
}
```

⚠ 注意判据住在**能同时看见两个通道**的地方。
如果判据住在只看得到 `output` 的那一层，它就永远数不到形状 2。

### 2. 判据**和采集**都要收成一份

只抽「分类」不抽「采集」等于没抽 —— 采集也是一份规则，
两份一模一样的规则就是两份会各自漂的规则。

### 3. 改口径前先量风险面

这条判据改的是**口径**，会改变行为。所以先数一遍：

> 17 个算子里只有 3 个会 `return false`
> （读不到配方 / 没装 ONNX Runtime / 连不上相机），
> **全是真失败，没有一处是正常路径** ——
> 所以补上这条判据**不会改变任何正常流水线的行为**。

量完再改，才知道自己在改什么。

## 通用教训

### 「没报错」和「报错了」之间还有第三种状态

```
没报错        —— 什么都不知道
报错了        —— 有人看见了
报错了但没人看见  ← 最贵的一种，它看起来像第一种
```

第三种在日志和判据**分开**的系统里特别常见：
日志读 `error` 字段，判据读 `output` 字段，
两者本来就不是一回事。

### 判据和事实必须在**同一个地方**

写判据时问一句：
**「事实住在这个字段里吗？」**
如果事实住在 A 字段、判据读 B 字段，那么 B 字段为空的时候，
判据就等于不存在 —— 而「为空」在失败时**恰恰是最常见的状态**。

### 枚举「一件事有几种坏法」

盯着最常见的那种坏法写判据，剩下的就都是洞。
列一遍：
- 跑成了但报了错
- 压根没跑成
- 被跳过了
- 结果是空的

四种各有各的表现，判据要**四种都认**。

## 检查清单

- [ ] 这件事有几种坏法？判据认全了吗？
- [ ] 事实存在哪个字段？判据读的是**同一个**字段吗？
- [ ] 失败时那个字段是空的还是有值？**空的时候判据还在吗？**
- [ ] 断言的是「被报出来了」还是「**影响了判定**」？后者才管用
- [ ] 改判据之前，量过「有多少条正常路径会受影响」吗？
