# 「字段存在」≠「字段活过了中间那一跳」

## 现象
一个字段从头到尾都在，可它**从没被真正传过去**。

```
配方 JSON  ──→  核心 struct  ──→  中间 JSON  ──→  Qt struct  ──→  核心 struct
   有            有              **没有**          有              空
```

实测症状是**反的**，一度把人带偏：

- 该判废的图 → PASS（漏检）
- 好板 → 报了一堆本不该有的缺陷

第一反应是"判据把左右搞反了"，差点去改判据。
真因是中间那一跳**根本没带这个字段**，于是整条规则**静悄悄变成"没查"**。

## 为什么这么难查
链路每一段单独看都对：

| 段 | 状态 |
|---|---|
| 配方里有这个字段 | ✅ |
| 核心的 struct 里有 | ✅ |
| 生成器登记了 | ✅ |
| 中间 JSON 里**有**这个字段 | ❌ **就是这里** |
| 消费端**读**这个字段 | ✅（但读到的是空）|

而且**编译器不会报错**：字段是 `std::string`，空串是合法值。
"没传"和"值是空的"在类型上分不出来。

## 最狠的一招：只有一边能看见
变异验证时把这个字段的传递断掉，然后**两边分别跑测试**：

| 端 | 结果 |
|---|---|
| W6（直接调核心，不过 JSON）| **全绿** —— 这条路径根本不经过那个边界 |
| W7（过 JSON 边界）| 红 13 条 |

也就是说：**如果只有 W6 有测试，这个洞会一直躺着。**
每一端的测试只能看见**自己那条路径**上的失效。

## 修法
1. 上下游**都要**显式搬运这个字段（写出来，别指望"对象自己带过去"）
2. 缺字段时**降级成显式的"没查"**，并让 skipped 报出来 —— 不许悄悄变 PASS
3. 端到端测试**必须穿过那条边界**（W7 侧要有一份 W6 没有的用例）

## 检查清单
- [ ] 这个字段是不是只在一个 struct 里存在，没进过中间格式？
- [ ] 中间格式是 JSON 的话，**两端有没有各写一遍搬运代码**？
- [ ] 漏掉它的时候，行为是"显式没查"还是"悄悄当正常"？
- [ ] 有一条路径**绕过**了那个边界吗？绕过去的那端，测试覆盖到了吗？
- [ ] 有没有哪端的测试**根本不过**那个边界？（那样它对这条链路是瞎的）

## 推论
「字段加上了」和「字段被用上了」之间，隔着**任意多个中间格式**。
加字段的时候要顺着链路走一遍，
**每经过一个边界就问一次：这里谁负责搬它？**
