# 一个退出码说不出「哪里坏了」—— 工具坏了和流水线坏了必须分开

## 一句话
> **「非零」是一个**结论**，不是**信息**。CI 拿到一个非零码，
> 分不清该修工具还是修流水线 —— 而分不清就等于没人修。**

## 现象

给 W7 加 headless 模式（`w7_vm_lite.exe --run pipeline.json`）。
最先想的是「失败就返回非零」。

但"非零"同时盖住了三件**要修的东西完全不同**的事：

| 实际情况 | 该修谁 |
|---|---|
| 参数写错 / 文件读不了 / JSON 坏了 / 流水线有环 | **工具**（或者用法） |
| 跑起来了，但某个算子输出里带 `error` | **流水线**（工具是好的） |
| 跑起来了，判定是 FAIL | **流水线**（它说没通过，工具是好的） |

## 更贵的那个：退出码 0 的两种含义

最贵的情况不是"非零太粗"，是**0 有两种意思**。

算子"跑成功了"，只是输出里带了个 `error`：

```cpp
// 算子返回 true（没崩），但输出里带 error
o["error"] = "读不到配方文件";
```

引擎看的是**有没有崩** —— 于是当成功记下了。
对用户来说那是**没算成**。

窗口那边早就把这种状态点标成橙色了，headless 也得算成错误。
不然就是：退出码 0 → CI 当它过了 → 结论是错的。

> 这就是本项目那条老原则的又一次出现：
> **静默失效给你一个看起来完全正常的结果。**

还有第二个 0 的陷阱：**退出码 0 只说明"跑完了"，不说明"判定了"**。
一条什么都不判定的流水线也能跑得很漂亮、退出码 0。
所以 CI 断言的必须是**结果 JSON 里的 `final_result`**，
不是退出码 —— 这和 W5 的冒烟检查栽过的坑一模一样
（见 `notes/notes_CI_2026-10.md`）。

## 约定

```
0  跑完了，没有步骤报错，判定是 PASS（或者这条流水线本来就不做判定）
1  跑完了，没有步骤报错，但判定是 FAIL
2  用法错 / 文件读不了 / JSON 坏了 / 流水线根本跑不了（有环等等）
3  跑完了，但有步骤报错（某个算子跑了却在输出里带 error）
```

四种必须分开，因为它们说的是四件不同的事：

```
2 = 我们没跑起来     —— 工具坏了
3 = 跑起来了，但流水线里有步骤报错 —— 工具能用，流水线坏了
1 = 跑起来了，判定 FAIL —— 工具能用，流水线说没通过
```

### 3 优先于 1

有步骤报错时，那个 FAIL 往往只是它的**后果** ——
先修上游的 error，FAIL 可能自己就没了。
先判 3，报告才有指向性。

## 怎么证明这个约定不是摆设

约定写在注释里不算数。两条路都要堵：

### 1. 真实二进制上验（变异 M82~M84）

```
M82  判定 FAIL 的流水线退出 0     → 杀（bad board: 1 -> 0）
M83  有步骤报错却退出 0           → 杀（image missing: 3 -> 0）
M84  流水线文件读不了却退出 0     → 杀（pipe missing: 2 -> 0）
```

这三个变异只能靠**真二进制**验 ——
单元测试够不到 `headless_cli.cpp`（它要真算子）。

### 2. CI 里把四个码都断言一遍

`tools/ci.ps1` 的 Step 5/6 现在会跑四次真实二进制：

```
好板      -> 0
坏板      -> 1   （判定 FAIL 绝不能是 0）
图不存在  -> 3   （工具能用，流水线坏了）
文件不存在-> 2   （我们没跑起来）
```

> ⚠ 之前 CI 只断言了**退出码 0** 那条路。
> 退出码 1/2/3 **一条都没验过** ——
> 也就是说，把 FAIL 改成 0，CI 当时是全绿的。
> 这是"测了不等于测全"的又一个实例：门禁有，但门只有一扇。

## 通用教训

### 1. 退出码是**给调用方的信息**，不是"成功/失败"标志

如果你打算让 CI 或脚本读它，它就是一份**接口**。
一份接口只有一个"失败"值，等于没有接口。

### 2. 合成一个码的代价是"没人修"

CI 红了 → 没人知道红在哪 → 没人修 → CI 继续红 →
于是大家开始习惯红 → 门禁失效。

**分不清 = 没人修**，而没人修的门禁等于没有门禁。

### 3. 判据要落在"用户关心的事"上

引擎关心的是"有没有崩"；
用户和 CI 关心的是"**有没有算成**"。

这两件事不一样，而**只有后者**能当退出码的依据。
