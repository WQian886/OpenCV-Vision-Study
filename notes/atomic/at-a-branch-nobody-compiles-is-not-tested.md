# 没人编译过的那一半，不算存在过

## 一句话
> **`#ifdef` 的另一半不是「少测了」—— 它连「能不能编过」都不知道。**

## 现象

W7 的 `dl_infer` 算子有两半：

```cpp
#ifdef  HAS_ONNXRUNTIME
    ... 真的推理 ...
#else
    ... "SDK 没装" 的空实现 ...
#endif
```

本机没装 ONNX Runtime，所以 CMake 走 `#else` 那半。
于是 `#ifdef` 那半 —— **约 150 行** —— 从来没有被编译过一次。

一开始这看着像「环境限制，测不了」。直到真的把它编起来，
才发现那半边里有**三个 bug**（见下面「它抓到了什么」）。

## 关键：没编译 ≠ 没 bug

一般人说「这段代码没测过」，意思是「它可能有 bug，但没被发现」。

**没被编译过**是更狠的一档：

| | 没被测过 | 没被编译过 |
|---|---|---|
| 语法错 / 类型错 | 不可能 | **可能** |
| 链接错 | 不可能 | **可能** |
| 逻辑错 | 可能 | 可能 |
| API 用法错 | 可能 | **很可能**（没人对着真头文件编过） |

最后一行是重点：那段代码是照着 ONNX Runtime 的**文档**写的，
从来没和**真头文件**对过账。
所以它可能**装上 SDK 都编不过** —— 而本机装不上，
这件事就永远不会被发现。

> 这也是「静默失效」的一个新变体：
> **一段永远不参与编译的代码，等于一段不存在的代码。**
> 它不报错、不崩溃，只是「这个功能好像没实现」。

## 它抓到了什么

把假的 ONNX Runtime 顶上之后，那半边第一次被编译、第一次被跑，
当场抓到三个 bug：

1. **张量形状是 NCHW，喂进去的却是 HWC 数据** ——
   通道被打散，模型看到的是「红红红绿绿绿蓝蓝蓝」三张图。
   后果：不报错、不崩溃，只是**一个框都出不来**。
2. **输入名的指针悬空** ——
   `session.GetInputNameAllocated(0, ...).get()`，临时对象当场就死。
   真 SDK 上是 use-after-free。
3. **模型输出的维度没检查** ——
   输出不是 3 维时直接读 `oshape[1]`/`oshape[2]`，越界访问，崩。

三个都在**从没跑过**的那半边。

## 修法：给它造个环境

不是「改代码绕过 SDK」（那等于这段代码永远只能靠真环境验证），
而是**造一套假 SDK**：

```
third_party/fake_onnxruntime/include/onnxruntime_cxx_api.h
```

只实现 `dl_infer` 实际用到的那 8 个 API，零 OpenCV 零 Qt。
然后**单独建一个测试目标**（`w7_dl_infer_test`），
把 `dl_infer.cpp` **带着** `HAS_ONNXRUNTIME` 再编一遍。

> ⚠ 关键：这是**另一个目标**、**另一个目标文件**。
> 同一个可执行文件里不能有两个 `DlInfer::run` —— 那是 ODR 违规，
> 链接器会挑一个（而且挑哪个还不一定）。
>
> 而且绝不能顺手把 `HAS_ONNXRUNTIME` 加到 `w7_vm_lite` 上 ——
> 那等于把**假 SDK 塞进发货的二进制**里。假 SDK 只活在测试目标里。

## 另一半也不能不管

`#else` 那半是**实际发货**的那一半（绝大多数人和所有 CI runner
都没装 ONNX Runtime），它以前也一行没测过。

所以是两个**独立的目标**，各有一套断言：

| 目标 | 测哪半 | 断言数 |
|---|---|---|
| `w7_dl_infer_test` | `#ifdef`（推理） | 44 |
| `w7_dl_infer_nosdk_test` | `#else`（没装 SDK） | 10 |

**两个测试文件里都加了编译期守卫**：

```cpp
#ifndef W7_ONNXRUNTIME_FAKE
#error "这个套件必须在 HAS_ONNXRUNTIME + 假 SDK 下编译"
#endif
```

为什么要有这个：万一哪天 CMake 改坏了（忘了定义 `HAS_ONNXRUNTIME`），
这个套件会**测到空实现** —— 而空实现里根本没有推理。
断言会「莫名其妙地全红」，或者更糟：**某些断言恒真**。

> 宁可编译不过，也不要测错东西。

## 教训

### 1. 「跑不了」是结论，不是理由 —— 但更常见的是「没人给它造环境」

见 `notes/atomic/at-cannot-be-tested-is-a-conclusion-not-a-reason.md`。
这次不是「没法测」，是**没人想过要造个环境**。

先问一句：**这段代码需要什么才能跑？** 很多时候答案不是「真 SDK」，
而是「一个满足那几个 API 的东西」。

### 2. 条件编译的每一半都要有测试

`#ifdef` / `#else` 是**两份代码**，不是一份代码的两种配置。
一半有人测、另一半没人测，就等于**一半的代码不存在**。

### 3. 「不崩」不等于「没问题」

那三个 bug 里有**两个是不崩的**（通道打散、悬空指针）。
它们只会表现为「结果不对」，而结果不对是**最难查**的那一类。

## 检查清单

- [ ] 仓库里有几处条件编译？每一处**两个分支**都有测试吗？
- [ ] 有没有哪段代码，在本机的构建配置下**根本不参与编译**？
    （用 `#ifdef` 的次数对一下：每个宏的两个取值都编过吗？）
- [ ] 「这个功能跑不了」—— 需要的是**真环境**，还是**一个够用的替身**？
- [ ] 假的东西在**该严的地方**严不严？（见
    `notes/atomic/at-get-on-a-temporary-is-a-dangling-pointer.md`）
