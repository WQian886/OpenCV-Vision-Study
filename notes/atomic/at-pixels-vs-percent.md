# 像素阈值 vs 百分比阈值：换分辨率就整片失效

## 核心
**凡是"面积/距离/长度"类阈值，写成像素数就一定会在换设备时失效。**

实测（只改分辨率，**不改亮度**）：

```
绝对 min_area=80px：  0.5x→6  0.75x→9  1.0x→14  1.25x→18  1.5x→18  2.0x→18
占全图 0.05%（相对）： 7      10     10     11
```

同一块板被切成 6 个或 18 个"元件"。
**旧相机 6 个，新相机 18 个** —— 而两个都是"对的"，因为阈值没变。

## 为什么这类 bug 特别难发现
它**不会报错**，也不会在小分辨率上出错。
只有换到更高分辨率的相机/工位才暴露，而那通常在现场。

## 该用百分比还是相对量

### 面积类 → 占全图面积百分比
```cpp
const int minArea = static_cast<int>(
    std::lround(minAreaPct / 100.0 * img.cols * img.rows));
```

### 距离/聚类半径 → 跟着物体的**特征尺寸**，不是跟着图像尺寸
本项目的聚类半径改成"元件本体最大尺寸的一半"：

```cpp
const double mergeDist = std::max(1.0,
    0.5 * std::max(maxBodyW * img.cols / (double)kRefW,
                    maxBodyH * img.rows / (double)kRefH));
```

为什么不是"占图像宽度百分之几"？
因为聚类的物理意义是"同一元件的焊盘间距"，
它该跟**元件**缩放，不是跟**图像**缩放。元件和图像的比例本身可能是变量。

### 归一化坐标/ROI → 按标定分辨率归一化
SITES 里的参考坐标统一乘 `(imgW/kRefW, imgH/kRefH)`。

实测收益：图缩到 500×350 时，改之前 R2 的 ROI 整个掉到板外 →
元件被 `continue` 跳过 → 6 个元件只剩 2 个 → **判定照样输出 PASS**。
一条日志都没有。归一化之后 ROI 跟着缩放，不再掉出板外。

## 形态学核同理
固定 3×3 在 2× 图上等于噪点比原来大一倍，0.5× 上又小一倍。

```cpp
inline cv::Mat opened(const cv::Mat& mask, double scale = 1.0) {
    int n = std::max(1, static_cast<int>(std::lround(3.0 * scale)));
    if (n % 2 == 0) ++n;      // 必须是奇数,才有中心
    ...
}
```

## 怎么找出项目里所有该改的阈值
搜这几类字面量：
- 面积：`*_area`, `min_area`, `pad_drop`, `> 50`, `>= 80`
- 距离：`merge`, `bridge`, `shift_x`, `*_dist`
- 长度：`*_thresh` 后接尺寸类语义

然后逐个问：**它跟图像尺寸的关系是什么？**

## ⚠️ 改名要一起做
`min_area` → `min_area_pct`、`gold_px` → `gold_pct`。

沿用旧名字的话，老存档里的 80 会被当成"80% 全图"，
判据永远不成立或永远成立 —— **配置看着对、结果全错**。

> 读不到新名字就退回默认，宁可用默认
> 也不能让人以为是自己配的数在起作用。
