# 两个证人必须问同一个问题 —— 但它们**不能**互相抄

## 一句话
> **这个仓库里有一处，「有两份」是对的 —— 前提是那两份是「两个证人」，不是「一份定义 + 一份拷贝」。**
> **判错的后果不是「多了一份」，是「其中一份开始问另一个证人自己觉得对不对」。**

## 现象

2026-10-30，给 W5 补测试时碰到的。

「PCB 序列号长什么样」这件事，在仓库里有**两个地方**写着：

| 地方 | 是什么 |
|---|---|
| `W5_OCR_QRCode/present_pipeline.h` 的 `kSerialPattern` | **产品**这一边：W5 用它认解出来的号对不对 |
| `tools/check-ci-steps.ps1` 第 4 步的正则 | **CI 门禁**这一边：它在程序**输出**里搜「有没有一个像样的流水号」 |

两边的字面量是同一个东西：

```
PCB-\d{4}-\d{3}-SN:[A-Z0-9]+
```

## 本仓库的默认教法，在这一处是**错的**

这个仓库对「抄副本」的态度很硬：同一件事写两遍，两份慢慢漂开，
⇒ 收成**一份**。前面每一轮都是这么收的
（`pcb_sim.h` 收成一份、`operator_defaults.h` 收成一份、
判定口径收成一份……）。

如果把这一处也照这个教法收 —— **让门禁去读产品那份 pattern** ——
那就**把证据弄没了**：

- 门禁会问产品：「这个号对不对？」
- 产品说「对」。
- 门禁说「OK」。

⇒ **尺子给自己打分。**
这正是 `at-the-assertion-measures-the-library-not-you.md` 那张卡说的病：
**量的是库，不是你** —— 这里更糟，量的**就是它自己**。

⇒ 所以这一处的两份**必须留着**。

## 那怎么防止它们漂

两份文字都会漂。所以要有**第三条**：一条**逐字**比较两者的断言。

本仓库的做法（`tools/check-doc-numbers.ps1` 那套思路的同款）：
**期望值不许抄，要读。** 这里是反过来 —— **两份都要是原件**，
所以断言比的是「这两份原件是不是同一串字符」，
而不是「这一份对不对」。

## 第二半：字符一样，**还不够**

字符一模一样，两边**问的也可能不是同一个问题**。

| | 门禁（PowerShell） | 产品（C++） |
|---|---|---|
| 怎么用 | `-match 'PCB-\d{4}-...'` | `std::regex_search(payload, m, re)` |
| 是不是搜索 | **是**（整段文字里**含**一个就算） | **是** |
| 大小写 | **不区分** | `std::regex::icase`，**不区分** |

两边都是「**这一段文字里含一个流水号吗**」⇒ 同一个问题。

⚠ 如果哪天产品那边改成「**整串**必须就是这个号」
（`std::regex_match`），**字符一个字都不用改**，
但两边问的**已经不是同一个问题**了 ⇒
就会出现那种最难查的错位：

> **CI 绿着，产品说数据不对。**

⇒ 「字符一样」是**必要条件**，不是充分条件。
**充分条件是：两边问同一个问题。**

## 顺带一条：产品这一边也得**真的用**那个规则

如果产品只是把解出来的原文往上一打，
门禁那句正则就变成了「原文碰巧长得像」——
**门禁什么也没证明**。

所以 W5 的 demo 现在**先按规则认一遍**，再把认出来的号打出来：

```
  ✅ 解码: PCB-2026-001-SN:A12345X
  🔍 流水号: PCB-2026-001-SN:A12345X
```

⇒ 门禁搜到的那一行，是**规则认过的**那一个 ⇒ 两个证人真的在各自认同一件事。

## 检查清单

- [ ] 这两份是「一份定义 + 一份拷贝」，还是「**两个证人**」？
- [ ] 证人**独立**吗？—— 它有没有去问另一个证人「你觉得对不对」？
- [ ] 两边**问的是同一个问题**吗？（搜索 vs 整串 / 大小写 / 容不容忍空白）
- [ ] 它们漂了会怎样？—— 有没有一条断言**逐字**钉住？
- [ ] **反过来问一句**：这个仓库里有没有被「收成一份」**收错了**的副本？
      （收成一份 = 证据没了 —— 那是比漂移更贵的一种坏）
