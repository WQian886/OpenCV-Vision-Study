# 「报了缺陷」≠「报的是那个缺陷」

## 现象
一个用例长这样:

```cpp
check(result == "FAIL",        "废板应判 FAIL");
check(types.contains("missing"), "应检出 missing");
```

实测发现:被擦掉的那个电容**根本不再被检出**了,
但这个用例**照样绿**。

## 为什么
整张板的 verdict 是所有站点**聚合**出来的。
少了一个站点的 `missing`,还有另外 6 个站点在报 `missing` ——
**verdict 被别人撑住了**。

于是:

    真实状态:  C2 被擦掉 → 没检出   ← 缺陷漏了
    用例看到:  FAIL:missing          ← 绿

一个瞎子也能通过。

## 修法:断言要落到「具体是谁」
```cpp
check(sites.contains("power_baseline.png/C2"), "必须点名到 C2");
```

**类型不是身份**。`missing` 是类型,`C2` 是身份,
只有后者才能区分"这一个被找到了"和"总有一个被找到了"。

## 坑在期望值别想当然
补这条断言时,"C2"是**先跑探针量出来**的,不是照着真值表脑补的 ——
真值表说的是"这里有个缺陷",没说"检测器会点名它"。
脑补出来的期望值,恰好会写成检测器实际报的那个站点,断言就成了摆设。

## 推论:任何聚合量都会遮住个体失效
同型,同一个根:

| 聚合量 | 遮住了什么 |
|---|---|
| 整板 PASS/FAIL | 哪个站点失效 |
| 缺陷类型集合 | 同类型的哪个元件 |
| 站点总数 | 少了谁、多了谁 |
| 缺陷总数不增长 | 少了一个又冒出一个 |

**每一次"数量对得上"的断言,都是在放弃身份。**

## 检查清单
- [ ] 这个断言落到了**身份**(谁/哪个),还是只落到**类型/总数**
- [ ] 有没有别的站点能把这个聚合量撑住?有的话断言就是摆设
- [ ] 新加的期望值是**量出来的**还是想当然的?
- [ ] 想验证"新增能力"时,断言能不能被"退化成全报同一个"骗过?
      —— 用一个故意让所有站点都报同一缺陷的变异来验这条断言
