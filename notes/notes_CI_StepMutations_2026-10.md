# 给 CI 剩下三步配变异：W5 冒烟、W7 无头流水线、源码树干净（2026-10-29）

## 一句话
> **一道门禁如果从来没红过，就没有人知道它会不会红。**
>
> 这一轮给 **CI 自己剩下那三步**都配上了变异，
> 挂进 CI（**Step 3h**），**每次 CI 都跑**，
> 真树**一个字都不碰**。

## 现象：剩下这三步，从写下来那天起就一直是绿的

仓库里有一串门禁（`tools/ci.ps1`）：

| 步骤 | 门禁 | 管的是什么 |
|---|---|---|
| 3c / 3d / 3e | 文档的**数**、**链接**、**章节指针** | 文档说的话还对不对 |
| 3f / 3g | 上面那几道门**自己**会不会红 | 尺子坏没坏 |
| **4** | W5 冒烟 | 真的解出**一个**流水号了吗 |
| **5** | W7 无头流水线 | 整条流水线真的跑起来、真的判了 PASS 吗 |
| **6** | 源码树干净 | 测试有没有往源码树里**添**东西 |

3f 和 3g 已经证明了**文档那几道门**会红。
**第 4、5、6 步呢？从来没红过。**

为什么？因为它们**连「被问一句」都不可能** ——
这三步是**内联**在 `tools/ci.ps1` 里面的。
内联的检查**只能靠跑整个 CI** 来跑（十分钟，七个工程全编一遍），
所以「把 W5 弄坏，它会不会红」这个问题**根本没法问**。

⇒ 「CI 是绿的」只证明了**成功路径**是对的。
⇒ 一道从没红过的门禁，和一道**坏掉的**门禁，
在 CI 日志里长得**一模一样**。

⇒ 这一轮先把这三步**搬出来**，再给它们配变异。

## 这一轮做了什么

| 文件 | 干什么 |
|---|---|
| `tools/check-ci-steps.ps1` | 第 4/5/6 步搬成**一个**可调用的检查器，**每个输入都是一个命名参数** |
| `tools/mutate-ci-steps.ps1` | 三道门 × 四条变异，判定「该红的红、该绿的绿」 |
| `tools/ci.ps1` | 第 4/5/6 步改成调那个检查器；新增 **Step 3h** 跑变异脚本 |

**输入是参数，是故意的。**
一道只能看一个固定东西的检查，没法被问「要是那个东西不一样呢」。
所以可执行文件、工作目录、流水线文件、图、树的快照，
**全都变成了命名参数**。

`ci.ps1` 里原来的「树快照」本来是**一个内存里的数组**，
现在写成一个**文件**（UTF-8 无 BOM，一行一条），
因为检查器要能**在别的进程里**被调用，
而变异脚本要能**换掉**它。

## 变异的**杠杆**不一样

文档那几道门**读树** ⇒ 它们的变异**改树**。
这三道门**读输入** —— 可执行文件、工作目录、流水线文件、图、树的快照 ——
⇒ 它们的变异**改输入**。

> **同一个问题，同一个答案形状，换了一根杠杆。**

⇒ 「树」这个杠杆有个前提：**能复制一棵树**。
⇒ 「输入」这个杠杆不需要复制任何东西 ——
它改的是**可执行文件**、**工作目录**、**一个 JSON 文件**、
**一张图**，全都在**临时目录**里。

⇒ 而且它能问出**复制树问不出来**的问题：
第 6 步那条「树本来就脏」的用例，
在「改树」那套机械里**没法写** ——
因为副本永远是**另一棵树**。

## 三道门 × 四条变异

**A / B / C**：把**输入**弄坏，门禁**必须红**，
而且**必须是它该报的那条**（不是碰巧也红）。
**D**：**尺子坏了**，缺陷**还在**，门禁**必须绿**，
而且它打印的东西**必须和好树打印的一字不差**。

| 门 | A | B | C | D（尺子坏了） |
|---|---|---|---|---|
| 4 | 工作目录里**没有图** ⇒ 什么都解不出来（**退出码还是 0**） | 假的 w5：退出码 3，流水号**完美** | 假的 w5：退出码 0，流水号**形状不对** | 断掉**形状**那把刀 |
| 5 | 拿**有缺陷的板子**当好板子 ⇒ 判 FAIL | 好板子和缺陷板子**对调** ⇒ 该退 1 的退 **0** | 流水线里**裁判节点的 uuid 改了** ⇒ 查不到输出 | 断掉**退出码**和**判决**两把刀 |
| 6 | 往树里放一个**测试产物** | 树**本来就脏**（开发者自己没提交的东西） | 又脏、又漏 | 断掉**比较**那一步 |

第 4 步的 B 和 C **真程序做不出来**，
脚本**直说**，不装：
W5 找到什么都会退 0，所以没有哪个真输入能让它退 3；
真 W5 从图里解出来的**永远是对的**那个号。
⇒ 站桩（一个 `.cmd`）替身站在那儿。

第 6 步的 B 是这一轮**第一次被验证**的性质：
**一棵本来就脏的树必须绿。**
第 6 步问的是「测试有没有**添**东西」，不是「树干不干净」——
一个正在干活、还没提交的人，**不该**被 CI 弄红。
这条性质**从来没被验证过**，现在每次 CI 都验。

实测（2026-10-29，本机）：

| 门 | A | B | C | D |
|---|---|---|---|---|
| 4 | 1 条红（**形状**那把刀） | 1 条红（**退出码**那把刀） | 1 条红（**形状**那把刀） | 0 条红，输出**一字不差** |
| 5 | 1 条红（**退出码**那把刀） | 1 条红（**退出码契约**那把刀） | 2 条红（查不到输出 / 组件数不对） | 0 条红，输出**一字不差** |
| 6 | 1 条红（漏了东西） | **绿**，和好树一字不差 | 1 条红，**只报新**的那一个 | 0 条红，输出**一字不差** |

第 5 步的 A 之所以只有**退出码**那把刀响：
退出码非 0 的时候，那一步**后面的检查根本不跑**
（这和原来的行为一样：当年 `Fail` 是当场退出这一步的）。
⇒ **「红了」和「红在它该说的那句上」是两回事**，
这一轮的判据**两个都要**。

## 栽了七个跟头

每一个都差点变成**假绿**，所以每一个都写进了代码里。

### 一、**逗号的优先级比加号高** ⇒ 八个 token 变成四个

命令行本来是这么拼的：

```powershell
$a += @('-' + $k, [string]$p[$k])
```

看着是「加两个元素：一个名字，一个值」。

**不是。** 在 PowerShell 里，**逗号比加号优先**，
所以它被解析成：

```powershell
'-' + ($k, [string]$p[$k])
```

—— 一个**字符串加一个数组**，PowerShell 把数组用空格拼起来。
于是**每个参数变成了一个 token**，名字和值**焊在了一起**：

```
-BuildRoot E:\...\build\ci     <- 这是一个 token，不是两个
```

**八个 token 变成了四个。**

⇒ 那四个 token 到检查器那儿，每一个都是一个**不认识的参数**，
PowerShell **拒绝启动脚本** ⇒ 检查器**一次也没跑**。
⇒ 脚本那边看到的是「**exit 1，零条红**」。
⇒ 而「exit 1，零条红」和「检查器跑了、什么也没查到」
在日志里**长得一模一样**。

⇒ **修法**：一个 token 一个 token 地加（`$a.Add(...)` 调两次），
**并且断言命令行的形状**：token 数必须是偶数，
奇数位那个必须**像个参数名**（`^-[A-Za-z][A-Za-z0-9]*$`）。
**形状不对，当场抛错** —— 宁可脚本自己死，
也不能让一条**错的命令行**长成一次**像样的运行**。

### 二、**同一个参数给两次 = 绑定错误**

第一版的「破坏」返回的是一串**命令行参数**，
脚本把它们**追加**在默认值后面 ——
同一个参数给了两次（`-BaselineFile` 一次默认、一次覆盖）。

⇒ PowerShell 报绑定错误，**脚本没启动**。
⇒ 又一次「exit 1，零条红」。

⇒ **改法**：破坏返回的是一个**覆盖表**，
拼命令行时是**替换**默认值，不是追加。
⇒ 参数名**只出现一次**这件事，
从此是**构造出来的**，不是「小心别写错」。

### 三、**「拼起来打印」会骗人**

查上面那个 bug 的时候，打印的是：

```powershell
Write-Host ("cmd: " + ($args -join ' '))
```

打印出来**看着完全正常** —— 八 个参数，路径对，值对。

因为**四个 token 拼在一起**，中间加了空格，
和八个 token 拼在一起**长得一模一样**。

⇒ 真正能分开它们的，是**个数**：

```powershell
Write-Host ("n=" + $args.Count)
```

⇒ **教训**：打印一个集合时，
**要打印它的个数和元素的形状**，不要打印**拼起来的字符串**。
（这一条和仓库里那张
[断言的红字说的是一件事，断言做的可能是另一件事](./atomic/at-the-message-is-not-the-assertion.md)
是同一族：**说得像，不等于做的是那件事**。）

### 四、**摘要行必须只在整步都成立时才打**

检查器第一版，每个判据成立就打一行 `... : OK`。
⇒ 一条**在第一个判据上就红了的**运行，
后面三个判据照样打 `OK`。

⇒ 变异脚本是按「行尾是 `: OK`」来找摘要的 ——
于是一条**红了的**运行，被读成了**绿的**。

⇒ **改法**：每一步**只打一行摘要**，
而且**只在整步从头到尾都成立的时候**才打：

```
   STEP 4 OK: W5 decoded a serial number
   STEP 5 OK: the pipeline judged PASS, and the exit code contract held
   STEP 6 OK: the tests added nothing to the source tree
```

⇒ 这一条是**检查器自己的毛病**，
被变异脚本**逮到了** —— 这正是这一轮干的事。

### 五、`-match` **不区分大小写**

第 4 步那把「形状」刀，正则是：

```powershell
$w5text -match 'PCB-\d{4}-\d{3}-SN:[A-Z0-9]+'
```

PowerShell 的 `-match` **默认不区分大小写** ⇒
`PCB-2026-01-SN:abc` 也**能对上**（实测 True）。

⇒ **决定**：**不改**。这一步的意图是「**形状**对不对」，
不是「值和某一份副本一样」—— 值那一份由 `common/qr_ocr` 那个套件断言，
**一处**就够。
⇒ 但**这件事得记下来**：一个「检查形状」的检查，
因为正则不区分大小写，实际管得比它写的**宽一点**。

⇒ C 变异因此不用大小写去破坏（那破坏不了），
改用**数字级**的形状破坏：`PCB-2026-01-SN:A12345X`（三位流水号变两位）。

### 六、W7 是 **GUI 子系统**的程序

`& $W7Exe ...` **不等**它跑完 —— PowerShell 对 GUI 程序不等待，
实测：返回的时候**结果文件还没出现**。

⇒ 必须 `Start-Process -Wait`。
（这条在搬进检查器之前，`ci.ps1` 里就已经踩过；搬的时候**一并搬走了**。）

### 七、`$args` 是 PowerShell 的**自动变量**

脚本里有个变量叫 `$args` —— 那是 PowerShell 给
**脚本没绑定的参数**留的位置。
⇒ 改名叫 `$runArgs`。

## 这一轮跑出来的摘要（2026-10-29）

| | 摘要 |
|---|---|
| 第 4 步 | `STEP 4 OK: W5 decoded a serial number` |
| 第 5 步 | `STEP 5 OK: the pipeline judged PASS, and the exit code contract held` |
| 第 6 步 | `STEP 6 OK: the tests added nothing to the source tree` |
| 变异 | 12 条（3 道门 × 4 条），本地全绿；整轮 **24.7 秒** |

> ⚠ 上面这几条摘要里的数是**那一天**的。
> 现在该信哪个数：**跑一遍门禁**，每条摘要自己就是那个数。

**D 的验收条件**（三道门都一样）：

```
exit = 0，红 = 0，输出 == 好树的输出（逐字符）
```

⇒ 「绿」和「说得和好树一样」**一起**成立，才算数。

## 复发第五次

这一轮是
[门禁的失败路径，只有在它失败的时候才被验证](./atomic/at-a-gate-failure-path-runs-only-when-it-fails.md)
那张卡的**第五次复发**。

前四次复发的是「失败路径要有人走」；
这一轮多了**两层**：

**一、杠杆换了。**
前四轮问的都是「**树**坏了会不会红」；
这一轮问的是「**输入**坏了会不会红」。
⇒ 同一个问题，换了个**能被弄坏的东西**。

**二、这一轮逮到的不是「门禁坏了」，是「**脚本自己**坏了」。**
逗号优先级那一条，
在**没修之前**，脚本把每次运行都变成了「检查器压根没启动」，
而它**报告出来的是绿的** ——
「exit 1，零条红」被当成了「检查器没意见」。

⇒ 这和第四次复发是**同一个形状**：
一个**没人走过的分支**，和一个**坏掉的分支**，长得**一模一样**。

⇒ 而这一轮还多证了一条**别的**性质：
「树本来就脏 ⇒ 必须绿」。
这一条**从来没被验证过**，现在每次 CI 都验。

⇒ 顺带：**一张卡只写一条教训**，
这一轮的教训**没有新建卡**，
因为它和第四次复发**是同一条**（失败路径要有人走），
只是**换了一根杠杆**又复发了一次。
