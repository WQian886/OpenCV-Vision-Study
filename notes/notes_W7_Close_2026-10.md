## 2. 「收」的判据：三条硬标准

一份欠账只有**同时**满足下面三条，才算「收」：

| # | 标准 | 为什么 |
|---|---|---|
| 1 | 有**测试**钉住它 | 不是注释，不是纪律，不是「我看过代码」 |
| 2 | 有**变异**证明那条测试**抓得到** | 否则「零违规」和空断言没区别 |
| 3 | 变异脚本的结论是 `unexpected results = 0` | 「没重编」和「构建失败」都不算数 |

第 2 条是本项目反复栽过的坑：

> **零违规不能证明规则在干活。**
> 一条永远绿的断言，和一条不存在的断言，在报告里长得一模一样。
> 所以每加一条规则，就要配一条**必须变红**的变异；
> 还要配一条**必须活下来**的变异 ——
> 一个只会说「红」的规则是**噪音发生器**，下一个人会把它关掉。

## 3. W7 现在是什么（全部实测）

### 3.1 算子：17 个

| 分类 | 算子 |
|---|---|
| 采集 | `image_source_dir`（文件夹）/ `image_source_video`（视频）/ `image_source_camera`（工业相机，需 MVS SDK） |
| 检测 | `color_segment` / `blob_count` / `count_check` / `pcb_inspect` / `pcb_defect_judge` |
| 定位 | `template_match` |
| 识别 | `qr_decode` |
| DL | `dl_infer`（需 ONNX Runtime） |
| 测量 | `line_fit` / `circle_fit` / `caliper_dist` / `point_point_dist` / `point_line_dist` / `angle` |

> ⚠ **「本地图像」不是一个算子。** VM 有四种图像源，W7 只实现了**三种**。
> 喂单张本地图像走的是**引擎的兜底输入 `image_path`**
> （headless 的 `--image` 就是它）——
> 流水线里可以喂单张图，但**算子库里没有「本地图像」这一项**。
> 以前 README 上写「4 种图像源」，那是把兜底路径算成算子了。
>
> ⚠ 同理，`dl_postprocess`（letterbox / NMS / YOLOv5-v8 解析）**不是一个算子** ——
> 它没注册进 `operator_factory.cpp`，是 `dl_infer` 用的辅助库。
> 算子数是 **17**，不是 18。

**旋钮的类型检查覆盖**：17 个算子的 `run()` **全部**在覆盖范围内 ——
15 个走 `param_read.h`（整数 / 小数 / 文本三个 helper），
`color_segment` 走 `hsv_params.h`（必填的 HSV 数组 / 金层标量），
`qr_decode` **一个旋钮都没有**（`defaultParams()` 返回空对象）——
它落在覆盖范围内，是因为它**没有可以被类型搞错的旋钮**。

> ⚠ **第 21 轮多了 4 条另一种 SURVIVE** ——
> 它们改的是**历史快照里的数**（结项那天的表、审计的旧基线），

## 5. 假 SDK 换不来的债（欠账 15 / 16）

这一节单独拎出来，因为它最容易被「片 4/片 5 收口了」这句话盖过去。

> **假 SDK 只能保证「算子的逻辑对」，
> 保证不了「算子和真 SDK 对得上」。**

假件是**照公开文档抄的**，不是抄的真头文件。
所以下面这些**只有装上真 SDK 才能验**：

**假 ONNX Runtime（欠账 15）**
- `Env::GetAllocatorInfo()` 的**返回类型在版本之间变过**（有的返回值，有的返回引用）—— 装真 SDK 时可能要加 `&`；
- `Ort::AllocatedStringPtr` 的**真实生命周期**没验过；
- `CreateTensor` 对**输入缓冲区所有权**的约定没验过。

**假 MVS SDK（欠账 16）**
- `MV_CC_DEVICE_INFO` 的 `SpecialInfo` 结构、`MV_FRAME_FRAME_INFO` 的**字段顺序**，要再对一次账；
- `MV_CC_OpenDevice` 的**默认参数**是照文档写的，真头文件里 `#ifdef __cplusplus` 那支可能不同；
- 假件的 `MV_CC_GetImageBuffer` **只吐一帧**；真 SDK 的**超时语义、帧队列、`nFrameNum` 递增**都没验过。

**但反过来不成立** —— 假件**故意比真的严**：

| 假件的做法 | 效果 |
|---|---|
| 模型不存在 → **抛异常** | 真件会接受的坏状态，假件在**同一阶段**拒绝 |
| 名字**必须对** | 真件不认的假名，假件也不认 |
| **释放即清零** | UAF 从「偶尔错」变成「**一定错**」 |
| **不提供** `MV_TRIGGER_MODE_SOFT` | 真 SDK 里根本没这个常量 → 假件在**编译期**就拒绝 |

> 所以：**假件会拒绝的，真件也会拒绝**（方向一致）；
> 假件会接受的，真件**不一定**接受（字段/枚举可能对不上）。
> 这正是欠账 15 / 16 的全部内容。

## 9. 这一轮结项本身产出的两条教训

结项不是「写个总结」。这一轮它**又抓到两个东西**。
### 9.1 「有意留下的限制」必须写清边界和重开条件

不然「有意不还」和「忘了还」分不开 —— 结项只是把一堆说不清的活儿搬进了文档。

→ `notes/atomic/at-a-limit-you-keep-needs-a-boundary.md`

### 9.2 README 上那个「能复现」的行数，其实是错的

结项要更新行数。README 上写着「121 个 C++ 文件 / **33,088 行**（口径：逐个计数，2026-10-24 实测）」，
并特别声明「旧数字这次**复现不出来** …… 于是换成一个能复现的数」。

**这一轮复现它，复现不出来** —— 而且连最接近的 ANSI 口径（33,368）也对不上。

根因：**PowerShell 5.1 的 `Get-Content` 默认按 GBK 读文件**，而源码是 UTF-8 ——
一个中文字符的第三个字节成了新的前导字节，**把行尾的 `0x0A` 当尾字节吃掉了**。

```
UTF-8:  ... 0xE4 0xB8 0xAD 0x0A ...
GBK  :  ... [一]        [前导] [尾字节 = 换行，被吞] ...
```

- 121 个文件里 **102 个**对不上，总共少算 **3,268 行**；
- **少算得最多的恰恰是中文注释最多的文件** ——
  也就是说这个指标会**奖励写得少的人**，方向完全反了；
- 真值 **36,636**，三个独立方法互相印证。

→ `notes/atomic/at-the-decoder-eats-the-newline.md`

> **口径要写到「拿别人的命令能跑出同一个数」为止。**
> 「逐个计数」不是口径，是**过程描述**。

### 9.4 结项之后还的第二笔：又抓到两件事

还欠账 18 的运行期形状，又抓到两件事：

1. **上一轮只抽了一半** —— 判定**分类**搬进了 `frame_verdict.h`，
   但「**哪一步算坏**」的判据两边还各写一遍
   （`if (info.output.contains("error")) ++frameErrors;`）。
   那是**刚建好的架构里的裂缝**：说「规则只有一份」，
   而规则其实还有半份在外面。
2. **那句判据只认一种坏法** —— 算子返回 `false`（压根没跑成）时，
   引擎把输出**置空**、失败原因写在 `info.error` 里，

   那一步被吞掉，链继续往下跑，下游拿空输出兜底 → 数字正常 → 判 PASS。

> 这两条的共同点：**全都不崩，全都是绿的。**

> 而且第 2 条的发现路径值得记：
> **用例 5 断言的是「失败被报出来了」，没断言「失败影响了判定」。**
> 第一条成立**不等于**第二条成立 —— 而第二条才是产线看的那一条。
>
> 修法：判据扩成「两种坏法都认」（`w7::isBadStep`），
> **采集也收成同一份**（`w7::FrameErrorCounter`）。
> 改口径之前先量了风险面：17 个算子里只有 3 个会 `return false`，
> **全是真失败** —— 所以**不改变任何正常流水线的行为**

### 9.6 结项之后还的第五笔：测试**钉住过 bug**

第五笔（解析层别丢节点）抓到的东西，比前四笔都刺眼：

1. **两个旧用例正在断言 bug** —— `test_headless_runner` 里写着
   「未知算子被跳过，**其余的照跑**」，

2. **旧格式（v1.0）的 FIFO 队列被 from / to 共用消耗** ——

第六笔（主窗口第一次进测试）抓到的最有意思的东西，是**它自己**：

> 欠账 17 一直挂着，主窗口一直不进测试目标，

> **「没法测」和「没测」是两回事。**

> 第六轮（面板置灰）已经用同一句话推翻了另一个「没法测」，
> 这一笔把**同一个借口**用在主窗口上，又推翻了一次。

推翻它的做法只有三步，但每一步都是「常识」：

| 做法 | 为什么不是显然的 |
|---|---|
| 主程序源码编成**静态库** | 直觉是「测试目标再链一遍源文件」—— 那会让整个 OpenCV 那一坨**编两遍** |

| 按名字 **invoke private slot** | 直觉是「私有方法调不到」—— 改成 private slot 就行，**行为一点没变** |

而它抓到的三个真东西：

1. **上一笔的 GUI 那一半一条断言都没有** ——

2. **第十一遍「抄副本」** —— 而且是**行为一致、消息不一致**的那一种：
   GUI 说「未注册，**跳过**」，而它**并没有跳过**
   （那一步失败了，整批判 ERROR）。用户读到「跳过」会以为后面照跑了。
3. **状态和画面对不上** —— 切走时只把指针置空，表单**留在堆栈里**：
   面板上明明是占位页，主窗口却还记着「当前显示的是那个表单」。
   **界面看着完全正常**，而内部已经错了。

根因是程序化调 `setSelected(true)` **不会取消上一个选中**

于是场景里同时有两个选中，主窗口「取第一个」→ 取到谁**不确定**。

> **「时绿时红」的第一嫌疑不是产品不稳定，是测试自己制造了状态。**
>
> 一个抖动的测试最坏的地方是：它让人**习惯**了「这个偶尔会红」，
> 于是真出问题时也被当成「又抖了」。

### 9.8 结项之后还的第七笔：把「数字对不对得上」变成机器可查的一步

欠账 11 是**流程债**，它缺的那半步是「**强制**」：
Step 3b 把断言数**打印**出来，可文档里那十几个引用它的地方，
**没有一个会因为它过期而变红**。

这一笔加了一道新门禁 `tools/check-doc-numbers.ps1`（CI 的 Step 3c）。

**关键设计：期望值从文档里**读**出来，和实测比；不在 CI 里写死。**

```
硬编码的期望值  =  第二个副本  =  下一个会漂的东西
```

而且写死的那一份更坏：改代码的人看到 CI 红了只会去改 **CI** 里的数，
因为那是他**唯一看得见**的那个数 ——
**门禁把矛头指向了错误的方向**。

这一笔当场逮到**三处真漂移**（全是真问题，不是误报）：

1. 根 README 说 `camera` 是 **90**，实际 **93** ——
   `camera` 涨到 93 时**根 README 没跟着改**，
   而 W7 README 的套件表里写的是 93（**表对了，散文错了**）。
   这就是 `at-four-copies-of-one-number.md` 的现场版。
2. notes 体积**同一个数在根 README 里抄了两份**，其中一份从上一轮起就没更新。
3. 而且它牵出第三个问题：**量出来的数取决于怎么量** ——
   工作树直接量是 ~893 KB，**把行尾归一化成 LF 之后**（= 仓库里真正存的内容）
   是 ~891 KB，差在一个 CRLF 的文件上。
   ⇒ **字节数必须归一化之后再报**，否则换台机器 clone 一次就复现不出来。

还有一个设计上的坑：**历史快照长得和当前声明一模一样**。
结项报告里有**两张同形的表**（3.2 是结项那天的快照，3.5 是现在的数），
所以每条声明都带一个**作用域**（`After`），
只查从那个小节标题到下一个标题之间的行 ——
历史那份**既不被误报，也不被放过**。

### 9.9 结项之后还的第八笔：门禁自己**数不全**，而且**不说**

第七笔加的那道门禁（Step 3c），在 2026-10-26 早上第一次真跑的时候——

**红的。**

而且红的不是测试：26 个套件**全部通过**。
红的是 Step 3c 自己，它说「实测 18 套件 / 1804 断言」，
而文档里写的是 26 / 2371。

查下去发现：**文档是对的，实测是错的**。

那 8 个没被数到的套件，汇总行是用 `qInfo()` 打的，
而 Qt 6 在 Windows 上默认把 `qInfo` 送到**调试通道**而不是 stderr ——
ctest 看不见它们的输出。而 `set_tests_properties` 里那份
`QT_FORCE_STDERR_LOGGING=1` 的名单是**人手写的 16 个名字**，
2026-10-24 之后新加的那 8 个从没被加进去。

**这一笔最刺眼的地方在于**：Step 3c 红了，而它**指错了方向** ——
它让人去改**文档**里的 2371。照着改，真 bug 就被**写进文档**了，
门禁反而绿了。

（这和 `at-the-verdict-must-be-about-the-value-not-the-name.md` 是同一个病：
**报出来的不是那件事**。）

修法两条：

1. **名单用机器维护的那一份**（`${W7_TEST_SUITES}`）——
   抄出来的那份不会自己报警；
2. **计数的数不许比真值小而不说话** —— CI 现在会核对
   「ctest 跑了几个套件 vs 计数器看见几个」，
   少看见就红，并**点名是哪几个没看见**。

还有一个背景值得记：那道门禁**从落地起就一直是红的**，
只是**从来没被真正跑过** —— 仓库没有 remote（欠账 9）。
而这一轮的红**恰恰是环境造成的**（本机有没有那个环境变量），
真 runner 会用一台**没有你本机环境**的机器跑。

### 9.10 结项之后还的第九笔：**真跑一次，挖出四件「只有这台机器成立」**

欠账 9 的重开条件是「**仓库有 remote 的那一天**」。
2026-10-26 仓库建了（`WQian886/OpenCV-Vision-Study`），
workflow 在 `windows-2022` 上**真的启动并跑起来了**。

第一件事其实是**意外**：job 3 秒就死，

```
The job was not started because recent account payments have failed
or your spending limit needs to be increased.
```

私有仓库 + 账号消费上限。改成 **public** 之后才拿到免费分钟。

> **「job 没启动」和「job 跑失败了」在 UI 上长得不一样，但都叫红。**
> 差点把它当成「代码有问题」—— 那是**朝着错误的方向查**。

真跑起来之后，挖出**四件**东西。前三件有一个共同点：
**不是代码写错了，是「这句话只在某些机器上为真」。**
第 4 件**是**代码本身有歧义（拿窄串当路径），
而它**在这台机器上永远是绿的** —— 本机 ACP=936(GBK) 恰好有中文。

| # | 什么 | 为什么本地看不见 | 修法 |
|---|---|---|---|
| 1 | W1–W4 的空 `images/` **不在 git 里** ⇒ 干净克隆上 `copy_directory` 报错 ⇒ **整个 build 挂** | 本机那个空目录**一直在** | 补四个 `.gitkeep`（`.gitignore` 里**早就写着**这条约定，只是这四个漏了） |
| 2 | W7 的 exe 靠 **PATH** 找 `Qt6Core.dll`，而 runner 的 Qt **不在 PATH 上** | 本机 PATH 里**有** Qt（装的时候写进机器 PATH 的） | `tools/ci.ps1` 从**同一个** `-QtRoot` 把 `bin` 加进 PATH |
| 3 | tesseract 的 PATH 原来写在 **YAML** 里 ⇒ 本地彩排**根本没做**这件事 | 彩排跑在同一个 shell 里，而那个 shell 恰好有 | 搬进 `tools/ci.ps1`，YAML 里那份副本**删掉** |
| 4 | `path::string()` 是**严格**窄化（按 ACP），字符在 ACP 里表示不出来就**抛 1113** ⇒ 本机绿、runner 红 | 本机 ACP=936(GBK) **有**中文，转得出；runner 的 ACP=1252(Latin-1) **没有**中文 | 路径一律 `fs::path`；文本↔路径的转换收成**唯一**一处（`common/utf8_path/utf8_path.h`）；加**编译期守卫**（窄串当路径**编译不过**） |

第 4 件的机制**本机就能证成**：GBK 里**没有** emoji(U+1F600)，
拿 emoji 当路径，本机的 `path::string()` 抛**一模一样的 1113**。
⇒ **机器只决定哪个字符踩雷，规则是同一条。**
（可复现的探针：`tools/probe-acp.cpp`。）

第 1 件还牵出一个**更深的**问题 ——
W2/W3/W4 的代码在图缺失时会**自动生成**一张：

```cpp
if (img.empty()) {
    img = generatePcbLikeImage();
    cv::imwrite(imgPath, img);   // ← 目录不存在,这一步也失败
}
```

**`imwrite` 不会替你建目录。**
所以「目录不存在」不只是 build 挂 ——
**兜底路径本身也是坏的**。

### 9.11 结项之后还的第十笔：**链接断了，而链接自己不会说话**

第七笔和第十笔是**同一个形状**，只是对象换了：
第七笔漂的是**数**（没人检查的表），第十笔漂的是**链接**。

起因是一次**正确的删除**：删掉一张重复的 atomic 卡
（内容折叠进旧卡当「复发 N 次」）—— **三张别的卡还指着它**。

而**没有任何东西报过错**：

- 链接的文字还是那么好看；
- markdown 还是照常渲染；
- **CI 是绿的**。

> **链接本身一个字都没变。**
> 变的是**它指的那个文件没了**。
>
> 「表漂了」是有人改了现实没改表；
> 「链接断了」是链接写得**完全正确**，
> **它只是在说一个不再存在的东西**。
>
> ⇒ **盯着链接看是看不出来的，只能跟着走一遍。**

CI 因此新增 **Step 3d**（`tools/check-links.ps1`）：文档里**每一个相对链接**
都要**真的能走到**。它当场逮到**另一个**早就坏在那儿的链接
（`W7_VisionMasterLite/README.md` 里路径多了一层目录）。

⚠ 而**检查器自己第一版跑出来是红的** —— 那个红来自**它自己**：
它没跳过**行内代码**，而且把 `qsizetype i` 切成了 `qsizetype`
（markdown 的**裸目标不能带空格**）。

> **「检查器报错了」的第一反应应该是「检查器错了」**，不是「文档错了」——
> 否则就会把一段**正确的 C++ 代码**改成能骗过检查器的样子。

⇒ 详见 [atomic/at-a-link-does-not-know-its-target-is-gone.md](./atomic/at-a-link-does-not-know-its-target-is-gone.md)。

### 四条教训
1. **「本机能过」和「仓库能过」是两个问题。**
   而**只有干净克隆**才问第二个问题。
   ⇒ 「本地过了」这句话**永远只覆盖第一个**。
   要覆盖第二个，除了推上去，还可以**在本机 clone 一份再说** ——
   本笔用的就是这第二条：**便宜、快，而且能定位到具体那一步**。

2. **git 只带文件，不带目录。**
   凡是构建步骤**读**某个目录，
   那个目录要么**有文件**，要么**有 `.gitkeep`**。
   第三种状态（「本机有、仓库没有」）**在构建里就是一颗雷**。

3. **运行期按名字找 DLL，是这台机器的事实。**
   构建期用**绝对路径**，运行期用**名字搜索** ——
   ⇒ **链接成功 ≠ exe 跑得起来**。
   凡是运行期要找的东西，
   那个目录要么**在 PATH 上**（由拿到路径的那份脚本加进去），
   要么**被拷到 exe 旁边**。

4. **「机器事实」改不动，但它的「规则」可以在本机证成。**
   ACP 是机器事实（`_setmbcp(1252)` 试过了，进程里改不动），
   但「字符在 ACP 里表示不出来就抛」这条**规则**能证成 ——
   换一个本机 ACP 也没有的字符（emoji），本机就抛出**同一条消息**。
   ⇒ **「本机复现不了」不等于「查不清」。换触发条件，规则就现形。**
   ⇒ 而「这句话只在某些机器上为真」的代码，
   本机的绿**永远不算数** —— 只能去那台机器上问。

> ⚠ 顺带记一个**探针自己栽的坑**，因为它比上面三条更值得记：
> 本机复现用的探针第一版调的是**裸 `cmake`**，
> 而 `cmake` **不在那个子进程的 PATH 上** ——
> 命令**压根没跑**，而 `$LASTEXITCODE` 停在 0，
> 探针于是报了一句 **"build OK"**。
>
> **一个没有真的跑东西的探针，报绿比没有探针更坏。**
> 修法两条：先把工具**找出来**（找不到 = 硬失败），
> 再**验产物在不在**（exe 没生成 = 失败，不看退出码）。

详见 [notes_CI_FirstRunnerRun_2026-10.md](./notes_CI_FirstRunnerRun_2026-10.md)。

### 9.12 结项之后还的第十一笔：**章节指针断了，而它连「断了」都不像**

第七笔漂的是**数**，第十笔漂的是**链接**，第十一笔漂的是**位置**。

文档里大量写着这种话：

```
详见 notes/notes_W7_Knob_Audit_2026-10.md 第十节
```

它是**关于位置**的主张 —— 和链接是**不同的形状**：

| | 链接 | 章节指针 |
|---|---|---|
| 主张的是 | 一个**文件** | 一个**位置**（某文件的第 N 章） |
| 现实怎么变 | 文件被删 / 改名 | 那一章**被重新编号** |
| 指针本身 | **一个字都没变** | **一个字都没变** |
| 怎么发现 | 跟着走一遍 | **也得跟着走一遍** —— 但要走「章」这一层 |

第三行是全部的麻烦：
**两种情况下指针都没变。**
链接坏了，人至少还能想起来「那个文件好像没了」；
而「第 10 节」这句话在改编号之后**依然读得通** ——
只不过它现在指的是**另一节**。

⇒ **读是读不出来的，只能查。**

### 爆炸半径：改**一个标题**，**37 个指针**当场失效

量出来的：

```
142 个 markdown 文件 / 759 个章节标题 / 193 个章节指针
  ├─ 74 个 跨文件
  └─ 71 个 同文件
最被指着的是三个文件：
  notes/notes_W7_Knob_Audit_2026-10.md        60 个   ← 欠账台账
  notes/notes_CI_2026-10.md                   23 个
  notes/notes_PCB_Insufficient_2026-10.md      8 个
```

第一个恰恰是**每一轮都在改的那一个**（本项目唯一登记欠账的地方）。

变异：把台账里那个标题从 `## 十、` 改成 `## 十一、`（**只改这一个标题**），
在**树的副本**上跑检查器 → **37 条红**。

> 一个改动，37 处**读起来完全正常**的散文开始指错地方。

### 判据第一版是错的 —— 而且错法比漏报更坏

第一版规则「宽松」：指针在**它所在的文件**里找不到，
再去**这一行提到的文件**里找；两边都没有才算坏。

看起来很体贴 —— 毕竟一行里可能提到好几个文件。

| 规则 | 37 个断裂里逮到几个 |
|---|---|
| 宽松 | **18** |
| 严格 | **37** |

**少逮到的 19 个去哪了？**
它们**没坏** —— 它们被绑到了**读者自己那一篇的同号章节**上。

> 读者打开「欠账台账第十节」，看到的是**自己那篇的同号章节**。
> 他不知道走错了，而且**没有任何东西会告诉他**。

⇒ **一个安静指错地方的指针，比一个明显断掉的指针更贵。**
明显断掉的会被人看见；安静指错的会**被人当成对的**。

⇒ 规则收紧成：**指针只认它前面那个文件名**（顺序就是语义）。
37 个**全部**逮到。

### 代价：**23 处**散文当场被改写

规则一收紧，**8 处**原来靠「宽松」蒙混过关的散文就红了，
于是它们被**改写**成指得明确的样子（10 个指针）；
两个真 bug 修完（引文那条、绑定顺序那条），
**另外 8 处**也红了，也被改写（8 个指针）；
收尾时（4.5 那个改动）**还有 1 处** ——
**门禁逮到了它自己的说明书**：本节自己举的例子用了一个**不存在的文件名**，
而那句引文**点了名**，按规矩**就是一条主张** ⇒ **改例子，不改规矩**。

然后是**第四批**（9.13）：**又 6 处** ——
**其中 5 处是写这一轮的新文字时当场又犯的同一个错**
（记录修复的那张表把那个缺陷**又写了一遍**），
**连「记录这件事的那张表自己」都没躲过去**。

**改判据的代价，要当场付**，和第七笔同型：
期望值**从文档读**，文档写得不清楚就**改文档**，不是改检查器。

> ⚠ 而第四批还多了一层：
> **改判据的代价里，现在还包括「修法的记录本身要重新改一遍」。**
> ⇒ 而它**改起来还是同一个坑** ——
> 所以**记录也要用能挡住坑的形状**（**行内代码**，不是引号）。

### 顺带：把链接检查器**收成一份**

两个检查器需要**同样三样东西**（哪些文件在范围内、哪些行是散文、怎么按 UTF-8 读）。
**两份拷贝就是两份会各自漂的东西**（本项目栽过六遍的「抄副本」）。
⇒ 收进 `tools/lib/DocScan.ps1`，两个检查器都**点源**它。

> ⚠ 这个库**故意没有 `param` 块**：
> 点源的脚本跑在**调用者的作用域**里，
> 一个带默认值的 `param([string]$RepoRoot = "")`
> 会在点源的那一刻**把调用者的 `$RepoRoot` 重置成空串**。

CI 因此新增 **Step 3e**（`tools/check-sections.ps1`），
并照例做了**八条变异**（3 KILL / 1 RULER / 4 规则对照）。
第 D 条（**把解析结果强制成 `true`**）最要紧：
没有它，「变异都红了」只证明「检查器和变异在某个时刻表现一致」，
证明不了**是检查器在报的**。

> ⚠ 这一笔的检查器**自己也踩了三个坑**，
> 而**最要命的那个**只有**故意让它红**才看得见：
> 失败路径里有一个局部变量 `$list`，
> 和参数 `[switch]$List` **同名**（PowerShell 的变量名不区分大小写），
> 而一个带类型的参数是**带类型约束的变量** ——
> 于是往它身上赋数组会抛异常，
> **门禁在它唯一该说话的那一秒死了**。
> 而真实的那棵树是绿的 ⇒ **失败路径从来没被执行过**。
>
> ⇒ **一个门禁的失败路径，只有在它失败的时候才被验证。**
> 详见 [notes_SectionPointers_2026-10.md](./notes_SectionPointers_2026-10.md) 第 4.4 节。

⇒ 详见 [notes_SectionPointers_2026-10.md](./notes_SectionPointers_2026-10.md)、
[atomic/at-a-section-pointer-is-a-claim-about-a-place.md](./atomic/at-a-section-pointer-is-a-claim-about-a-place.md)。

### 9.13 门禁的第三个毛病：**记录修复的那张表，把那个缺陷又写了一遍**

这一笔收尾时，门禁逮到了它自己的**三个**毛病。
前两个记在 [notes_SectionPointers_2026-10.md](./notes_SectionPointers_2026-10.md) 第 4.4 节和第 4.5 节：
一个**报红的那一秒自己死了**，一个**被指错了树还是绿的**。

第三个更怪：它不是**门禁**的毛病，是**文档**的毛病 ——
而那份文档是**门禁自己的说明书**。

#### 那张表记的是**上一个修复**

[notes_SectionPointers_2026-10.md](./notes_SectionPointers_2026-10.md) 第 3.5 节
有一张表，记的是**上一批修复**（把一个假文件名换成真有的文件）。
那张表有一列叫「原来」，那一列**原样抄了修复前的那句话**：

```
「`x.md`。见第 3 节」
```

按规矩（规则 7），**引号里的指针不是主张 —— 除非引号里自己点了名**。
这一句**点了名**（`x.md`）⇒ 它**就是一条主张** ⇒ 它说的是 ``「`x.md` 有第 3 节」``
⇒ 而 `x.md` **不在这棵树里** ⇒ **那一轮门禁报的是红**：

```
notes\notes_SectionPointers_2026-10.md:298: pointer '第 3 节' is bound to 'x.md',
  which is not in this tree -- so it cannot be checked
```

> ⚠ 上面那两行是**那一轮门禁的原话输出**（**历史快照**），
> 不是现在还红着 —— 现在**绿的**。

⇒ **修复记录里的那句坏话，把那个缺陷又造了一遍。**

#### 修法：把引文写成**行内代码**，不是引号

| | 改之前 | 改之后 |
|---|---|---|
| 行内代码里的指针（跳过） | 3 | **4** |
| **查不了**的指针 | **1** | **0** |

规矩一个字没改 ⇒ **改的是记录**。

#### 而「复发」比「首次」更值得记

写这一节的时候，**新卡
[notes/atomic/at-a-fix-record-re-creates-the-defect.md](./atomic/at-a-fix-record-re-creates-the-defect.md)
自己也犯了同一个错**：它的第一稿里有**两处**把那句坏例子放进了引号
⇒ 门禁**当场报了两条红** ⇒ 同样改成**行内代码**才绿。

量的结果（当场量的，不是推的）：

| | 写新卡之前 | 新卡第一稿 | 改完之后 |
|---|---|---|---|
| 看见的指针 | 168 | 171 | 171 |
| 解析成功（跨文件） | 124（56） | 125（57） | 125（57） |
| **红** | 0 | **2** | **0** |
| 行内代码里（跳过） | 4 | 4 | **6** |

⇒ **「我只是举个例子」不是豁免的理由。**
⇒ 而这正是那张卡要记的那件事：
**门禁的说明书，本身就是被检查的文档。**
⇒ 三个毛病的共同形状：
**门禁只在「它自己出错」的时候才暴露** ——
而「它自己出错」**包括它写下的、关于它自己的话**。

⇒ 详见 [notes_SectionPointers_2026-10.md](./notes_SectionPointers_2026-10.md)、
[atomic/at-a-fix-record-re-creates-the-defect.md](./atomic/at-a-fix-record-re-creates-the-defect.md)。

### 9.14 第十一笔的尾巴：**失败路径脚本自己**先坏了

第十一笔收尾时给普查门禁加了一道**失败路径**：
CI Step 3f 每次都跑四条变异，跑在**树的副本**上
（A/B/C：引用的数漂一个 ⇒ **必须红**；D：尺子坏了 ⇒ **必须绿**）。
脚本住在仓库里（`tools/mutate-census.ps1`），**谁都能重跑**。

#### 第一次上真 runner，它自己红了

```
UNEXPECTED: mutation D should be GREEN but came out RED
MUTATION HARNESS FAILED
```

⇒ **红的不是门禁，是脚本。**

#### 那一轮日志里的两堆红

| 堆 | 条数 | 它说的是 |
|---|---|---|
| 「查不了」（目标文件不在这棵树里） | **50** | **副本不是那棵树** |
| 普查断言的红 | **5** | **尺子只坏了一把** |

（**那一轮 runner 日志的原话** —— 历史快照，不是此刻的数。）

⇒ 第一堆：每一条红里的文件路径前面都挂着一层 `C,D\` ——
而副本目录就叫 `A,B,C,D` 这个名字 ⇒ 副本的**结构**错了
⇒ 门禁量的是**另一棵树**：同文件的指针还能查（**69** 个），
跨文件的全查不了（**62** 个只剩 **12** 个）。

⇒ 第二堆：普查的数有**两种**查法 —— **块断言**和**行断言**；
D 只断了**行断言**那一处 ⇒ 块断言还在 ⇒ 还剩 **5** 条红。

⇒ 而本地跑 D 是**绿**的 —— 但那个绿**不能算数**：
副本是**原封不动**的，尺子好着坏着**都不会有红**。
⇒ **一棵没坏的树给出的绿，不是「尺子坏了」的证据，是「树没坏」的证据。**

#### 三个修法

1. **先认副本，再信它**：副本用之前先跑一遍检查器，
   它的汇总行必须和真树**一字不差**，文件集必须**逐个相等**；
   对不上就 `THE COPY IS NOT THE TREE`，**拒绝给结论**。
2. **尺子两把一起断**，而且每一处替换都**断言只替换了一处**
   （替换了 0 处 = 变异没发生 = 一个假的绿）。
3. **期望写成正面的话**：D 要「**它说通过了，而且一条红都没有**」，
   A/B/C 要「**至少一条红，而且零条「查不了」**」。

⇒ 第三个修法堵的是一个具体的洞：
原来那种「别出现 `SECTIONS OK`」的写法，**检查器崩了也满足**；
而「至少一条红」也会被**树坏了**满足 —— 那种红不是**尺子**报的。

#### 这道新门**自己被抓过一次**

把复制逻辑**故意改坏**成 runner 上那个形状（每个文件都塞进一层 `C,D\`），
再跑一次：它**拒绝给结论**，并把两边差在哪**列了出来**。

⇒ 不是「它跑过了」，是「它**在该红的时候红了**」。

#### 顺带：那张说「1:1」的表，**本来就是假的**

[notes_SectionPointers_2026-10.md](./notes_SectionPointers_2026-10.md) 8.5 那张表
列着门禁查的每一个文件和它带几条声明，并写着
「**这张表和门禁的声明是 1:1 的**」。

⇒ 量出来：**少了一行** ⇒ 行加起来 **75**，合计写着 **76**。
⇒ 而**一行没有的东西，没法被检查** ——
门禁只会检查表里有的行，所以这一行漏掉的时候**没有人会知道**。

⇒ 这一笔**没有还债**（修的是门禁本身），但它又犯了同一个形状：
**被记录的事实没有门 ⇒ 它会漂** ——
这次漂的是「那张表声称自己是 1:1」这句话本身。

⇒ 详见 [notes_SectionPointers_2026-10.md](./notes_SectionPointers_2026-10.md)、
[atomic/at-a-gate-failure-path-runs-only-when-it-fails.md](./atomic/at-a-gate-failure-path-runs-only-when-it-fails.md)。

### 9.15 第十一笔的尾巴（续）：**一个目录，两个字符串**

第二次上真 runner（失败路径脚本的**第二次**），还是**脚本**红 —— 但这一次，
**是上一轮刚加的那道门喊出来的**：

```
THE COPY IS NOT THE TREE: the copy does not hold the same files
   missing from the copy (142): notes\atomic\at-a-blind-reading-cannot-watch.md, ...
   extra in the copy (142): ine\notes\atomic\at-a-blind-reading-cannot-watch.md, ...
```

⇒ 一边干净，一边每个都多三个字符 `ine\` ——
而 `ine` 是 **`pristine` 的尾巴**（副本目录就叫这个名）。

#### 三个字符从哪来：8.3 短名

runner 上 `$env:TEMP` 是 **`C:\Users\RUNNER~1\AppData\Local\Temp`**（8.3 短名），
provider 枚举文件时给的是**展开后的** `C:\Users\runneradmin\...` ——
**同一个目录，两个字符串**，差三个字符。

⇒ 而相对路径是**拿长度切出来的**
（`$f.FullName.Substring($root.Length)`）：
切的长度来自**短名**，路径来自**长名** ⇒ 每一条相对路径从头就错了三个字符。

#### 本机造得出来

造一个 8.3 短名的目录，拿它当根跑失败路径脚本 —— 本机**红在同一句上**：

```
root string : ...\t8probe\AVERYL~1              (len 47)
Get-Item    : ...\t8probe\AVeryLongDirectoryNameToForceShortNameHere  (len 81)
Substring   : [gDirectoryNameToForceShortNameHere\f.txt]      <-- 垃圾
```

⇒ **这一轮那个红，本机也造得出来** ——
不是「runner 有 runner 的毛病」，是**同一个毛病**。

#### 修的不是脚本，是**根**

同样的切法在**四个检查器**里都有：它们拿 `Resolve-Path` 解析出来的根去切枚举出来的路径 ——
而 `Resolve-Path` **原样返回短名**，`Get-Item` 才给展开后的。

⇒ 修在**共用的那一处**：`Resolve-RepoRoot` 改成问 provider 要那个目录；
相对路径**不再切字符串** —— 基址取 provider 自己的答案，
文件不在基址底下就**喊出来**，不切。

⇒ 这个病**本来是潜伏的**：runner 的检出路径没有 8.3 成分；
它发作在**临时目录**上 —— 那才是从 `$env:TEMP` 拼出来的。

⇒ 而上一轮那道「先认副本，再信它」的门，
**在它自己的第一次真跑上就派上用场了**：
它没有给出结论，它说**副本不是那棵树**。
