# W7：解析层别丢节点（欠账 18 加载期 + 欠账 19 收口）

> 2026-10-25 · 旋钮审计结项之后的**第五笔**
> 上一篇：`notes/notes_W7_FrameProtocol_2026-10.md`（欠账 17 第三次收一半）

## 0. 一句话

「存盘里少一个算子」这件事，以前在 W7 里的后果是：

> **那个节点被丢掉 → 指向它的边端点缺失 → 边也被丢掉 → 链断成两截
> → 下游拿空输出 → 默认值兜底 → 数字看着正常 → 静默判 PASS。**

而且有**两条绿着的用例**在**断言这个 bug 是对的**。

这一轮把解析层改成**别丢节点**（留在画布上、标「未安装」、那一步失败 → 整批 ERROR），
顺带挖出**两个原本没人知道的洞**，
以及**一个错的、连着错了两轮的断言数**。

## 1. 起因：解析层**丢掉**了一个节点

`pipeline_graph.h`（2026-10-25 之前）：

```cpp
if (!def.known) {
    logFn(QString("[Load] 跳过未知算子: %1").arg(opName));
    ++skipped;
    continue;          // ← 节点没了
}
```

看着很合理：算子没装，留着也跑不了，跳过就完了。

## 2. 但丢掉一个节点，是**连锁**的

```
未知算子被跳过
  → 指向它的**边端点缺失**
  → **边也被跳过**
  → **链断成两截**
  → 下游拿**空输出**
  → 默认值兜底
  → 数字正常
  → 判 PASS
```

> **存盘里少一个算子，伤的是它后面所有算子。**

这条链上**没有一环会报错**：
不崩、不异常、退出码 0、GUI 和 CI **两边都是绿的**。

日志里确实有一行「[Load] 跳过未知算子: xxx」——
但那是**日志**，不是**画布**：
画布上那个节点**压根不在**，连线也**压根不在**。
用户看到的是一条**少了一半**的流水线，跑出来**判 PASS**。

## 3. 最毒的一层：有两条**绿着的**用例在给 bug 发通行证

`test_headless_runner.cpp` 当时写着：

```cpp
check(ok, "有未知算子 -> 其余的照跑");
check(!rec->opOrder.contains(QStringLiteral("不认识的算子")),
      "不认识的算子**没有**被跑");
```

`test_undo_redo.cpp` 当时写着：

```cpp
checkEq(cv3.nodes().size(), 2, "未知算子被跳过,只留下 2 个真节点");
```

两条都在**断言那个 bug**。

> 一条**绿着**的用例，给 bug 发了通行证。
> 「有测试」不等于「测的是对的东西」——
> 一条断言如果写的是「跳过是对的」，那它就**锁死**了跳过这件事。

这两条本轮都**重写了**（不是微调）：

| | 以前（断言 bug） | 现在（断言该有的样子） |
|---|---|---|
| headless | 「其余的照跑」 | 那一步**失败** + 整批判 **ERROR** |
| undo_redo | 「只留下 2 个真节点」 | **3 个节点**（那个没装的也在）+ 标了「未安装」 |

## 4. 收法：解析层别丢节点

`pipeline_graph.h`：

```cpp
struct GraphNode {
    ...
    bool known = true;   // false = 这个算子没装(但节点仍在图上)
};
```

```cpp
// ⚠ 认不出来的算子**也留在图上**(known=false)。
//   以前这里是 `continue` —— 节点被丢掉,于是指向它的边端点缺失,
//   边跟着被跳过,链断成两截,下游拿空输出兜底,
//   数字看着正常,判 PASS。
//   少一个算子,伤的是它**后面所有算子**。
```

三个关键动作：

| 动作 | 效果 |
|---|---|
| 节点**留在图上**，`known=false` | 画布上看得见（**画布忠实度**） |
| 它的 uuid / op 名**照样登记** | 指向它的边**接得上** → **链不断** |
| 运行时那一步**失败** | 整批判 **ERROR**，不是静默 PASS |

### 4.1 「链没断」不等于「没事」

链没断的意思**不是**「一切正常」，而是：

> **下游拿到的是「上游那一步失败了」这个事实**，
> 而不是「上游安静地什么都不产出」。

前者能被 `w7::isBadStep` 认出来（这正是欠账 18 的**运行期**那一半干的事），
后者认不出来。

### 4.2 画布上要**看得出**它没装

「节点留在画布上」还不够：
一个灰扑扑的方块，用户会当成正常节点。

于是 `OperatorNode` 加了 `setOperatorMissing(bool)`：
**灰底 + 虚线框 + 顶上写「未安装」**。

> 为什么不用「跑起来会红」代替标记：
> 用户可能**根本没跑**就存盘走了 ——
> 那时候画布上那个方块在他眼里就是个正常节点。
> 而「用户存了什么」必须**当场**看得见。

### 4.3 参数面板也不许说谎

节点现在**点得到**了 —— 于是 `mainwindow.cpp` 里那个

```cpp
if (!op) { qDebug() << "[UPN] op is null, return"; return; }
```

就变成了一条**新的谎**：面板上留着的是**上一个节点**的参数表单，
用户以为自己在看这个节点的参数，其实看的是别人的。

现在改成：切到占位页 + 写清「算子 X 未安装，跑到这一步会失败，整批判 ERROR」。

> 面板**不会说谎**是这一层的底线：宁可什么都不显示。

## 5. 顺带挖出来的**第二个洞**：旧格式的 FIFO 队列被共用

新套件的用例 3 写的是「旧格式（按 op 名 FIFO）下，没装的算子也参与配对」，
它**红了**：

```
[FAIL] 没断边(实际 1)
[FAIL] 第一条边:配到 ghost(不是别的节点)
```

查下去发现，`graphFromJson` 的旧格式配对是：

```cpp
if (opIndex.contains(fromKey) && !opIndex[fromKey].isEmpty())
    fromIdx = opIndex[fromKey].takeFirst();
if (opIndex.contains(toKey) && !opIndex[toKey].isEmpty())
    toIdx = opIndex[toKey].takeFirst();       // ← 同一份队列!
```

**from 和 to 共用一份队列。** 于是：

```
节点: src -> mid -> dst
边 1: {from:"src", to:"mid"}
边 2: {from:"mid", to:"dst"}

边 1 的 to="mid" 把队列里那个 mid **消耗掉**了
  → 边 2 的 from="mid" 找不到人 → **断**
```

> **旧格式里三节点以上的链必断。**
> 而默认流水线（四节点三连线）正好就是这种形状。

这是个**预先存在**的洞（不是本轮引入的）：
老的测试只用了**两个**节点，所以它一直没被看见。

修法：**from 和 to 各用各的队列** —— 一个节点当然可以**既是**某条边的下游、
**又是**另一条边的上游（那就是链）。

> 这也是同一个病：**链断成两截**，只是断的原因不同。

## 6. 顺带挖出来的**第三个洞**：「算子没装」被托付给了调用方

解析层知道哪些算子没装（`factoryFn` 说的）。
但**执行**的时候，那一步会不会失败，取决于**调用方给的 runner**。

而在 headless 这一层，runner 是「跑一个算子」的回调 ——
它**不知道**哪些算子装了。

真程序里两处都问 `createOperatorByName`，所以**碰巧**一致。
但那只是**碰巧**：换个调用方（比如测试里的假算子），runner 会对**任何**名字都返回成功，
于是又变回静默 PASS。

所以规则改到**解析层和执行层之间**：

```cpp
// headless_runner.cpp
QSet<QString> missingOps;
for (const GraphNode& gn : g.nodes)
    if (!gn.known) missingOps.insert(gn.op);

const EngineRunner guardedRunner = ... {
    if (missingOps.contains(opName)) {
        if (err) *err = QStringLiteral("算子 %1 未注册,这一步跑不了").arg(opName);
        return false;
    }
    return runner ? runner(...) : false;
};
```

> **解析层已经知道答案了，没理由再去猜。**

## 7. 三个死字段：改名 + 变成**可读**

欠账 19 记的是「`PipelineGraph` 的三个字段**写了没人读**」。
实测确认：生产代码里**一处都不读**，只有测试断言它们是 0
—— 那证明的是「它们一直是 0」，不是「有人在看」。

### 7.1 改名（因为**含义**变了）

| 旧名 | 新名 | 为什么 |
|---|---|---|
| `skippedNodes` | **`unknownNodes`** | 以前是「跳过了几个」（节点被**丢弃**）；现在节点**留着**，数的是「有几个算子没装」 |
| `skippedEdges` | **`brokenEdges`** | 以前混着两件事（指向未知算子的边 + 端点真不存在的边）；现在只有后者才算「断」 |
| `defaultedSides` | 不变 | 含义没变 |

> 旧名留着会**说谎** —— `skippedNodes` 现在一个节点都不跳了，
> 还叫这个名字就是骗人。
> **规则会搬家，但不许改口。**

### 7.2 变成可读（两处读者）

| 字段 | 谁读 | 读出来干什么 |
|---|---|---|
| 三个计数 | `describeLoadAnomalies`（纯层） | 告诉用户「有 N 个算子没装」 |
| 三个计数 | headless 结果 JSON（`unknown_operators` / `broken_edges` / `defaulted_sides`） | CI 能问「这批为什么是 ERROR」，而不只是得到一个结论 |

## 8. 那段人话搬进纯层（因为 **M179 存活**）

第一次写守卫时是这样：

```cpp
check(code.contains("loadedGraph.unknownNodes"),
      "mainwindow.cpp 读了 unknownNodes(不然它又是死字段)");
```

然后变异 M179 来了：**把 `.arg(loadedGraph.unknownNodes)` 换成硬编码 `.arg(0)`**。

实测：**SURVIVED**。一条没红。

因为 `loadedGraph.unknownNodes` **还出现着** —— 在那个 `if` 条件里：

```cpp
if (loadedGraph.unknownNodes > 0) {                   // ← 名字还在这里
    appendLog(tr("...").arg(loadedGraph.unknownNodes)); // ← 这里被换成 0
}
```

守卫查的是「**这个名字在不在**」，它要量的却是「**这个值有没有被用上**」。

> 又一次是**「守卫查的东西」和「守卫要量的东西」不是一回事**：
> 差一个字，差的就是「硬编码」。

### 8.1 修法不是加强 lint，是**换问法**

把那段人话从 `mainwindow.cpp` 搬进**纯层**：

```cpp
// pipeline_graph.h
inline QString describeLoadAnomalies(const PipelineGraph& g);
```

于是：

| | 以前 | 现在 |
|---|---|---|
| 那段话住在哪 | GUI 里 | **纯层** |
| 能不能直接测 | 不能（GUI 造不出来） | **能** —— 喂一张图进去，看它说没说对 |
| GUI 那侧的守卫问什么 | 「`loadedGraph.unknownNodes` 在不在」（**文本**） | 「有没有调 `w7::describeLoadAnomalies`」（**可测入口**） |
| 硬编码骗得过吗 | **骗得过**（M179） | 骗不过 —— 纯层那条断言直接看**数对不对** |

纯层那条断言：

```cpp
PipelineGraph g;
g.unknownNodes = 3;
const QString msg = describeLoadAnomalies(g);
check(msg.contains("3"), "消息里写的是 3");
check(!msg.contains("0 个算子"), "不是硬编码的 0");
```

> **只要那段逻辑能搬进纯层，就别在 GUI 里守着它** ——
> 搬进去，它就变成一条**断言**，而不是一条**文本检查**。

## 10. 数字勘误：一个**过期二进制**给出的、看着完全正常的错数

这一轮量断言数时发现：**上一笔记的数是错的**。

| 提交 | 记的 | 真值 | 差 |
|---|---|---|---|
| `33dd280` | 23 套件 / **2218** 断言 | 23 / **2230** | +12 |
| `eb5b8cd` | 24 套件 / **2251** 断言 | 24 / **2263** | +12 |

根因**不是算错了**，是**量的对象过期了**：

> 本地 build 树里 `w7_engine_test.exe` 是**旧的** ——
> 前一轮的命令只编了**几个**目标
> （`w7_pure_test w7_run_test w7_result_render_plan_test w7_headless_test w7_vm_lite w7_test_data`），
> **没编它**。于是那个 exe 停留在 10-23 的版本，比源码少 12 条断言。
>
> 而**总数看着完全正常** —— 别处的套件都是新编的，
> 差的那 12 条藏在**一个**套件里，谁也不会去核。

**它错了两轮，一次都没人发现。**

### 10.1 为什么没人发现

因为 **CI 也不数断言** —— CI 只数**套件数**（`out of (\d+)`）。
断言数一直是**人手数**的。

> 人手数 + 数的是**可能过期的树** = 这个数可以是错的，
> 而且错得**毫无痕迹**。

### 10.2 修法：让 CI 自己数，而且只从**刚建的那棵树**里数

`tools/ci.ps1` 新增 **Step 3b**：

- 再跑一次 ctest，这次带 `-V`，把每个套件的 `pass=N` 收上来；
- 断言总数**打印出来**，并写进 `build/ci/assertions.txt`；
- **不硬编码期望值** —— 硬编码的期望值就是那个会悄悄漂的数，
  正是这一步要治的病（把「打印」变成「强制」是**欠账 11**）。

> 要量的东西，**必须由刚跑完的那道工序产出**。
> 手工量的数字，有一天会过期，而它过期的时候不会告诉你。

（这条是 `notes/atomic/at-ninja-mtime-stale-binary.md` 的**第三次复发**，
前两次是「文件改了但没重新编译」，这次是「**压根没要求编译那个目标**」。）

> 而且它会**骗人**：测试里「边接上了」，可真实文件根本不是这么写的。

（这个坑在 `test_headless_runner.cpp` 的注释里已经记过一次，我**又栽了一遍**。

这一轮把**读盘异常那段话**搬进了纯层（`describeLoadAnomalies`），
于是它从「只能靠源码守卫看着」变成「**能直接测**」。

> 这是欠账 17 的标准：**能测的就搬出去**。
> 而这一笔证明了「搬」这件事本身可以是**一轮债**的副产品。

剩下的还是 **UI 接线**（点 Run 有没有反应、参数面板、拖拽连线）。

### 欠账 11（审计要跟着代码升级）—— 有了**具体实例**

这一轮发现：「靠数字对不对上来发现」这个机制，
**用的那个数自己就可能是错的**（见第 10 节）。

## 14. 这一轮的教训

### 14.1 「处理不了的东西」有两种做法

**丢掉它**，或者**留着它但说清它处理不了**。

丢掉它 = 让**下游**替它背锅，而下游**不会知道**自己背了锅
（它拿到的是空输出，不是错误）。

> 静默失效比崩溃难查。
> 而「丢掉一个节点」是**最贵的那种静默失效**：
> 它不是让**一个**节点出错，是让**一整段**链在背一个没人知道的锅。

### 14.2 一条**绿着的**用例，可以给 bug 发通行证

两条用例写的是「跳过是对的」，于是「跳过」就成了**规格**。

> 「有测试」不等于「测的是对的东西」。
> 一条断言如果写的是「bug 的行为」，它比**没有测试**更危险 ——
> 因为它还**挡着**别人去修。

### 14.3 守卫量「值有没有被用上」，就不能只查「名字在不在」

M179 存活教会的。

而修法**不是**把 lint 写得更巧，是**换问法**：
把逻辑搬进纯层，让它变成一条**断言**。

### 14.4 「数出来」不等于「数的是新的」

第 10 节那个错数。

> 要量的东西，**必须由刚跑完的那道工序产出**。
> 手工量的数字，有一天会过期，而它过期的时候不会告诉你。

### 14.5 一条**编不过**的变异，测不到任何规则

第二遍的 M184：它编不过，所以它既不是「杀」也不是「活」，
它是「**我这条变异写错了**」。

> 把这种变异标成 `Expect = BUILD-FAIL` 混过去，
> 等于**假装测过了一条规则**。
