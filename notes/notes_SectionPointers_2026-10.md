# 第十一笔：章节指针也会漂 —— 链接能查「文件没了」，查不了「章被重编号了」

> 📅 2026-10-27。结项之后还的第十一笔账。
> 上一笔（第十笔）给文档加了**链接**检查器；
> 这一笔给它加**章节指针**检查器。
> 顺带把链接检查器**收成一份**（两份同样的代码各自漂，本项目栽过六遍的「抄副本」）。

---

## 0. 一句话

> **链接是关于「文件」的主张，章节指针是关于「位置」的主张。**
>
> 链接检查器**结构上**看不见后者 ——
> 它找的是 `](...)`，而「第 N 节」里**没有** `](`。
>
> 而这一类主张的爆炸半径是：
> **改一个标题，60 个指针里的 37 个当场失效 —— 而且没有一个会自己发出声音。**

---

## 1. 上一笔解决了什么，还剩什么

第十笔（`notes_W1W2_Tests_2026-10.md` 第 6.3 节）加的 `tools/check-links.ps1`
解决的是**链接**：

> 「那个文件还在」—— 链接是一个**关于文件**的主张。

它查得很干净：109 条相对链接逐条**跟着走**，走不通就红。

**但它没管的，是另一种形状。**

文档里大量写着这种话：

```
详见 notes/notes_W7_Knob_Audit_2026-10.md 第十节
（notes_W7_Verdict_2026-10.md 的 §7.2.1 是这一轮补上的结案）
```

这是**关于位置**的主张。它和链接有两个关键区别：

| | 链接 | 章节指针 |
|---|---|---|
| 主张的是 | 一个**文件** | 一个**位置**（某文件的第 N 章） |
| 现实怎么变 | 文件被删 / 改名 | 那一章**被重新编号** |
| 指针本身 | 一个字都没变 | **一个字都没变** |
| 怎么发现 | 跟着走一遍 | **也得跟着走一遍** —— 但要走「章」这一层 |

第三行是全部的麻烦：
**两种情况下指针都没变。**
链接坏了，人至少还能想起来「那个文件好像没了」；
而「第 10 节」这句话在改编号之后**依然读得通** ——
只不过它现在指的是**另一节**。

⇒ **读是读不出来的，只能查。**

新卡：`notes/atomic/at-a-section-pointer-is-a-claim-about-a-place.md`

## 2. 量出来的：这不是一个理论问题

### 2.1 有多少指针

```
139 个 markdown 文件
743 个章节标题
190 个章节指针（看见的）
  ├─ 142 个解析成功（71 跨文件 / 71 同文件）
  ├─  40 个在引号里 —— 引文，不是主张
  ├─   8 个在行内代码里 —— 代码，不是主张
  └─   0 个查不了 —— 目标文件不在这棵树里
```

> **看见的** 和 **查过的** 是两个数，差的那 48 个**一个都没藏起来**：
> 检查器把它们**数出来、印出来**（4.1）。
>
> ⚠ **「0 个查不了」是这一笔最后才有的。**
> 它本来是 **1** —— 那是**本节自己**举的一个例子（3.3），
> 例子里的文件名 `x.md` **不存在**，而例子里那句「见第 3 节」
> 因为**引号里点了名**，按规矩**就是一条主张**。
> ⇒ 门禁**逮到了本节自己**。
> ⇒ 修法是**改例子**，不是**改规矩**：把那个例子换成**真有的文件**，
> 于是它演示的还是同一条规矩（句号会断开绑定），却不再是一句**假的主张**。
>
> ⚠ 而**第三次**逮到本节自己，逮到的还是**同一个例子**
> —— 只不过这一次它躲在**记录第三次修法的那张表**里（3.6）。
> ⇒ **「0 个查不了」这个数，是被逮了三次才守住的。**

### 2.2 它们指着哪儿

```
最被指着的是三个文件：
  notes/notes_W7_Knob_Audit_2026-10.md        60 个
  notes/notes_CI_2026-10.md                   23 个
  notes/notes_PCB_Insufficient_2026-10.md      8 个
```

第一个是**欠账台账**——本项目唯一登记欠账的地方，
而**它恰恰是每一轮都在改的那一个**。

⇒ 于是：**改一个标题，60 个指针里的 37 个当场失效。**
一个改动，37 处**读起来完全正常**的散文开始指错地方。

### 2.3 变异把它量成了确数

把台账里那个标题从 `## 十、` 改成 `## 十一、`（**只改这一个标题**），
在**树的副本**上跑检查器：

```
=== MUTATION A: knob audit chapter 10 -> 11 ===
  pointers that went RED: 36
```

**36** —— 和 2.2 算出来的一致。

## 3. 规则：指针绑到**它前面**那个文件

这是这一轮最难的部分，也是第一版**做错**的部分。

### 3.1 第一版（宽松，错的）

> 指针先在**它所在的那个文件**里找；找不到，再去**这一行提到的文件**里找；
> 两边都没有，才算坏。

看起来很体贴 —— 毕竟一行里可能提到好几个文件。

### 3.2 它错在哪

量出来：

| 规则 | 37 个断裂里逮到几个 |
|---|---|
| 宽松 | **18** |
| 严格 | **37** |

**少逮到的 19 个去哪了？**

它们**没坏** —— 它们被绑到了**读者自己那一篇的同号章节**上。

> 读者打开「欠账台账第十节」，看到的是**自己那篇的同号章节**。
> 他不知道走错了，而且**没有任何东西会告诉他**。

⇒ **一个安静指错地方的指针，比一个明显断掉的指针更贵。**
明显断掉的会被人看见；安静指错的会**被人当成对的**。

### 3.3 现在的规则

> **一个章节指针，绑到同一行里、在它**前面**的那个文件名。**
> 它必须在**那个文件**里解析。
> 前面没有文件名 ⇒ 指针说的是**它所在的那一篇**，就在那一篇里解析。

```
`notes/notes_W7_Knob_Audit_2026-10.md` 第十节
    └── 文件在前面 ⇒ 绑到台账      ✅

第 9.6 节 + `notes/atomic/at-ninja-mtime-stale-binary.md`
    └── 文件在后面 ⇒ 是「相关链接」，指针说的是当前文件  ✅
```

**顺序就是语义。**

两处细节：

- **句号会断开绑定**：`notes/notes_W7_Knob_Audit_2026-10.md` 第十节。第 3 节
  说的是**当前文件**，不是台账 —— 句号把它和前面的文件名分开了。
- **一个文件名前面没有文件名**时，指针说的是**它所在的那一篇**。

### 3.4 写完以后，**它自己**红了 —— 三个真 bug

新写的检查器**第一版是错的**，而且是**三种**错。
它们不是「差一点」：每一个都会让检查器**看不见东西**，
而一个**看不见东西**的检查器和一个**没有**的检查器，
在 CI 上长得**一模一样**（都是绿的）。

**Bug 一：绑错了文件（顺序被当成了模式）**

规则说「绑到**它前面**那个文件名」，
可代码取的是「**数组里最后一个**」。
而这个数组是**按模式**填的（反引号式 → 链接式 → 裸名式），
**不是按文字顺序**填的。

⇒ 于是一个指针会绑到**离它最远**的那个文件名上。
量出来的样子：一行里有两个文件，
前面那个带 `:行号` 后缀（**只有裸名式能认出来**），
后面那个是反引号包着的 —— 数组里最后一项是**前面**那个，
指针于是绑到了**它前面 100 行**的那个文件上。

**量出来的后果**：**21 条**红里有 **5 条**是这么错的。
修法只有一行：取**文字顺序上最近**的那个，不是数组里最后一个。

> 修完之后，同一行上的两个文件，**近的那个**说了算（4.3 的 **E** 条）。

**Bug 二：把引文当成了主张**

一条指针**写在引号里**，它说的是「**那句话**」，
不是「**那一章**」。

- `notes/notes_SectionPointers_2026-10.md` 里那张「改成了什么」的表，
  整张表都是**引文** —— 它记的是**过去**改了什么，
  不是**现在**还有那一章。
- 而它当时被当成主张去查了 ⇒ **一堆红**。

⇒ 规则加上：**引号里的指针不是主张**（除非引号里**自己**点了名）。

**但这条规则差点写成另一个样子。**
先试的是「整个文件里配对出来的引号段」——
量出来的后果是：**153 个指针里有 133 个**（87%）
被算成「在引文里」，**检查器基本被掏空了**。

⇒ 规则必须是**本行**的：
**同一行**里成对的 `「…」` 才是引文。
（还有两条实测的坑：没配上的 `「` **不许**吞掉整个文件；
引号**跨行**的时候，**不许**把中间那些行也算成引文 ——
仓库里有两篇文档的 `「` 一直没配上。）

**Bug 三：行内代码里的 `「`，被当成了引号**

引号的配对是「**先进先出**」：
一个 `」` 配**最老**那个还没配上的 `「`。
而**行内代码里的 `「` 是一个字面量** —— 渲染器把它**原样显示**。

本项目**恰好有一篇文档在解释这条规则**，
而它**必须把那个字符写在反引号里**才能说清。
⇒ 它**自己踩了这条规则**：
一个本该是「字面量」的 `「` 被当成了**开引号**，
配对从此**错位**，而且**再也没能恢复** ——
于是这一篇里**后面每一个引号**都配错了人。

量出来（`notes/notes_SectionPointers_2026-10.md` 这一篇）：

| | 配出来的引文段 | 跨行的那些 |
|---|---|---|
| 算上行内代码（**第一版**） | 77 | **53** |
| 不算行内代码（**现在**） | 76 | **0** |

那 53 个跨行的段，把本篇里**本来引得很好的**指针
判成了「在引文里」 ⇒ **8 条假红**。

全树：跨行的引文段 **81 → 28**。

⇒ 修法只有一行：**行内代码里的引号不算引号**
（`tools/lib/DocScan.ps1`）。

**代价**：**4 处散文**当场被改写（见 3.5 的表，和本节后面的说明）。

### 3.6 第四批：**记录第三批的那张表，把第三批的缺陷又写了一遍**

第三批的修法是「**改例子**」——
把 3.3 那个例子里的假文件名换成**真有的**文件。

可是**记下这个修法的那张表**，有一列叫「原来」，
那一列**原样抄了修复前的那句话**：

```
「`x.md`。见第 3 节」
```

按规则 7，**引号里的指针不是主张 —— 除非引号里自己点了名**。
这一句**点了名** ⇒ 它**就是一条主张** ⇒ 它说的是 ``「`x.md` 有第 3 节」``
⇒ 而 `x.md` **不在这棵树里** ⇒ **那一轮门禁报的是红**：

```
notes\notes_SectionPointers_2026-10.md:298: pointer '第 3 节' is bound to 'x.md',
  which is not in this tree -- so it cannot be checked
```

> ⚠ 上面那两行是**那一轮门禁的原话输出**（**历史快照**），
> 不是现在还红着 —— 现在**绿的**。

⇒ **修复记录里的那句坏话，把那个缺陷又造了一遍。**

**修法：把引文写成**行内代码**，不是引号。**

```
原来那一句是 ``「`x.md`。见第 3 节」``
```

代码是**字面量**，渲染器原样显示 ⇒ **不是主张**。
⇒ 规矩一个字没改，改的是**记录**。

## 4. 检查器：tools/check-sections.ps1（CI 的 Step 3e）

它做的事，和链接检查器同型，但对象是**位置**：

- 遍历仓库里**所有** `.md`（工作区，不是 git index）；
- 跳过**围起来的代码块**（C++ 行不是指针）；
- **三种记法都认**：`第 4 节` / `第四章` / `§4`，
  而且**标题和指针用同一套编号**（中文写法和阿拉伯写法是**一个命名空间**）；
- `第 N 条`（清单里的第 N 条）**不是指针** —— 那是**枚举**，背后没有章节；
- 指针**绑到它前面那个文件名**（3.3 的规则）；
- 文件名**解析不到**就**说清楚**，并且**不假装查过**。

### 4.1 它会把「查不了」的东西说出来

| 数量 | 是什么 |
|---|---|
| 18 | 跳过的**枚举**（「第 N 条」） |
| 9 | 提到但**不在这棵树里**的文件名（附名字） |
| 2 | 被**中文字符切掉一半**的裸文件名（由精确匹配接管） |
| **0** | **查不了**的指针 |

> 9 个「不在这棵树里」的文件名，每一个都有出处：
> `at-no-such-card-exists.md` 和 `./at-no-such-card-exists.md` 是那张卡**故意写的反例**（一次带路径，一次不带）；
> `at-the-verdict-must-be-checkable.md` 是一张**没写的卡**（真悬空）；
> `CHANGELOG.md` 是一条**建议**（"可以新建"）；
> `notes/notes_W7_路线C_2026-09.md` 是**丢了的**笔记（原笔记自己写明了）；
> `Windows2022-Readme.md` 在**别的仓库**里；
> `x.md` 是**本节自己**举的例子（3.3 那条「句号会断开绑定」）——
> 而它**曾经**是那 **1 个查不了**的指针，
> 这一轮**把例子改成了真有的文件**（3.5 第三批），于是它变成了 **0**；
> `E:\qianwie\00study\OpenCV\notes\x.md` 和 `:\qianwie\00study\OpenCV\notes\x.md`
> 是**被指错了树**那一次的残留（4.5）——
> 那次算出来的「相对路径」**谁都不存在**，所以它们**只数不红**。

> ⚠ 这张表的第一版**印漏了一个名字**：
> 打印时用了「只印前 6 个」的截断，于是**数目写着 7，名单只有 6 个**。
> ⇒ 一个**数目**和一份**名单**对不上，两个就都**不能信**。
> 现在**一个名字都不截断**（`at-the-table-nobody-checks-drifts.md`）。

> ⚠ 而「**提到**一个不在这棵树里的文件」**不算红**，
> 「**指针**指向一个不在这棵树里的文件」**算红**（4.5）。
> 这条线是这一轮才画出来的：提到可能是**建议**，指针**一定**是**主张**。

### 4.1b 跳过的**指针**，也要说出来

| 数量 | 是什么 | 为什么不是主张 |
|---|---|---|
| **40** | 在**引号**里的指针 | 引文说的是「**那句话**」，不是「**那一章**」 |
| **8** | 在**行内代码**里的指针 | 代码是**字面量**，渲染器**原样显示** |
| **0** | **查不了**的指针 | 目标文件**不在这棵树里** |
| 18 | **枚举**（「第 N 条」） | 清单里的第几条，背后**没有章节** |

> **跳过的每一个都数出来、印出来。**
> 一个**没查**的指针，如果**不报**，
> 那它和一个**查过而且过了**的指针**长得一模一样** ——
> 而这两种在 CI 上都是**绿的**。
>
> ⇒ 本项目的规矩：**查不了要说出来，跳过了也要说出来**
> （`notes/atomic/at-an-audit-that-cannot-see-starts-lying.md`）。
>
> ⇒ 而这一轮把这条规矩**往前推了一步**（4.5）：
> **说出来还不够，结论也得跟着变。**

### 4.2 「一条指针都没查到」= **失败**

和链接检查器同一条规矩：
如果检查器一个指针都没找到，那要么树指错了，要么正则不匹配了 ——
**这两种情况看起来都像通过**。

⇒ 所以它还有一条**自检**：
它用来认中文的那几个码点**必须真的出现在文档里**，
否则**大声失败** —— 一个码点写错会让所有模式**匹配不到任何东西**，
而那正好是「看起来通过」。

### 4.3 变异验证（八条）

新写的检查器**自己**也可能是错的，所以照例先变异：

| # | 改了什么 | 期望 | 实测 |
|---|---|---|---|
| **A** | 台账「第十章」**被重新编号**（只改一个标题） | 红 | **红，37 条** ✅ |
| B | 塞一个**假的跨文件指针**（「台账第 99 节」） | 红 | **红，1 条**，消息点名了它绑到哪个文件 ✅ |
| C | 塞一个**假的同文件指针**（「本篇第 99 节」） | 红 | **红，1 条**，消息说它读的是所在文件 ✅ |
| **D** | **尺子坏了**：把解析结果强制成 `true` | 上面三条**必须不再被逮到** | **0 条红** ✅ |
| **E** | 一行里两个文件，**近的那个**说了算（3.3 的顺序规则） | 绿（绑对了） | **0 条红** ✅ |
| **E-OLD** | 同一条散文，把规则换回**旧的**（取数组里最后一个） | 红（会绑错文件） | **红，1 条** ✅ |
| **F** | 把同一个假指针**包进引号**里 | 绿（引文不是主张） | **0 条红**，且引号里的指针 40 → **41** ✅ |
| **A-LOOSE** | A **再加上**宽松规则（先看所在文件） | 红，但**比 A 少** | **红，18 条**（A 是 37） ✅ |

第 D 条是**这一轮最要紧的一条**：
没有它，「变异都红了」只能证明
「检查器和变异在某个时刻表现一致」，
证明不了**是检查器在报的**。

⇒ 和 `notes/atomic/at-mutation-ruler-broken.md` 是同一件事：
**尺子自己坏了的时候，你测出来的数一个都不能信。**

**E 和 E-OLD 是一对**：同一条散文，**只换绑定规则**，
一个绿一个红 ⇒ 证明那条顺序规则**真的在起作用**，
而不是「反正也不红」。
E-OLD 报的那条红，正是**绑错了文件**的红。

**F 证明的是「跳过也要说出来」**：引号里的指针从 40 变成 41，
而红是 0 —— 跳过它，**并且把跳过的数报出来**。
一个**只跳不报**的检查器，跳过的那 41 个和查过的 137 个
在 CI 上**长得一模一样**。

**A-LOOSE 把 3.2 那个数又量了一遍**：宽松规则只逮到 37 里的 **18** 个。

还有一条**反向**的验证：
3.2 里那个**已知的误报点**（`notes/notes_W7_Close_2026-10.md:125`，
「第 9.6 节 + 一个相关链接」）在变异 A 里**必须保持绿** ——
它证明新规则**没有把对的判成错的**。

> **误报和漏报一样致命**：
> 漏报是「本该红没红」，误报是「本该绿报红」——
> 后者更隐蔽，因为它会**训练人忽略这个检查**。

### 4.4 门禁**在报红的那一秒**死了

上面那条 A 变异（把台账的「第十章」改成「第十一章」）**本该**报 **36 条红**。
而它报出来的**不是红**，是一串绑定错误：

```
Cannot convert value "System.Object[]" to type
"System.Management.Automation.SwitchParameter"
```

⇒ **门禁在它唯一该说话的那一秒，死了。**

而且**没有人会发现**：
真实的那棵树是**绿的**（没有红），
所以**失败路径根本没被执行过** ——
而一条**从没跑过**的失败路径，**就是**一条坏路径。

> **门禁的失败路径，只有在它失败的时候才被验证。**
> 而「让它失败」这件事要**故意**去做（4.3 的 A 变异）——
> 否则它就**一直坏着**，一直没人知道。

**原因**（量出来的，不是猜的）：
`[switch]$List` 这个**参数**，在 PowerShell 里是一个
**带类型约束的变量**；
而失败消息里那个章节清单的局部变量叫 `$list` ——
**同名**，而 PowerShell 的变量名**不区分大小写**。

于是 `$list = @(...)` 不是「新建一个数组」，
是「把数组**塞进那个 switch 参数**」——
数组**转不成** switch。

⇒ 报错信息指向 `Sort-Object`，**没有**指向真正的原因。
（量到这里花了很久：先怀疑数据、再怀疑表达式、
再怀疑是不是「这个脚本里第一次调用」——
**全被排除了**，因为同一个表达式在别处跑得好好的。
真正把它分开的是**把赋值目标改个名字**：
`$warm` 行、`$list` 不行。）

**它只在脚本作用域里发作**：
在**函数**里，赋值会**新建一个子作用域的变量**，
根本碰不到那个参数 ⇒ **测的时候看起来是好的**。

> ⇒ 本项目栽过的**又一次**「**测的地方和出问题的不是同一个地方**」。
> 一个在错误作用域里做的测试，会给出一个**绿色的假象**。

⇒ 修法两条：
1. 参数改名 `-ShowSkips`，局部改名 `$chapList` ——
   **局部的名字不许和带类型的参数同名**；
2. 那个排序**加了保护**：排序坏了就退回原顺序 ——
   **顺序是装饰，红才是重点**，
   排序不该有能力弄死这条消息。

新卡：`notes/atomic/at-a-gate-failure-path-runs-only-when-it-fails.md`
（并在 `notes/atomic/at-powershell-names-ignore-case.md` 里记了**复发**：
这一次撞上的是**带类型的参数**，而它**只在失败路径上**发作，
所以比第一次**更难发现**）。

### 4.5 门禁被**指错了树**，结论**还是绿的**

4.4 是**门禁自己死了**。这一条更怪：**门禁活着，而且说了所有该说的话，
然后判了个 OK。**

起因是一个手滑：`-RepoRoot` 传成了 `.`，而不是绝对路径。
再跑一次，输出是：

```
166 pointers seen: 123 resolve (54 cross-file, 69 same-file), 0 do not
named files not in this tree: 117 distinct -- ../notes/notes_CI_2026-10.md, ...
pointers that could NOT be checked (their target file is not in this tree): 46
SECTIONS OK: 123 of 166 section pointers resolve across 129 files
```

> ⚠ 上面这四行是**那一天的历史快照**，**不改** ——
> 那一轮树上的指针数就是 166，门禁当时就是这么报的。
> 把它当成当前值会**看见一个不存在的现象**（现在早就不是 166 了）。

⇒ **46 个指针查不了**，**117 个文件名找不到**，而结论是 **OK**。
⇒ 而且它连**自己量到了什么**都不知道：
`notes/atomic/` 下的卡它**一张都没找到**（**0 张**），
真实的树上有 **83** 张（**那一轮测量时的数**）。

**根因**是一句**前缀假设**：

```powershell
$rel = $f.FullName.Substring($RepoRoot.Length)
```

这只在 `$RepoRoot` 是**绝对路径的前缀**时成立。
传 `.` 时，`$RepoRoot` 长度是 1，而 `$f.FullName` 是
`E:\qianwie\00study\OpenCV\notes\x.md`
⇒ 算出来的「相对路径」是 `:\qianwie\00study\OpenCV\notes\x.md`
—— **谁都不存在的一个路径** ⇒ **每一次查找都不中**。

**三道门，一个根，三种下场**：

| 门 | 树看错之后 | 结论 |
|---|---|---|
| `check-sections.ps1` | 路径全错，**46 个指针查不了** | **绿的（谎）** |
| `check-doc-numbers.ps1` | **0 张 atomic 卡**、115 张「笔记」 | **红的**（它和现实对照，自己对不上就露馅） |
| `check-links.ps1` | 只影响**打印出来的路径**（链接按所在文件解析） | 绿的（**这次是碰巧对的**） |

⇒ **和现实对照的门会自曝；只往前看的门不会。**
「查完了吗」不是自曝，**「查到的数对得上吗」**才是。

**修法三处**（三道门**共用**一份，放在 `tools/lib/DocScan.ps1`）：

1. **根先解析成绝对路径**（`Resolve-RepoRoot`），再拿去做前缀运算。
2. **先认树，再量**（`Get-RepoTreeProblems`）：
   `README.md`、`notes`、`notes\atomic`、`tools\ci.ps1` 四样缺一样，
   就**大声拒绝** ——
   **被指错了树，要报错，不要报告。**
3. **查不了的指针 = 失败**，不是「跳过了」 ——
   和链接门对齐（链接指向不存在的文件，本来就是红的）。

第 3 条顺带修掉一处**不一致**：
链接门对「相对链接指向不存在的文件」是**红**的，
指针门对「指针指向不存在的文件」却只是**数一数**。
⇒ 同一件事，两道门两个态度。现在统一了：
**指向不存在的地方的主张，就是坏了的主张。**

> 而**提到**一个不存在的文件仍然是**只数不红** ——
> 提到可能是**建议**（「可以加一个 CHANGELOG.md」）、
> 也可能是**别处的文件**（`Windows2022-Readme.md` 在另一个仓库）。
> **提到**不是主张，**指针**才是。

**验证：三条路，都量过**

| 跑法 | 结果 |
|---|---|
| `-RepoRoot <绝对路径>` | 142 of 190 解析成功，48 个跳过，**0 个查不了** |
| `-RepoRoot .` | **和上面一模一样**（修好之前**不一样**） |
| `-RepoRoot <别的目录>` | **红的**：`is not the OpenCV study tree`，并列出缺了什么 |

新卡：`notes/atomic/at-a-checker-pointed-at-the-wrong-tree-still-says-ok.md`

## 5. 顺带：把链接检查器**收成一份**

这一轮还做了一件不显眼但该做的事：
`tools/check-links.ps1` 和 `tools/check-sections.ps1` 需要**同样三样东西** ——

## 7. 这一笔的边界（明写出来）

- 这一笔**没动产品代码**，**一条断言都没加**。
  它加的是一道**门禁**。
- 欠账 11（流程债）**不可能「还清」**：
  这一笔做的是把「发现不一致的成本」压到最低。
  它**永远**是「这一版文档对上了这一版现实」。
- 检查器**不判断**一个指针「写得对不对」，
  它只判断「这一篇里**有没有**那一章」。
  语义对不对（比如「第十节」指的那节是不是讲的那件事）**是人的事**。
- 指针**绑到前面那个文件名**这条规则是**约定**，不是真理：
  写文档的人**知道**自己指的是谁；
  规则只是把那个知识**机械化**，好让机器能查。
- 这一轮把「**查不了**」从「**数一数**」改成了「**红**」——
  这是一条**更严**的规矩，它可能让 CI 因为一条**真的**坏指针而红。
  这正是它该做的：**一个指向不存在的地方的主张，就是坏了的主张。**
- 而「**提到**一个不存在的文件」仍然**只数不红** ——
  提到可能是建议、可能是前瞻引用、也可能是另一个仓库里的文件。
  这条线是**故意**画在这儿的。

## 8. 收尾：普查的门禁 —— 把那次实验搬进门禁

### 8.1 发现：这些数**到处都在**，而**没有一道门看着它们**

上一笔的门禁写完了，它的输出里有一份**普查**（2.1）。

**而这些数，被写进了 11 个文件，一共 79 处。**

每一处都是**一条关于现实的主张**。
而上一笔那道门只查**指针指向哪里**，
**不查「指针的数目」对不对** ⇒ 它**结构上就看不见**这些数。

⇒ 于是上一笔的原则（`at-the-table-nobody-checks-drifts.md`）在这里**又复发了一次**：
**被记录的事实没有门 ⇒ 它会漂。**

### 8.2 它**当场就漂了**

量一下上一笔结束时的树（HEAD）和现在：

| | HEAD | 现在 |
|---|---|---|
| markdown 文件 | 129 | **139** |
| 章节指针 | 164 | **190** |

**多出来的那些数，全是这一轮的新文字带来的。**
因为新文字里**有章节指针** —— 而**指针总数是被新文字自己推高的**。

⇒ 于是 HEAD 上还**完全正确**的那些引用
（`164` / `57` / `35` / `19` / `54` / `69` / `691` / `129`），
在这一轮里**一起过期了** ——
而**没有一个门会叫**。

⇒ 这是 `at-writing-the-number-changes-the-number.md` 的**同一个形状**：
**写下这个数的动作本身，就让这个数过期。**
⇒ 而这一轮**又**没为它准备门。

### 8.3 「加个门查这 79 处」是**错的修法**

最直觉的修法：把「改一个标题断几个指针」那个数写进门禁，当期望值。

```
文档写 36  ⇒  门禁说 36  ⇒  绿的
```

**这钉住的是快照。**

那个数是「某天的实验结果」，而树一直在变 ——
钉住快照的门禁，只会在**树变了之后**继续说「36 是对的」，
而 36 早就不是真相了。

⇒ 门禁成了一个**更响的转述**：
它把一个过期的数**说成了**当前的事实，
而且**说得比散文更可信**（因为它是机器说的）。

### 8.4 正确的修法：把那场实验搬进门禁

不是「记下实验的结论」，是「**让实验每次都跑**」。

`tools/check-sections.ps1` 现在每次运行都**当场模拟**一次改号：

1. 找出**指着同一个文件、同一个章节**的所有指针（= 爆炸半径）；
2. 逐个判断：那个章节**不存在**了 ⇒ 这个指针**断**；
3. 再判断：如果改用**宽松规则**，它会不会**被绑到读者自己那一篇的同号章节**上
   ⇒ 那就是**安静指错地方**的那些。

⇒ 于是那个数不再是「那天的实验结果」，而是「**此刻**算出来的数」。
⇒ 而文档里那 79 处引用，门禁每次都拿它们和**此刻**的数比。

**期望值一个都不是抄的**：
每一条声明的期望值都来自**这一次的测量**，
文档里那个数是**唯一**存放它的地方
（`at-the-expected-value-must-be-read-not-copied.md`）。

⇒ ⚠ 而「1:1」这句话**本来是假的**，这一轮才把它变成真的：

### 8.6 变异验证（四条）

| **D** | **尺子坏了**：把比较改成永远成立 | A/B/C **必须不再被逮到** | **0 条红** ✅ |

第 D 条最要紧：没有它，「变异都红了」只证明

证明不了**是检查器在报的**


它自己会判定「**A/B/C 必须是红，D 必须是绿**」，
对不上就**报错退出**（退出码 1）——
⇒ **连「这条验证自己有没有坏」，也写进了它自己。**

### 8.7 这一节的数，是**写完这一节之后**才量的

§8.5 那张表里的每一个数，都是**这一轮量出来的**，

（新写的散文里有章节指针 ⇒ 指针总数在变）。

⇒ 所以顺序是：**先写完这一节，再量，再回填**。
⇒ 而**回填之后还要再跑一遍门禁** ——
因为回填本身**又改了文件**，
而文件大小是**另一个**被门禁看着的数
（`at-writing-the-number-changes-the-number.md`）。

新卡：`notes/atomic/at-a-number-nobody-can-recompute-is-hearsay.md`

## 9. 第四次真跑：失败路径脚本**自己**先坏了

8.6 那四条变异，第一次上真 runner 就红：

```
UNEXPECTED: mutation D should be GREEN but came out RED
MUTATION HARNESS FAILED
```

⇒ **红的不是门禁，是脚本。**
⇒ 而这件事**本地看不出来**：本机（5.1 和 7.4.6 都试过）跑出来是绿的。

### 9.1 读日志：两堆红，**不是一个**毛病

55 条红分成两堆（**那一轮 runner 日志的原话** —— 历史快照，不是此刻的数）：

| 堆 | 条数 | 它说的是 |
|---|---|---|
| 「查不了」（`which is not in this tree`） | **50** | **副本不是那棵树** |
| 普查断言的红 | **5** | **尺子只坏了一把** |

第一堆：每一条红里的文件路径前面都挂着一层 `C,D\`，
而那三个字符正好是**变异清单 `A,B,C,D`** 的尾巴
（副本目录就叫这个名）。
⇒ 副本的**目录结构**错了 ⇒ **门禁量的是另一棵树**：
同一个文件里的指针还能查（**69** 个全在），
跨文件的全查不了（**62** 个只剩 **12** 个）。

第二堆：普查的数有**两种**查法 ——
**块断言**（`$nums[$g].Value -ne $claim.Expect[$g]`）
和**行断言**（`$got -ne $want`）；
8.6 的 D 只断了**行断言**那一处 ⇒ 块断言还在 ⇒ 还剩 **5** 条红。

### 9.2 三个修法，三条都写进了脚本

1. **先认副本，再信它**：副本用之前，先跑一遍检查器，
   它的汇总行必须和真树上**一字不差**；文件集也必须**逐个相等**。
   对不上就 `THE COPY IS NOT THE TREE`，**拒绝给结论**。
   ⇒ 这一条治的是「副本不是树」那个毛病。
2. **尺子两把一起断**：D 现在断**两处**比较，
   每一处替换都**断言只替换了一处**
   （替换了 0 处 = 变异没发生 = 一个假的绿）。
   ⇒ 这一条治的是「尺子只坏了一把」。
3. **期望写成正面的话**：
   D 要「**它说通过了，而且一条红都没有**」，
   A/B/C 要「**至少一条红，而且零条「查不了」**」。
   ⇒ 原来那两种写法，**检查器崩了也满足**
   （崩了就没有那行 `SECTIONS OK`）；
   而「至少一条红」也会被**树坏了**满足 ——
   那种红不是**尺子**报的，是**树**报的。
   ⇒ 这一条治的是「期望写成了症状的缺席」。

### 9.3 这道新门**自己被抓过一次**

把复制逻辑**故意改坏**成 runner 上那个形状
（每个文件都塞进一层 `C,D\`），再跑一次：

```
THE COPY IS NOT THE TREE: the copy does not hold the same files
   missing from the copy (142): notes\atomic\at-a-blind-reading-cannot-watch.md, ...
   extra in the copy (133): C,D\notes\atomic\at-a-blind-reading-cannot-watch.md, ...
```

⇒ 它**拒绝给结论**，并把两边差在哪**列了出来**。
（上面那几行是**本机破坏那一次的原话** —— 历史快照。）

⇒ 不是「它跑过了」，是「它**在该红的时候红了**」
（这正是
`notes/atomic/at-a-gate-failure-path-runs-only-when-it-fails.md`
那张卡说的那件事）。

### 9.4 这一笔**没有改**任何被门禁看着的数

> ⚠ 这一节记的是**那一轮**（修「CI 第一次上真 runner」那轮）的结论：
> **那一轮**没动任何被门禁看着的数。
> 下面两行是**当前**的数 —— 门禁核的就是当前值；
> 后来 2026-10-28 补 W3 测试那轮加了 2 个文件、6 条指针，
> 2026-10-29 给三道文档门禁配变异那轮又加了 1 个文件、0 条指针，
> 所以这两个数**已经回填过**了。

普查还是 **139** 个 markdown 文件 / **190** 个章节指针
（**71** 跨文件 / **71** 同文件），门禁里那一条条数断言**一条都没漂**。

⇒ 那一轮唯一变的是**章节标题数**：它给这一篇和结项报告各加了几个带编号的小标题，
所以那个数变了，**两处**都改了
（这一篇的普查块，和结项报告的那一行）—— 门禁把这两处都抓到了。
⇒ 那一轮指针总数**没变**：新增的散文里**一个章节指针都没写**
（写一个，指针总数就 +1，全仓要重新回填一遍）。

## 10. 第五次真跑：**一个目录，两个字符串**

第二次上真 runner（失败路径脚本的**第二次**），红的还是**脚本**，不是门禁 ——
但这一次，门禁**自己喊了出来**：

```
THE COPY IS NOT THE TREE: the copy does not hold the same files
   missing from the copy (142): notes\atomic\at-a-blind-reading-cannot-watch.md, ...
   extra in the copy (142): ine\notes\atomic\at-a-blind-reading-cannot-watch.md, ...
```

⇒ 一边是**干净的相对路径**，一边每个都多三个字符：`ine\`。
⇒ 而 `ine` 是 **`pristine` 的尾巴** —— 副本目录本来就叫 `pristine`。

### 10.1 那三个字符从哪来：8.3 短名

runner 上 `$env:TEMP` 是 **`C:\Users\RUNNER~1\AppData\Local\Temp`**（8.3 短名），
而 PowerShell 的 provider 枚举文件时给的是**展开后的**
`C:\Users\runneradmin\AppData\Local\Temp`。

```
RUNNER~1    =  8 个字符
runneradmin = 11 个字符
```

⇒ **同一个目录，两个字符串，差三个字符。**

而相对路径是**拿长度切出来的**
（`$f.FullName.Substring($root.Length)`）：
切的时候用的是**短名**的长度，枚举出来的是**长名**的路径
⇒ 切深了三个字符 ⇒ 每一条相对路径**从头就错了三个字符**。

### 10.2 本机复现：造一个 8.3 短名的目录就够了

（下面是**本机量出来的原话** —— 历史快照。）

```
root string : C:\...\Temp\t8probe\AVERYL~1              (len 47)
Get-Item    : C:\...\Temp\t8probe\AVeryLongDirectoryNameToForceShortNameHere  (len 81)
child       : C:\...\Temp\t8probe\AVeryLongDirectoryNameToForceShortNameHere\f.txt
Substring   : [gDirectoryNameToForceShortNameHere\f.txt]      <-- 垃圾
```

⇒ 拿短名当根，跑那个失败路径脚本，本机**红在同一句上**：

```
THE COPY IS NOT THE TREE: the copy does not hold the same files
   extra in the copy (142): meToForceShortNameHere\mw\pristine\notes\atomic\...
```

⇒ **这一轮那个红，本机也造得出来** ——
不是「runner 有 runner 的毛病」，是**同一个毛病**，
而它**本来就能在本地复现**（只是要**造**一个 8.3 短名的目录）。

### 10.3 修的不是脚本，是**根**

只修脚本**不够**：同样的切法在**四个检查器**里都有 ——
它们都拿 `Resolve-Path` 解析出来的根，去切枚举出来的路径；
而 `Resolve-Path` **原样返回短名**（本机量到：47 个字符），
`Get-Item` 才给**展开后的**（81 个字符）。

⇒ 所以修在**共用的那一处**：
`Resolve-RepoRoot` 改成**问 provider 要**那个目录（`Get-Item ... .FullName`）；
而相对路径**不再切字符串** —— 基址取 provider 自己的答案，
文件不在基址底下就**喊出来**，不切。

⇒ 这个病**本来是潜伏的**：runner 的检出路径没有 8.3 成分，
所以它**没发作**；它发作在**临时目录**上 ——
因为那才是从 `$env:TEMP` 拼出来的。

### 10.4 这一节**只**动了一个被门禁看着的数

新增的散文里**一个章节指针都没写**（写一个，指针总数就 +1，全仓要重新回填一遍），
所以指针总数、文件数、普查的其它数**一条都没漂**。

唯一变的是**章节标题数**：这一节给这一篇和结项报告各加了几个带编号的小标题，
所以那个数变了，**两处**都改了 —— 门禁把这两处都抓到了。
