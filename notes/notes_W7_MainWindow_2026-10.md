## 2. 判据：错了用户会不会自己发现

搬不搬、测不测，用的**不是**「哪段逻辑重要」，是这个：

| 现象 | 用户能自己发现吗 | 要不要测 |
|---|---|---|
| 节点画歪了、窗口尺寸不对、按钮没排好 | **能**（一眼就看见） | 不用 |
| 表单显示新值，跑出来是旧值 | **不能**（画面很正常） | **必须** |
| 显示的是另一张图，数字对不上 | **不能** | **必须** |
| 参数改了，右键回看还是**旧结果** | **不能** | **必须** |
| 算子没装，面板上看不出来 | **不能** | **必须** |

> 画错了会自己发现；**选错了不会**。
> 后者才是必须搬出去、必须测的那一类。

这条线**早就定过**（第三笔的笔记里就写了），
只是从来没人拿它给主窗口**切一遍**。这一笔切了，切完的结果在第 6 节。

## 3. 怎么让它可测：三步

### 3.1 主程序源码 → 静态库

```
w7_app_core          mainwindow.cpp + 算子 + 画布 + Command 层   (实现)
w7_vm_lite               main.cpp + w7_app_core                    (GUI 外壳)
w7_mainwindow_test       测试 + w7_app_core                       (测试外壳)
```

两个外壳**共用同一份实现** —— 这条是必须的：
测试里另写一份加载逻辑，测的就不是产品了。

顺带的好处：`mainwindow.cpp` 和那一坨 OpenCV 算子**只编一次**
（本机内存只有 15.7 GB，连续编七次就会 OOM）。

> ⚠ 静态库 + AUTOMOC 的坑：moc 出来的 `moc_mainwindow.cpp` 进的是静态库，
> 链接时靠「`mainwindow.o` 引用了 `MainWindow::staticMetaObject`」把它拉进来。
> 真丢掉的现象是链接期报 `unresolved external symbol`，而且报在 moc 出来的符号上，
> 一眼看不出来源。

### 3.2 真的起一个 `QApplication`

```cpp
qputenv("QT_QPA_PLATFORM", "offscreen");
SetConsoleOutputCP(CP_UTF8);
QApplication app(argc, argv);
```

离屏，不需要显示器。和别的 25 个套件一模一样。

### 3.3 走**和用户一模一样的那条路**

不许在测试里另写一份「加载工程」「跑一次」的逻辑：

| 用户做的 | 测试怎么驱动 |
|---|---|
| 点「打开工程」 | `QMetaObject::invokeMethod(&w, "loadProjectFrom", Q_ARG(QString, path))` |
| 点「▶ Run」 | `QMetaObject::invokeMethod(&w, "onRunClicked")` |
| 点一个节点 | `scene()->clearSelection(); node->setSelected(true);` |
| 改参数再点「应用参数」 | 找输入框 → 改值 → 找按钮 → `click()` |
| 从算子库拖一个节点 | `canvas->nodeAddRequested(...)` |

> `loadProjectFrom` 以前是**私有方法**，不在元对象里，invoke 不到。
> 这一笔把它改成 **private slot** —— 行为一点没变，但能按名字 invoke 了。
> （选 private slot 而不是 public：能 invoke，又**不扩大公开面**。）

## 4. 改了什么

### 4.1 「算子没装」这条规则收成**一份**（纯层）

上一笔立了规矩：「算子没装」由**解析层**说了算，那一步**强制失败**。

但那一笔只在 headless 侧落了地。GUI 侧当时是**另一份实现**：

| | headless | GUI（上一笔之后） |
|---|---|---|
| 判据 | `gn.known`（解析层给的） | `createOperatorByName()` 返回空（**另一个事实来源**） |
| 消息 | 「算子 X 未注册，**这一步跑不了**」 | 「算子 X 未注册，**跳过**」 |

**行为一致、消息不一致** —— 这是最难发现的那一类：
不比对两边就看不出差别。

而 GUI 那句「**跳过**」是**错的**：它**并没有跳过**。
那一步返回了 `false`，引擎记成失败，整批判 ERROR。
用户在日志里读到「跳过」，会以为后面照跑了。

新文件 `W7_VisionMasterLite/missing_operator.h`（**纯 QtCore**）：

```cpp
inline QString missingOperatorMessage(const QString& opName);
inline bool rejectMissingOperator(const QString& opName,
                                  const QSet<QString>& missingOps,
                                  QString* err);
```

`pipeline_graph.h` 里多了一个收拢用的纯函数：

```cpp
inline QSet<QString> missingOperatorNames(const QVector<GraphNode>& nodes);
```

> ⚠ 判据是「**调用方给的事实**」，不是「纯层去问工厂」：
> 纯层不能 new 算子（`OperatorBase` 的头拖 `opencv2`），
> 而「装没装」这个事实是**解析层**知道的（`known=false`）。
> 纯层只负责**判**和**说**，不负责**查**。

### 4.2 主窗口的**只读可观测面**

```cpp
struct MainWindowWiring {
    int  nodeCount, connectionCount, missingOperatorNodeCount;
    int  paramPageIndex, paramPanelPages;
    bool paramShowsForm;
    QString paramPlaceholderText, logText, resultTitle, resultDetail;
    bool undoEnabled, redoEnabled, stopEnabled;
    QStringList cachedNodeIds;
};
MainWindowWiring wiringSnapshot() const;
```

为什么要有这个东西：

- 主窗口的状态**全是私有的**，而私有就等于**没测过**。
- 只暴露**读**接口：暴露写接口的测试可以「先改再断言」，
  把 bug 藏进自己的设置里。
- **不含任何指针**：拷贝一次就够，不牵扯窗口生命周期。

> ⚠ 为什么不全用「按类型找控件」（`findChild<QPlainTextEdit*>`）：
> 窗口里同类控件有好几个（两个 `QPlainTextEdit`、好几个 `QLabel`），
> 按类型找就得靠「第几个」，而顺序一改断言就错位 ——
> 那样的测试测的是**顺序**，不是**接线**。

见第 6 节。

## 5. 「算子没装」那条规则，在 GUI 侧长什么样

| | 行为 |
|---|---|
| 画布 | 节点**留着**，灰底 + 虚线框 + 顶上「未安装」 |
| 参数面板 | 切**占位页**，写清「算子 X 未安装 … 整条流水线会被判为 ERROR」 |
| 运行 | 那一步**强制失败** → 整批判 **ERROR** |
| 日志 | 「算子 X 未注册，**这一步跑不了**」（不再说「跳过」） |

> 「链没断」≠「没事」：
> 链没断意味着下游拿到的是「**上游那一步失败了**」这个**事实**
> （能被 `w7::isBadStep` 认出），而不是「上游安静地什么都不产出」。

## 6. 测试抓到了什么

**这一笔的四个发现，全都不是「产品早就坏了」，而是「上一笔的 GUI 那一半没人测」。**

### 6.1 上一笔的 GUI 改动，一条断言都没有

上一笔（P0-1）改了主窗口两处：

1. 算子没装 → 参数面板切占位页（不再留着上一个节点的表单）
2. 算子没装 → 那一步失败、整批判 ERROR

**两处都没有断言。**
新套件写的第一条断言就是「面板切占位页」——
它**当场就绿了**（因为上一笔确实写对了），
但**从那一刻起**，它才**被钉住**。

> 改完不测 = 改完不知道对不对。
> 而「写对了」和「碰巧对」在报告里长得一模一样。

### 6.2 「算子没装」有两份实现（第十一遍抄副本）

见 4.1。消息还不一样。

> 本项目栽过**十遍**「抄副本」，这是**第十一遍**。
> 这一遍的特别之处：两份**行为一致**，只有**消息**不一致。
> 行为一致意味着「两份一起错」也看不出来 ——
> 只有**消息**这个「无害的差别」暴露了它。

### 6.3 状态和画面对不上（真 bug）

「算子没装」和「没选中节点」这两条分支当时是：

```cpp
m_currentParamWidget = nullptr;      // ← 只把指针置空
m_currentParamNode   = nullptr;
m_paramPanel->setCurrentIndex(0);    // ← 切回占位页
```

那个表单 widget **还留在堆栈里**。后果：

| 后果 | 症状 |
|---|---|
| **孤儿表单** | 每选一次没装的节点，堆栈里就多一个死表单 —— 面板**越点越胖** |
| **状态和画面对不上** | 面板上明明是占位页，主窗口却还记着「当前显示的是那个表单」 |

第二个尤其要命：**界面看着完全正常**。
用户看得见的全对，看不见的全错。

修法：收成一处 `dropParamForm()`，**三条分支都走它**
（没选中节点 / 算子没装 / 换了一个节点）。

→ `notes/atomic/at-the-state-and-the-screen-must-agree.md`

### 6.4 一个**时绿时红**的测试

新套件第一版连跑 6 次：

```
run 1 exit=0    run 2 exit=0    run 3 exit=1
run 4 exit=0    run 5 exit=1    run 6 exit=1
```

红的断言写的是「选中没装的节点时，面板不该显示上一个节点的表单」，
而真正的原因是「面板显示了**另一个已知节点**的表单」。

根因：**程序化调 `setSelected(true)` 不会取消上一个选中** ——
取消选中是 `QGraphicsView` 在处理**鼠标点击**时做的，程序化调用绕过了那一层。
于是场景里**同时有两个选中**，而主窗口是「取第一个」。

> 一个时绿时红的测试，最容易让人怀疑产品不稳定。
> 而真相是：**产品是稳的，是测试自己制造了一个产品不会有的状态。**

修法：补上「先 `clearSelection()`」这一步，和用户点空白处一样。
补完之后连跑 12 次全绿。

→ `notes/atomic/at-programmatic-calls-are-not-user-actions.md`

> ⚠ 顺便把「会不会自己发现」这条判据用在了**测试自己**身上：
> 这个 bug **不会**让用户看见（那是测试内部的事），
> 但它**会让断言说谎** —— 而一条说谎的断言比没有断言更坏。

## 7. 新套件

`W7_VisionMasterLite/tests/test_mainwindow_wiring.cpp`（**52 条**，8 个用例）：

| 用例 | 测什么 | 「用户发现不了」? |
|---|---|---|
| 1 | 主窗口能起来，默认流水线在 | 前提 |
| 2 | 算子没装 → 节点**留在画布**、标「未安装」、**链不断** | ✔ |
| 3 | 算子没装 → 面板切占位页，**不显示别人的表单**，占位页点名是哪个算子 | ✔✔ |
| 4 | 算子没装 → 跑起来是 **ERROR**，日志**不许**说「跳过」，跑完 UI 恢复原状 | ✔✔ |
| 5 | 改了参数 → **节点上的参数真的变了** | ✔ |
| 6 | 改了参数 → 这一步的**旧结果作废**（缓存清了 + 标记清了） | ✔✔ |
| 7 | 「算子没装」这条规则**只有一份**（源码守卫，查前先剥注释） | — |
| 8 | 守卫查的是「**有没有调**」，不是「名字在不在」 | — |

用例 6 是这一轮**最值钱**的一条。
用户调完阈值，右键回看这一步，看到的是**调参之前**的结果 ——
画面看着完全正常（就是那张图），数字却和当前参数对不上。
用户会以为「改了没生效」，或者更糟：以为程序算错了。

所以规则是：**参数一改，这一步的旧结果就不作数**（宁可看不到）。
三件事必须**一起**发生：节点参数更新 / 缓存被清 / 「有可回看结果」的标记被清。
少了任何一件，症状都是「画面正常、数字对不上」。

### 提交前又差点栽进同一个坑（**量法**，不是数）

核对「C++ 文件 / 行数」这一栏时，我按老习惯数工作树：
`Get-Content` 默认编码数出 **37,381**，而文档写着 **41,330**，差 4,578 行。

**文档那个数是对的，我那个数是错的。**

PowerShell 5.1 的 `Get-Content` 默认按 ANSI(GBK) 读文件，
仓库里的 `.cpp`/`.h` 是 UTF-8 —— 中文字符的 UTF-8 字节被 GBK 解码器
**当成双字节 + 落单字节**，第 3 个字节成了新的前导字节，
它后面那个字节如果是 `0x0A` 就被**当成尾字节吃掉** ——
**行尾没了，两行合并成一行**。

131 个文件里 **114 个**对不上，少算 **3,931 行（9.5%）**。

> ⚠ 这已经是**第二次**栽进同一个坑了，
> 而那张卡（`notes/atomic/at-the-decoder-eats-the-newline.md`）
> **就躺在 `notes/atomic/` 里**，
> 里面甚至**早就印着**我这一轮量到的同一组数
> （`test_operator_knobs.cpp`：3,689 vs 3,210，一模一样）。
>
> 第一次栽的时候危险方向是「数比文档多 → 怀疑文档过期」；
> 这一次是「**数比文档少 → 差点把一个对的数字改坏**」。
>
> **后者更贵** —— 错的数字还能被查出来，
> 被「确认过」的错数字看上去已经没问题了。
>
> 判据：**「你先能改的那一方，多半是你错了。**
> **你能让量法和权威一致（改命令），还是只能让权威和你一致（改文档）？**

处置：用**索引内容**（`git show :path`，= 将被提交的内容）重算，
并把 41,330 **拆开验平**：

```
HEAD 129 文件           40,374
  + 5 个改动的 C++ 文件  +224
  + 2 个新文件           +732
  ---------------------------
  = 131 文件            41,330   ✓
```

**能拆开、拆完对得上**，才算这个数是「算出来的」而不是「抄来的」。
→ 文档里的 **131 / 41,330 没动**。

⚠ 顺手逮住另一个**真的漂了**的数：**notes 体积**。
根因有两条，**都不是「算错了」**：

1. **那个数在追加 atomic 卡之前**量的 —— 本轮追加了两段
   （ninja-mtime 的「第四次复发」+3.6 KB，
   解码器那张卡的「第二次复发」+5.5 KB）。
   **「先量数字、后改文件」= 数字立刻过期**，
   量的动作必须排在所有改动**之后**。
2. **同一个数在根 README 里抄了两份**（「变更日志」那一段和「统计」那一段），
   而其中一份**从上一轮起就没跟着更新** ——
   `at-four-copies-of-one-number.md` 的现场版。

⚠ 而且它还牵出**第三个**问题：**量出来的那个数本身取决于怎么量**。

同一批文件：
| 口径 | 结果 |
|---|---|
| 工作树直接量字节 | ~893 KB |
| **把行尾归一化成 LF 之后**（= 仓库里真正存的内容） | **~891 KB** |

差在一个 CRLF 的文件上（`notes_W7_Knob_Audit_2026-10.md`）。

⇒ **字节数必须归一化之后再报**，
否则「换台机器 clone 一次」就复现不出来 ——
这跟行数那条（`at-the-decoder-eats-the-newline.md`）是**同一个病的两个变体**：
一个是**读**的时候把行尾吃了，一个是**存**的时候行尾不一样。

这一条已经写进 `tools/check-doc-numbers.ps1` 的口径里。
