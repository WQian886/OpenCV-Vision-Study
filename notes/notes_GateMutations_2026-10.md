# 给三道文档门禁配变异：数、链、章节指针（2026-10-29）

## 一句话
> **一道门禁如果从来没红过，就没有人知道它会不会红。**
>
> 这一轮给**文档那三道门**都配上了自己的变异脚本，
> 挂进 CI（**Step 3g**），**每次 CI 都跑**，
> 跑在**树的副本**上（真树一个字都不碰）。

## 现象：三道门从写下来那天起，就一直是绿的

仓库里有一串门禁（`tools/ci.ps1`）：

| 步骤 | 门禁 | 管的是什么 |
|---|---|---|
| 3c | `tools/check-doc-numbers.ps1` | 文档里引用的**数**还对不对 |
| 3d | `tools/check-links.ps1` | 文档里的**链接**还指不指得到 |
| 3e | `tools/check-sections.ps1` | 文档里的**章节指针**还指不指得到 |
| 3f | `tools/mutate-census.ps1` | 普查门禁**自己**会不会红 |

**3f 是这串里唯一一个有过「失败路径」的。**
3c / 3d / 3e 呢？**从来没红过。**

为什么？因为**树一直是绿的** ——
失败路径**只有在树红的时候才跑**，而树**从来不红**。

⇒ 「CI 是绿的」只证明了**成功路径**是对的。
⇒ 一道从没红过的门禁，和一道**坏掉的**门禁，
在 CI 日志里长得**一模一样**。

这不是猜测，是**量过的**：
`tools/check-sections.ps1` 当初写完就绿，
第一次**故意**让它红，它当场死了
（`Cannot convert value "System.Object[]" to type
"System.Management.Automation.SwitchParameter"`）——
**门禁在它唯一该说话的那一秒，死了，而没有人会发现**。

那次的结论收在一张卡里：
[门禁的失败路径，只有在它失败的时候才被验证](./atomic/at-a-gate-failure-path-runs-only-when-it-fails.md)。

⇒ 这一轮补的是**同一个洞的另外三个门**。

## 这一轮做了什么

新增两个文件，CI 多一步：

| 文件 | 干什么 |
|---|---|
| `tools/lib/MutHarness.ps1` | 共用的机械：造副本、跑子进程、替换文本、比对摘要 |
| `tools/mutate-gates.ps1` | 三道门 × 四条变异，判定「该红的红、该绿的绿」 |

CI 的 **Step 3g** 每次都跑：

```
powershell -File tools/mutate-gates.ps1 -RepoRoot <tree> -Mutation A,B,C,D
```

跑完是绿的，说明**四道门（3c/3d/3e 各四条）都按该有的样子表现了**。

### 三道门 × 四条变异

**A / B / C**：往**副本**里放一个缺陷，门禁**必须红**，
而且**必须是它该报的那条**（不是碰巧也红）。
**D**：**尺子坏了**，缺陷**还在**，门禁**必须绿**，
而且它打印的那句摘要**必须和好树打印的一字不差**。

| 门 | A | B | C | D（尺子坏了） |
|---|---|---|---|---|
| 3c | README 里的 C++ 行数漂一行 | 逐套件表的一行漂一条断言 | 逐笔记大小表的一行漂 1 KB | 断掉**两把**尺子（块断言 + 行断言） |
| 3d | 链接指到一个不存在的文件 | 链接指到别的文件里一个不存在的标题 | 链接指到自己文件里一个不存在的标题 | 断掉**三把**刀（文件不在 / 目标是目录 / 标题不在） |
| 3e | 欠账台账的一个标题**改号** | 指针**指到的那个文件**不存在 | 一个**指针**指到不存在的章节 | 断掉那条「这个指针解不解析」的判据 |

实测（2026-10-29，本机）：

| 门 | A | B | C | D |
|---|---|---|---|---|
| 3c | 1 条红 | 2 条红 | 1 条红 | 0 条红，摘要一字不差 |
| 3d | 1 条红 | 1 条红 | 1 条红 | 0 条红，摘要一字不差 |
| 3e | 87 条红 | 13 条红 | 11 条红 | 0 条红，摘要一字不差 |

3e 的 A 之所以是 **87** 条：改一个标题，断掉的是**三样**东西 ——
**37 条**指着那个章节的指针、**3 条**「锚点没找到」
（那几个断言靠「`## 十、` 这一行」定位自己），
还有 **47 条**普查数（那些数**跟着章节表一起动**）。
⇒ **改一个标题，断的从来不只是一个标题。**

### D 为什么必须**带着缺陷一起坏**

这是这一轮**最要紧的一条**，也是和 3f 最大的不同。

3f 的 D 是：**尺子坏了，树是好的**。
它要求 D 是绿的、零条红。

但那个绿**能证明的东西比看上去少**：

> **一棵没坏的树给出的绿，不是「尺子坏了」的证据，是「树没坏」的证据。**

（因为树没坏 ⇒ 不管尺子好着还是坏了，**都不会有红**。）

⇒ 所以这一轮的 D 改成：**尺子坏了，缺陷还在。**

这样才有东西可解释：

- 树**坏了** + 尺子**好着** ⇒ **红**（A/B/C 证明的）
- 树**坏了** + 尺子**坏了** ⇒ **绿**（D 证明的）

⇒ **红是尺子报的。**
⇒ 「A/B/C 红了」不再只是「检查器和变异碰巧表现一致」，
而是**尺子坏掉的时候，红确实消失了**。

而且 D 多加一条：**摘要必须和好树的一字不差**。

这不是锦上添花。3e 的 D 里，**断掉判据之后，那些数也得跟着对** ——
「142 个解析成功 / 71 跨文件 / 71 同文件」这些数是检查器**自己算**的，
判据一坏，算出来的数也得跟着变；
**摘要对不上**，就说明这把尺子**坏得不是只坏在比较那一步**。

⇒ **「绿」不够，**「绿，而且说得和好树一模一样」才够。

## 建这个脚本的时候，栽了六个跟头

每一个都差点变成**假绿**，所以每一个都得写进代码里。

### 一、`git add` 没有 `--quiet`

副本要**自己是一个 git 仓库**（3c 是拿 `git ls-files` 量树的，
副本不是 git 仓库 ⇒ 它量到**零个文件**，然后报一张干净的纸）。

第一次写的是 `git add -A -f --quiet` ——
git 2.50.1 说 `unknown option 'quiet'`（**`git add` 压根没有这个选项**），
索引里只剩 **1 个文件**，而副本有 **353 个**。

**改法**：不写 `--quiet`，把输出丢掉；
再**断言**副本索引里的文件数和真树一样多。
**断言比参数重要** —— 参数错了会报错，断言错了会绿。

### 二、`@(...)` 把**包装层**数成了元素

`Get-MutTrackedFiles` 返回的是 `,@($out)`（为了空结果也是数组），
调用方再套一层 `@(...)`，数出来的是**包装层**，不是文件。

⇒ 「副本的索引里有 **1** 个文件」—— 其实是 353。

⇒ **教训**：数组返回值的包装层是**数出来的**东西的一部分。
凡是数东西的地方，**先看一眼数出来的是什么**。

### 三、副本里**不能只放 markdown**

3d / 3e 只读 markdown，看起来「副本放 markdown 就够了」。

**错。** 一条链接**可以指向任何东西** —— 一个 `.cpp`、一个 `.txt`、一张图。
只放 markdown 的副本里，**每一条指向非 markdown 的链接都是断的**。

⇒ 第一次跑 3d，副本里那条检查器**什么都没打印**。

⇒ **改法**：三道门**共用同一种副本** —— **真树的全部 tracked 文件**，
副本**自己 git init**，索引**逐个文件对齐**。

### 四、锚点写在**括号外面**，检查器**根本没看见**

3d 的 B 变异本来想把
`(./notes/notes_W7_Close_2026-10.md)` 改成
`(./notes/notes_W7_Close_2026-10.md)#no-such-heading-zzz`。

链接的样子是 `](...)` —— **括号里面**才是链接。
`#` 写在括号外面 ⇒ 检查器看到的是一条**普通的文件链接**，它解析得了。

⇒ **第一次跑，B 是绿的。**

⇒ **改法**：`#` 放进括号里
（`(./notes/notes_W7_Close_2026-10.md#no-such-heading-zzz)`），
B 才真的红。

⇒ **这一条仓库里根本没有**：这个仓库**一条锚点链接都没有**，
所以「文件在、标题不在」那条分支**从来没被触发过**。
B 和 C 这两条变异，就是**专门去触发它的**。

### 五、一个变量名把**检查器的参数**吃掉了

脚本里有个 `$extra`，本来是「副本里多出来的文件」；
而检查器的参数也叫 `$extra`（`-PerSuiteFile <路径>`）。

⇒ `$extra = @(...)` 那一行**把参数覆盖了** ——
副本那次运行**没带逐套件计数**，3c 找不到那个文件，**什么都没打印**。

⇒ 而脚本当时只说了「副本和真树不一样」，**没说为什么**。

⇒ **改法两处**：
1. 文件集合那组变量改名（`$onlyInTree` / `$onlyInCopy`），**别和参数同名**；
2. **检查器一个字都没打印的时候，把它打印的东西显示出来** ——
   「它没说话」不是一个诊断。

### 六、`git add` 之后还要**再说一遍树的样子**

副本是**tracked 文件**的拷贝，而三个检查器读的是**工作树**。

⇒ 一个**没被 tracked 的新笔记**，在真树里，不在副本里 ——
**两个不同的树**。

⇒ 脚本现在**先比两边的 markdown 集合**，不一样就**拒绝给结论**，
并说清楚：**`git add` 一下**。

⇒ 这条是从 3f 那次「副本不是那棵树」学来的：
**先认副本，再信它**（相对路径要用 **provider 自己给的路径**，
不是拿字符串长度切出来的）。

## 这一轮跑出来的摘要（2026-10-29）

| | 摘要 |
|---|---|
| 3c | `DOC NUMBERS OK: 28 claims + the per-suite table agree with reality` |
| 3d | `LINKS OK: 168 relative links across 139 files all resolve` |
| 3e | `SECTIONS OK: 142 of 190 section pointers resolve across 139 files; 48 pointers skipped (counted above), 18 enumerations; 79 quoted census numbers agree with reality` |
| 变异 | 12 条（3 道门 × 4 条），本地全绿 |

> ⚠ 上面这三条摘要里的数是**那一天**的 ——
> **链接数会随文档一起动**（这一轮它就动了好几次），
> **别拿它们当现在的数**。
> 现在该信哪个数：**跑一遍门禁**，每条摘要自己就是那个数。

**D 的验收条件**（三道门都一样）：

```
exit = 0，红 = 0，摘要 == 好树的摘要（逐字符）
```

⇒ 「绿」和「说得和好树一样」**一起**成立，才算数。
