## 📌 一句话总结

极性判据漏检了整整一个方向，**调阈值调不出来** —— 因为病根不在阈值，在于**量错了对象**：
老判据量的是「ROI 里所有白丝印的质心」，而极性条只是其中 4~7px 宽的一小条，
旁边还有丝印外框、二极管符号线、电解电容十字线在抢这个质心。
改成「**腐蚀出极性条本身 → 定它在左还是在右 → 和配方给的基准比**」之后，
`signal_polarity.png` 从 PASS 变成 FAIL:polarity；
「应该在哪一侧」由**生成器自己登记**、配方带下来，判据**不猜** —— 猜错就是把好板判成反装。

## 一、老判据错在哪

### 1.1 【实测】老判据是**单边**的

原判据（`common/pcb_core/pcb_core.cpp` 旧版）：

```
白丝印掩膜 → 取质心 → 质心 x 占 ROI 宽的百分比 > polarityRatio(60%) → 报 polarity
```

「反装」的定义是**把极性条挪到另一边**。挪到右边撞上单边阈值（抓得到），
挪到左边 —— 那条阈值**根本不看那边**（抓不到）。

所以它只覆盖了反装的一半，而且漏掉的那一半是**结构性的**。

### 1.2 【实测】直觉上改成双边，没有可用的容差

「那就两个方向都设一个阈值」，听起来是显然的解。实测不成立：

| 量 | 数值 |
|---|---|
| 好板 power D1（极性条在右）| 41.84 % |
| 废板 signal D1（极性条被挪到左）| 29.87 % |
| 不误报好板要 | 容差 < 8.16 |
| 抓到废板要 | 容差 > 20.13 |

`8.16 < T < 20.13` —— **空集**。双边化在"质心"这个量上无解。

> 📌 这条是本项目的老教训 `at-one-sweep-isnt-a-window.md` 的又一次应验：
> 一次扫描得到一个点，不是一个窗口。

### 1.3 【实测】真正的病根：量错了对象

老判据量的是 **"ROI 里所有白丝印的质心"**，而极性条只是其中一小条。
ROI 里所有白的像素还包括：丝印外框（1px 细线）、二极管符号线、电解电容的十字线。

实测最能说明问题的一组数：

| 板/元件 | 有没有极性条 | 老判据量出来的质心 |
|---|---|---|
| signal C5–C8 | **没有** | **正好 50.0%** |
| signal D1（正常）| 有，在右 | 41.84 % |
| signal D1（反装）| 有，在左 | 29.87 % |

**"根本没有极性条"的电容，质心也正好 50.0%** —— 丝印外框左右对称，把质心拽回正中间。
质心二分天然没有余量可谈。

### 1.4 【实测·项目】我自己先弄错了一次

动手之前我给出的建议是「polarity 改看**明暗**（明暗翻转）」。

**这是错的。** 读源码 + 看图确认后：反装时极性条是**平移**（白条从左边挪到右边），
**没有明暗翻转**。两个极性条都是白的。

> 📌 记这一条是因为它差点把整轮工作带偏。判据的物理模型没搞清楚就动手，
> 改出来的东西能编译、能跑、测试也能红 —— 但红的方向是错的。

## 二、四种量法的实测对比

候选方案（全部在 5 张板、8 个带极性条的元件上实测）：

### 方案 A：质心阈值（老的）
量 ROI 里所有白丝印的质心。

- 实测：单边，漏掉一半；双边化无解（1.2）
- ❌ **否**

### 方案 B：左右半白像素计数差
量 ROI 中线左右两侧的白像素数之差。

- 分离度确实好：无极性条时 |diff| ≤ 2，带极性条时 51~178
- ❌ **否**，两个污染源：
  - 丝印外框**不对称露头**（灰色圆头盖住框的中间）→ 左段 14px / 右段 18px
  - 电解电容的垂直十字线正好落在 ROI 中线，**整条被算进右半**
- 判据被两个"不是极性条的东西"绑架

### 方案 C：连通域取「实心块」
在白掩膜上取连通域，挑最大的一块。

- ❌ **否**：二极管的极性条和白色符号线**连成一块**（25×11，中心在正中），分不出左右

### 方案 D：腐蚀 → 连通域取最大块 ✅

1. 白丝印掩膜
2. **腐蚀**（3×3）—— 1px 细线全灭，4~7px 的极性条完整留下
3. 连通域取最大块 = 极性条
4. 看它**完全**落在 ROI 中线的哪一侧

**实测 100% 正确**（8 个带极性条的元件全对，5 块板全对）：

| 板/元件 | 腐蚀后残留 | 侧 |
|---|---|---|
| demo C1 正常 / 反转 | 5×23 @15 / 5×23 @75 | 左 / 右 |
| signal C1–C4 | 3×13 @14 | 左 |
| signal D1 正常 / 反转 | 3×9 @34 / 5×9 @14 | 右 / 左 |
| signal C5–C8 | **什么都没有** | 无极性条 |
| power C1/C2（CAP_BIG）| 3×5 @15 | 左 |
| mcu C1–C6 | **什么都没有** | 无极性条 |

腐蚀是 W3 形态学的老本行，这一步本身没有新东西。

## 三、「应该在哪一侧」必须由配方给

### 3.1 【实测】判据不猜

「电容的极性条在左、二极管的极性条在右」这个约定，实测在四块板上是一致的
（生成器的 `draw_capacitor` / `draw_cap_small` / `draw_cap_big` 画左边，`draw_diode` 画右边）。

但**判据不能自己猜**，原因是：

> 猜错的后果是**把好板判成反装** —— 这是**静默误报**，比漏检更难查。
> 漏检至少还会出现在"已知漏检"清单里；误报会让整条产线停下来追一个不存在的问题。

所以「应该在哪一侧」进配方（`polarity_side`，site 级），判据只负责**量**和**比**。

### 3.2 【实测】登记粒度是 `(cx, cy)`，不是 `kind`

一开始想按封装类别登记（`CAP_SMALL` → left，`DIODE` → right）。实测不成立：

**power 板 C3/C4/C5 有极性条，C6/C7 没有，但它们的 kind 是一样的。**

按 kind 登记会把"这个具体位置的元件有没有极性条"的信息丢掉。
所以登记表的键是 **元件中心坐标 `(cx, cy)`**，不是 kind。

### 3.3 生成器自己登记，导出脚本不抄表

`W6_PCB_DefectProject/gen_complex_pcb.py` 和 `gen_pcb_dataset.py` 里，
**画极性条的那一行代码自己登记**：

```python
POLARITY_SIDE[(cx, cy)] = "left"    # draw_cap_small / draw_cap_big
POLARITY_SIDE[(cx, cy)] = "right"   # draw_diode
```

`W7_VisionMasterLite/tools/export_recipes.py` 只是把这个表**原样搬进配方**。

> 📌 为什么不让导出脚本自己维护一张"kind → side"的表：
> `export_recipes.py` 里已经有一张 `BODY` 表了，它的注释**自承**"这是一份会漂的副本"。
> 再加第二张，就是本项目栽过四遍的那个坑的第五次。

### 3.4 【实测】没有极性条的封装**不配** polarity 检查

C5–C8、mcu 全部、power C6/C7 这些封装**没有极性条**。
如果给它们配 polarity 检查，报告里会塞满"没查"（skipped）的噪音，
把真正该看的那几条淹掉。

所以导出脚本**不给它们配 polarity 规则**。

> ⚠️ 代价要说清楚：这些元件的极性**没有被检查**。
> 现在的 skipped 机制会如实报出来（"读不到极性条"），
> 所以是"诚实的不检查"，不是"假装检查过了"。

## 五、变异验证：4 个变异，4 个都红

方法：改坏代码 → 编译 → 跑测试 → 看有没有断言变红 → 还原。

| 编号 | 变异 | 预期 | 实测 |
|---|---|---|---|
| M1 | 腐蚀核 3×3 → 5×5 | — | ⚠️ **存活**（见下）|
| M1' | 腐蚀核 → 1×1（等于不腐蚀）| 抓不到极性条 | ✅ **杀**：W6 core 红 2 条（期望 FAIL 实际 PASS / 必须命中 polarity），W7 红 5 条 |
| M2 | 配方里非法的 `polarity_side` 从「报错」改成「当没写处理」| 配方校验红 | ✅ **杀**（**先补了测试才杀掉**，见 5.2）|

| M4 | 定侧逻辑左右写反 | 好板误报 | ✅ **杀**：W6 core 红 6 条（三块好板全变 FAIL）|

### 5.1 【实测】M1 存活暴露的事：腐蚀核**大小**不是敏感点

5×5 和 7×7 都存活。实跑 CLI 才发现原因：

| 腐蚀核 | D1 实测残块 | 结论 |
|---|---|---|
| 3×3 | 5×9 实心块 | FAIL:polarity ✓ |
| 7×7 | **1×5** 实心块 | FAIL:polarity（**照样对**）|

腐蚀核变大只是把残块**磨小**，**位置没变** —— 而判据看的是位置。
所以核的大小不是承重点，「有没有腐蚀」才是。

> 📌 这条值得记：**变异不是随便挑的坏代码，是"改了会真的坏"的代码。**
> 5×5 腐蚀**不是 bug**，它照样工作 —— 拿它当变异，测不出任何东西，
> 只会浪费一轮编译。挑变异前先问："改了这一行，行为真的会变吗？"

### 5.2 【实测】M2 是靠**补测试**才杀掉的

M2 第一次跑的时候**存活**了 —— 因为「配方的 `polarity_side` 写错必须报错」这条守卫
**一行断言都没有**。把守卫删掉，整套测试照样全绿。

**一条没人验证的守卫，等于没有守卫。**

于是补了 12 条断言（`common/pcb_core/tests/test_pcb_core.cpp`）：

- 合法值 `left` / `right` / `""` 必须能加载，且**真的落到字段上**（不是"没报错"就算过）
- 非法值 `"up"` / `"Left"`（大小写）/ `123`（不是字符串）必须加载失败
- 报错消息必须点出**字段名**和**站点名**（`polarity_side`、`C1`）——
  否则人拿到一句"配方有问题"，还得自己回去找是哪一条

补完之后 M2 被杀，红 2 条。

## 六、顺带逮到的两个真问题

### 6.1 【实测】W7 的 JSON 边界把 `polarity_side` 吃了

第一次跑 W7 测试，**红了 10 条**，而且症状很怪：

- demo 的 `polarity.png`（该判废）→ PASS
- complex 的 `power_baseline.png` / `signal_baseline.png`（好板）→ 报了一堆 polarity

一开始差点误判成"判据把左右搞反了"。真因是：

```
pcb_inspect  → components[] JSON →  pcb_defect_judge → core InspectSite
```

**这一跳里 `polarity_side` 根本没传。** 判定算子从 JSON 重建站点时拿不到基准，
于是整条 polarity 规则**静悄悄地变成"没查"（skipped）**。

- 好板：polarity 不跑 → 少报 → 看起来"没问题"
- 废板：polarity 不跑 → **漏检**

**核心一直是对的，W6 一直是对的，坏的是这一跳。**

修法：`pcb_inspect` 往下游发这个字段，`pcb_defect_judge` 往回读。

> 📌 这正是本项目反复吃过的那个亏：**字段存在 ≠ 字段被验证**。
> 字段在配方里有、在核心的 struct 里有、在 W7 的 Qt struct 里也有 ——
> 但没人验证它**活过了中间那一跳**。
>
> 变异 M3 证明了这件事的严重性：**W6 在 M3 下全绿（180/180）**，
> 只有 W7 的测试能看见这个洞。如果只有 W6 有测试，这个洞会一直躺着。

### 6.2 【实测】`InspectSite` 中间插字段 → 位置聚合初始化整体错位

给 `InspectSite` 加 `polaritySide` 时，字段插在了中间，
`tests/test_w6_cli.cpp` 里的位置聚合初始化 `{...}` 立刻错位：

```
error C2665: push_back: 无法将参数 1 从"initializer list"转换到 InspectSite
    原因如下: 初始化: 无法将参数 1 从"bool"转换为"std::string"
```

这次的报错**运气好** —— `bool` 塞进 `std::string` 会被编译器拦下。
换成两个同类型字段，就是**静默错位**：编译照过，行为悄悄变了。

修法两条：

1. `InspectSite` 的新字段一律**放末尾**（并在字段旁写明为什么）
2. `test_w6_cli.cpp` 里改用具名赋值（`makeSite()` 辅助函数），不再用位置聚合初始化
